## Найденное и исправленное

- В `_response_gifts` после прямого `response.gifts` reflection fallback берёт первый `ArrayList` в иерархии класса без проверки типа его элементов. Это эвристика, а не надёжное разрешение схемы ответа; source page и факт `custom-nft-021` теперь говорят об этом явно.
- `_list_gifts_field` имеет аналогичный fallback. `_inject_live` добавляет объект в каждый найденный `GiftsList`, не проверяя уже присутствующий id. Source page и факт `custom-nft-023` теперь фиксируют риск повторов и зависимость от приватных полей клиента.
- В строке Gift builder и факте `custom-nft-020` уточнено, что availability берётся из базового подарка, а при отсутствии код ставит локальные fallback counts и `limited=True`; эти значения служат попыткой отрисовки и не доказывают серверную редкость или доступность.
- Факты `custom-nft-016` и `custom-nft-018` описывали противоположные ветки одного правила custom pattern. Они объединены в один факт с общей доказательной областью `plugins/custom_nft.py:3804-3831` и `3856-3868`; удалён повторяющийся ID `custom-nft-018`.

Проверка конкретных рискованных реализаций подтвердила и уже записанные в source page замечания: `_clone_attr` при неудаче `newInstance()` возвращает исходный donor, который вызывающий код способен изменить; `pre_request_hook` сохраняет self/other в одном `_last_request_self`, а `account` игнорируется; `only_self=false` разрешает локальное добавление в ответы чужих профилей; notification/cache операции адресуют `UserConfig.selectedAccount`. Это статические наблюдения исходника, не воспроизведённые runtime-сценарии.

## SDK, документация и доказательства

Код объявляет `__app_version__ >=12.5.1` и `__sdk_version__ >=1.4.3.3`. README повторяет эти минимумы и заявляет Python 3.11/Chaquopy v16; встроенный SDK reference указывает SDK 1.4.3.10 и app >=12.8.1, а старое описание плагина также указывает app >=12.8.1. Страница корректно оставляет это противоречие как документационные/авторские декларации, не выводит из него реальную совместимость. Reference документации не заменяет исходник SDK конкретной версии.

Страница маркирует README и авторские документы как документационные утверждения, вывод о гонке как статическое предположение, а исходный код как `code`; ни один просмотр кода не назван `runtime-verified`. Утверждение о локальном характере подарка подтверждается README как `docs` и локальным путём хранения/подмены как `code`, но остаётся заявлением об отсутствии серверного вызова в изученной области, не проверкой сетевого поведения.
