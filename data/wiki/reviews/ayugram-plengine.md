# Независимая проверка: AyuGram Desktop PLEngine

- Вердикт: **accepted-with-gaps**.
- Snapshot: `MrCheatEugene/AyuGramDesktop-PLEngine`, commit `55feefdb6abd702e368b12431de97313441362a0` (`dev`). Проверены зафиксированные локальные материалы этого SHA; README рассматривается как `docs`, поведение кода как `code`, выводы об отсутствии вызова — как ограниченное `inference`. Исходники не собирались и не запускались.
- Независимо сверены первичные снимки, `tree.json`, `file-manifest.json`, source page и fact JSON. Исходные документы README-плагина, английский и русские README, основной README и LICENSE сопоставлены с PLEngine ABI, реализацией, call-sites и HTTP endpoints. Полностью проверена зона `Telegram/SourceFiles/plengine` (18 файлов): `PLEMains.cpp/.h`, `PLESettings.cpp/.h`, `debugger/Windbg.cpp/.h`, `helpers/MixedServer.cpp/.h`, `helpers/PseudoPopup.cpp/.h`, `settings/settings_engine.cpp/.h`, `settings/settings_main.cpp/.h`, `settings/settings_plugins.cpp/.h`, `settings/settings_trustedUA.cpp/.h`. Дополнительно сверены `AyuPlugin.h`, `ExternSharedVariables.h/.cpp`, запуск из `main.cpp`, `Telegram/CMakeLists.txt`, APIWrap message hook, фильтр и deletion helper, MTProto declaration, settings/plugin-info UI и упомянутые тесты.
- Для проверки popup-hook получены и просмотрены еще восемь целевых файлов, которых не было в первоначальном наборе 37: `history/view/history_view_context_menu.cpp/.h`, `ayu/ui/context_menu/context_menu.cpp/.h`, `ayu/ui/message_history/history_inner.cpp/.h` и `ayu/ui/message_history/history_item.cpp/.h`. В `PLEMains.cpp` callback `doDrawPopup` динамически обнаруживается и сохраняется в `FunctionsDrawPopup`/`PluginData`, но invocation в этих кандидатах не найден. В целом поиск охватывает 45 файлов; все 18 файлов PLEngine получены. Большая часть 6 704 записей дерева AyuGram/Telegram не изучалась, поэтому это пробел именно исследованного покрытия, а не доказательство отсутствия call-site во всём репозитории.
- Точность: подтверждены ABI typedefs и exports, startup/load flow, callback order/semantics, `ApiWrap::sendMessage` preprocessing, deletion/filter integration, UI `doDrawGUI`, MemData/queue и локальные endpoints. Важное расхождение HTTP: README документирует `127.0.0.1:8080`, но listener возвращается до `Listen` при пустом или невалидном `AYUPL_PORT`; expression с fallback `8080` ниже по коду недостижим. Settings UI записывает `AYUPL_HOST=127.0.0.1` и `AYUPL_PORT=8081`. Также README показывает `ok` строкой, а сериализатор выводит JSON boolean; `result_json` всегда строка, включая вложенный JSON для session list. Это уточнено на source page и в факте `ayugram-plengine-020`; ответные типы и nested payload описаны с кодовыми ссылками.
- Исправление popup evidence: формулировка `unavailable` заменена на scoped `inference`, поскольку возможный invocation не найден в конкретных изученных history/context-menu call-sites, но весь клиентский upstream не проверялся. Source page и факт `ayugram-plengine-018` теперь называют границу поиска явно.
- Проверка повторов: JSON содержит **27 фактов, 27 уникальных ID и 27 уникальных claim**; совпадающих claim внутри страницы фактов нет. Внутренних дублей не обнаружено. Повторное знание HTTP mismatch в source page и facts является согласованным отображением одного вывода в двух слоях; Desktop ABI сохранён отдельно от Android API и sample-плагина, который не изучался.
- Остаточные ограничения: нет runtime/build/test evidence; не исследован AyuSamplePlugin; не выполнен сплошной анализ всего 6 704-файлового дерева или всей upstream логики Telegram Desktop; не проверены бинарная совместимость DLL и реальный popup hook invocation. Статический просмотр не подтверждает фактическое поведение сборки или безопасность указателей/потоков.

Покрытие достаточно для справочной страницы о PLEngine ABI, callback integration, HTTP control plane, build inclusion и известных ограничениях, если сохранять перечисленные границы. Полнота для неохваченного клиентского кода и runtime остается открытой.
