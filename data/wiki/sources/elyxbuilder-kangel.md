# Kangel-Plugins/ElyxBuilder

## Роль и закреплённая версия

Это отдельный форк `shareui/ElyxBuilder`: CLI на Python для генерации каркаса ElyxCore-плагина, проверки синтаксиса, необязательной AST-обфускации, компиляции Python в `.pyc` и упаковки проекта в ZIP-архив с настраиваемым расширением. README прямо перечисляет изменения форка: раздельные `obfuscationIgnore` и `compilationIgnore`, сохранение mapping, новый набор режимов obfuscator и исправления `new -zf`/watch. Не переносите сюда предположения о других ElyxBuilder-форках: эта страница привязана к SHA `b6db59093324dc5148f811c9058a6c1414fbb849` ([README](https://github.com/Kangel-Plugins/ElyxBuilder/blob/b6db59093324dc5148f811c9058a6c1414fbb849/README.md#L1-L31), [pyproject.toml](https://github.com/Kangel-Plugins/ElyxBuilder/blob/b6db59093324dc5148f811c9058a6c1414fbb849/package/pyproject.toml#L5-L26)). В `pyproject.toml` версия пакета указана как `0.6.3.2`, минимальный Python — 3.10; Python 3.11 нужен только для bytecode-сборки, а `pyzipper` — только для шифрования ([docs/en/en.md](https://github.com/Kangel-Plugins/ElyxBuilder/blob/b6db59093324dc5148f811c9058a6c1414fbb849/docs/en/en.md#L1-L32)). Лицензия по метаданным и `LICENSE` — MIT.

История GitHub API на дату сбора содержит 24 видимых коммита: ранняя история принадлежит `shareui`, а поверх неё Kangel добавил, среди прочего, `obfuscationIgnore` ([46a96a6](https://github.com/Kangel-Plugins/ElyxBuilder/commit/46a96a645eac)), исправления zipformat/watch/аргументов ([af8f4b8](https://github.com/Kangel-Plugins/ElyxBuilder/commit/af8f4b808214)), расширенные режимы обфускации ([0d72805](https://github.com/Kangel-Plugins/ElyxBuilder/commit/0d7280595eb0)), динамический loader-stub ([bb4caa7](https://github.com/Kangel-Plugins/ElyxBuilder/commit/bb4caa7c9944)) и документацию к нему. Последний commit — `b6db590`, исправляющий `loaderStubDynamic` UnboundLocalError и независимую активацию режима. Это история репозитория, а не доказательство runtime-совместимости. [История коммитов](https://github.com/Kangel-Plugins/ElyxBuilder/commits/main/).

## Формат проекта и сборки

`elyb` установлен как console script `elyb = elyb.cli:main`; `elyb new` создаёт структуру плагина и `refmap.yml` либо `refmap.json`, metadata YAML/JSON, `.elyxbuilder/config.yml`, `src`, `res`, `assets`, `locales/strings_en.json` и `locales/strings_ru.json`. Refmap указывает `metainfo`, `elyxbuilder`, `assets` и `strings`; это записи путей для упаковщика, а не реализация загрузки ресурсов/переводов приложением ([pyproject.toml](https://github.com/Kangel-Plugins/ElyxBuilder/blob/b6db59093324dc5148f811c9058a6c1414fbb849/package/pyproject.toml#L11-L26), [new.py](https://github.com/Kangel-Plugins/ElyxBuilder/blob/b6db59093324dc5148f811c9058a6c1414fbb849/package/src/cmds/new.py#L445-L459), [new.py](https://github.com/Kangel-Plugins/ElyxBuilder/blob/b6db59093324dc5148f811c9058a6c1414fbb849/package/src/cmds/new.py#L604-L710)).

`elyb build` ожидает запуск из корня проекта. Код ищет `refmap.yml`, `refmap.yaml` или `refmap.json`; требует в refmap `elyxbuilder` и `metainfo`, а из builder config — `zipFormat`, `buildNameUncompiled` и при compile `buildNameCompiled`; `source` обязателен для `--compile` ([build.py](https://github.com/Kangel-Plugins/ElyxBuilder/blob/b6db59093324dc5148f811c9058a6c1414fbb849/package/src/cmds/build.py#L23-L44), [build.py](https://github.com/Kangel-Plugins/ElyxBuilder/blob/b6db59093324dc5148f811c9058a6c1414fbb849/package/src/cmds/build.py#L346-L443), [build.py](https://github.com/Kangel-Plugins/ElyxBuilder/blob/b6db59093324dc5148f811c9058a6c1414fbb849/package/src/cmds/build.py#L542-L548)). Обычная сборка идёт в ZIP DEFLATED, добавляет refmap и проходит по файлам проекта; `zipFormat` управляет расширением имени архива. Отдельного EAF-кодека здесь не видно, поэтому `.eaf` — выбранное расширение упакованного ZIP, а приём архивов клиентом по этой реализации не устанавливается ([build.py](https://github.com/Kangel-Plugins/ElyxBuilder/blob/b6db59093324dc5148f811c9058a6c1414fbb849/package/src/cmds/build.py#L81-L90), [build.py](https://github.com/Kangel-Plugins/ElyxBuilder/blob/b6db59093324dc5148f811c9058a6c1414fbb849/package/src/cmds/build.py#L629-L680)). `--no-assets` исключает только пути из `optionalAssets`; `ignoreAll` действует при любых сборках, а `compilationIgnore` управляет compile. Списки обновляются CLI-командами `add-ignore`/`del-ignore` ([build.py](https://github.com/Kangel-Plugins/ElyxBuilder/blob/b6db59093324dc5148f811c9058a6c1414fbb849/package/src/cmds/build.py#L395-L402), [ignore.md](https://github.com/Kangel-Plugins/ElyxBuilder/blob/b6db59093324dc5148f811c9058a6c1414fbb849/docs/ru/ignore.md#L5-L33)).

Хотя build и генератор scaffold принимают JSON refmap, ветка `elyb stats` жёстко ищет `refmap.yml` и читает его через YAML loader. Для проекта только с `refmap.json` статистические команды по dispatcher не доступны без дополнительной адаптации ([cli.py](https://github.com/Kangel-Plugins/ElyxBuilder/blob/b6db59093324dc5148f811c9058a6c1414fbb849/package/src/cli.py#L117-L148), [build.py](https://github.com/Kangel-Plugins/ElyxBuilder/blob/b6db59093324dc5148f811c9058a6c1414fbb849/package/src/cmds/build.py#L23-L30)).

`--ast` обходит `.py` внутри source и вызывает `ast.parse`; это только синтаксическая проверка исходников. Она не импортирует проект, не разрешает зависимости, не проверяет SDK/host API и не является sandbox/security review ([build.py](https://github.com/Kangel-Plugins/ElyxBuilder/blob/b6db59093324dc5148f811c9058a6c1414fbb849/package/src/cmds/build.py#L328-L344), [build.md](https://github.com/Kangel-Plugins/ElyxBuilder/blob/b6db59093324dc5148f811c9058a6c1414fbb849/docs/ru/build.md#L23-L39)).

При `--compile` инструмент находит внешний Python 3.11 и использует `py_compile`; cache лежит в `.elyx/cache/python311`, а ignored от компиляции `.py` остаются исходниками в архиве. `--reset` требует `--compile`; уровни оптимизации 0–2 передаются компилятору. Компиляция/совместимость с клиентским runtime здесь не запускались ([build.py](https://github.com/Kangel-Plugins/ElyxBuilder/blob/b6db59093324dc5148f811c9058a6c1414fbb849/package/src/cmds/build.py#L94-L109), [build.py](https://github.com/Kangel-Plugins/ElyxBuilder/blob/b6db59093324dc5148f811c9058a6c1414fbb849/package/src/cmds/build.py#L204-L320), [build.md](https://github.com/Kangel-Plugins/ElyxBuilder/blob/b6db59093324dc5148f811c9058a6c1414fbb849/docs/ru/build.md#L63-L75)).

`elyb cached` сравнивает для `.py` файлов manifest-поля `mtime` и `size` с текущими stat значениями и выводит `ok`, `modified`, `new` или `ignored`; сравнение не основано на content hash. Поэтому одинаковые размер и timestamp не дают сильной гарантии обнаружения изменения ([cached.py](https://github.com/Kangel-Plugins/ElyxBuilder/blob/b6db59093324dc5148f811c9058a6c1414fbb849/package/src/cmds/cached.py#L81-L124), [cached.md](https://github.com/Kangel-Plugins/ElyxBuilder/blob/b6db59093324dc5148f811c9058a6c1414fbb849/docs/ru/cached.md#L1-L16)).

`buildMetaInfo` патчит metadata только во время записи архива: добавляет вложенный `elyxbuilder` с `compiled`, `buildNum`, датой, `pythonVer`, `sourceHash` и версией пакета; опции могут добавить `staticVer` и `client`. Файл metadata на диске этой функцией не перезаписывается. Таблица YAML-примера в RU build docs показывает поля на верхнем уровне, в отличие от вложенного блока в коде, поэтому для этого SHA приоритет у реализации ([build.py](https://github.com/Kangel-Plugins/ElyxBuilder/blob/b6db59093324dc5148f811c9058a6c1414fbb849/package/src/cmds/build.py#L167-L202), [build.py](https://github.com/Kangel-Plugins/ElyxBuilder/blob/b6db59093324dc5148f811c9058a6c1414fbb849/package/src/cmds/build.py#L678-L680), [build.md](https://github.com/Kangel-Plugins/ElyxBuilder/blob/b6db59093324dc5148f811c9058a6c1414fbb849/docs/ru/build.md#L41-L61)).

## Изменения Kangel: ignore, mapping и obfuscation

Форк добавляет `obfuscationIgnore`, независимый список от `compilationIgnore`. При отсутствии нового ключа код сохраняет старое поведение и использует `compilationIgnore` как fallback. Если путь только в `compilationIgnore`, Python-файл пропускает `.pyc` компиляцию, но может обфусцировать и записать исходник; если путь в `obfuscationIgnore`, код пропускает обфускацию. При `-o` исходники обфусцируются по AST перед упаковкой; с `-c` выбранный код перед compile преобразуется и заново компилируется, обфусцированные файлы не идут по cache-hit пути ([build.py](https://github.com/Kangel-Plugins/ElyxBuilder/blob/b6db59093324dc5148f811c9058a6c1414fbb849/package/src/cmds/build.py#L204-L250), [build.py](https://github.com/Kangel-Plugins/ElyxBuilder/blob/b6db59093324dc5148f811c9058a6c1414fbb849/package/src/cmds/build.py#L489-L536), [build.py](https://github.com/Kangel-Plugins/ElyxBuilder/blob/b6db59093324dc5148f811c9058a6c1414fbb849/package/src/cmds/build.py#L542-L590), [obfuscation docs](https://github.com/Kangel-Plugins/ElyxBuilder/blob/b6db59093324dc5148f811c9058a6c1414fbb849/docs/ru/obfuscation.md#L267-L282)).

Новый `applyObfuscationPipelineWithMapping` сопоставляет имена top-level функций, классов, методов и параметров через AST-проход, а успешный obfuscated build может записать `builds/latest_mapping.json`; ключи — относительные пути файлов. При включённом статическом `loaderStub` помощник явно возвращает пустые списки mappings, потому что payload спрятан в blob; динамический режим отдельно обрабатывается другим helper, поэтому документационное обещание о полезности mapping нельзя обобщать на loader-режимы ([obfuscate.py](https://github.com/Kangel-Plugins/ElyxBuilder/blob/b6db59093324dc5148f811c9058a6c1414fbb849/package/src/cmds/obfuscate.py#L944-L1025), [build.py](https://github.com/Kangel-Plugins/ElyxBuilder/blob/b6db59093324dc5148f811c9058a6c1414fbb849/package/src/cmds/build.py#L529-L539), [build.py](https://github.com/Kangel-Plugins/ElyxBuilder/blob/b6db59093324dc5148f811c9058a6c1414fbb849/package/src/cmds/build.py#L581-L590), [obfuscation docs](https://github.com/Kangel-Plugins/ElyxBuilder/blob/b6db59093324dc5148f811c9058a6c1414fbb849/docs/ru/obfuscation.md#L14-L18)).

Помимо унаследованных AST-проходов (удаление docstrings/log-вызовов, переименование локальных имён, кодирование строк и чисел), Kangel добавил junk-функции и dynamic multi-byte XOR. Документация описывает `stringSplitting` для длинных строк, однако pinned код только сохраняет флаг в `EncodeStringsAdvanced` и далее не читает его; helper `_makeSplitStringExpr` содержит обращение к неопределённому `decoder_call` и не вызывается из прохода. Следовательно, фактическое разбиение строк этим снимком не подтверждается, а включение опции по коду не меняет путь кодирования строк ([obfuscate.py](https://github.com/Kangel-Plugins/ElyxBuilder/blob/b6db59093324dc5148f811c9058a6c1414fbb849/package/src/cmds/obfuscate.py#L28-L124), [obfuscate.py](https://github.com/Kangel-Plugins/ElyxBuilder/blob/b6db59093324dc5148f811c9058a6c1414fbb849/package/src/cmds/obfuscate.py#L127-L157), [obfuscate.py](https://github.com/Kangel-Plugins/ElyxBuilder/blob/b6db59093324dc5148f811c9058a6c1414fbb849/package/src/cmds/obfuscate.py#L766-L816), [obfuscation docs](https://github.com/Kangel-Plugins/ElyxBuilder/blob/b6db59093324dc5148f811c9058a6c1414fbb849/docs/ru/obfuscation.md#L240-L265)).

Есть два генератора loader-stub. Статический распаковывает payload через zlib/base64 и выполняет его; динамический генерирует RC4 payload, предлагает plaintext `BasePlugin` stub, пытается найти `org.telegram.ui.Components.LayoutHelper` через `hook_utils.find_class` и вычисляет runtime-ключ как SHA-256 от UTF-8 байтов конкатенации отсортированных непубличных имён атрибутов класса. Сгенерированный текст вызывает `exec` в `globals()`; sandbox/ограниченные builtins в коде отсутствуют. Код принимает `loaderStubDynamicKey` как hex-строку и преобразует её в байты для шифрования build-time payload; по документации это должен быть хеш, снятый helper-плагином на целевом устройстве. Если ключ не задан, fallback вместо этого вычисляет `sha256(xorKey-byte || compressed-payload-prefix)`, тогда как сгенерированный stub всё равно вычисляет runtime-ключ из атрибутов `LayoutHelper`; соответствие этих ключей из кода не следует, поэтому fallback статически выглядит несовместимым с расшифрованием. Кроме того, generated loader глушит исключения вокруг расшифрования/exec через `except Exception: pass`, что может скрыть причину отказа. Это вывод по коду, runtime-проверки нет ([obfuscate.py](https://github.com/Kangel-Plugins/ElyxBuilder/blob/b6db59093324dc5148f811c9058a6c1414fbb849/package/src/cmds/obfuscate.py#L1162-L1193), [obfuscate.py](https://github.com/Kangel-Plugins/ElyxBuilder/blob/b6db59093324dc5148f811c9058a6c1414fbb849/package/src/cmds/obfuscate.py#L1246-L1291), [docs](https://github.com/Kangel-Plugins/ElyxBuilder/blob/b6db59093324dc5148f811c9058a6c1414fbb849/docs/ru/obfuscation.md#L170-L215)). README/docs предупреждают, что obfuscation beta; `zlibCompression` несовместим с `.pyc`. Документированную фразу «извлечь статически невозможно» следует понимать только как авторское заявление, не проверенную гарантию криптографической защиты ([obfuscate.py](https://github.com/Kangel-Plugins/ElyxBuilder/blob/b6db59093324dc5148f811c9058a6c1414fbb849/package/src/cmds/obfuscate.py#L1088-L1160), [obfuscate.py](https://github.com/Kangel-Plugins/ElyxBuilder/blob/b6db59093324dc5148f811c9058a6c1414fbb849/package/src/cmds/obfuscate.py#L1294-L1371), [docs](https://github.com/Kangel-Plugins/ElyxBuilder/blob/b6db59093324dc5148f811c9058a6c1414fbb849/docs/ru/obfuscation.md#L107-L166)).

## CLI, локализация и runtime-граница

`elyb watch <seconds> --args "..."` — полноэкранный polling file watcher проекта; он сканирует текущую директорию, сравнивает путь/mtime, вызывает build и переносит результат в `builds/latest.<ext>`. Это не HTTP DevServer, hot reload или клиентская синхронизация. Изменения Kangel добавляют обработку ошибки `shlex.split` с понятным выходом и исправляют текст ошибки `Built failed` на `Build failed` ([cli.py](https://github.com/Kangel-Plugins/ElyxBuilder/blob/b6db59093324dc5148f811c9058a6c1414fbb849/package/src/cli.py#L35-L40), [cli.py](https://github.com/Kangel-Plugins/ElyxBuilder/blob/b6db59093324dc5148f811c9058a6c1414fbb849/package/src/cli.py#L107-L116), [watch.py](https://github.com/Kangel-Plugins/ElyxBuilder/blob/b6db59093324dc5148f811c9058a6c1414fbb849/package/src/cmds/watch.py#L25-L45), [watch.py](https://github.com/Kangel-Plugins/ElyxBuilder/blob/b6db59093324dc5148f811c9058a6c1414fbb849/package/src/cmds/watch.py#L178-L260), [docs](https://github.com/Kangel-Plugins/ElyxBuilder/blob/b6db59093324dc5148f811c9058a6c1414fbb849/docs/ru/watch.md#L1-L38)).

Kangel исправил передачу `-zf/--zipformat` в `elyb new`: аргумент передаётся в `runNew`, `writePlugin` записывает `zipFormat` в builder config. Это формат/расширение выхода, а не новый архивный encoder ([cli.py](https://github.com/Kangel-Plugins/ElyxBuilder/blob/b6db59093324dc5148f811c9058a6c1414fbb849/package/src/cli.py#L20-L22), [cli.py](https://github.com/Kangel-Plugins/ElyxBuilder/blob/b6db59093324dc5148f811c9058a6c1414fbb849/package/src/cli.py#L69-L82), [new.py](https://github.com/Kangel-Plugins/ElyxBuilder/blob/b6db59093324dc5148f811c9058a6c1414fbb849/package/src/cmds/new.py#L590-L623), [docs](https://github.com/Kangel-Plugins/ElyxBuilder/blob/b6db59093324dc5148f811c9058a6c1414fbb849/docs/ru/new.md#L11-L31)).

Генератор создаёт JSON-каталоги `strings_en.json` и `strings_ru.json`, но в проекте не обнаружен код потребления этих файлов: нет функции переводов, проверки ключей или fallback locale. Так же `refmap` перечисляет `assets`/`strings`, но клиентский ресурсный loader не входит в это репо. Вызовы `BasePlugin` в scaffold — текст generated plugin, а не API, реализованный ElyxBuilder ([new.py](https://github.com/Kangel-Plugins/ElyxBuilder/blob/b6db59093324dc5148f811c9058a6c1414fbb849/package/src/cmds/new.py#L634-L710), [tree.json](../../raw/elyxbuilder-kangel/tree.json)).

Документация и CLI не показывают проверки plugin imports или отдельную import sandbox. Generated loader-stub использует `__import__`, `getattr`, `exec` и общие globals; эта сборочная реализация выполняет код без видимого ограничения builtins. Это не следует трактовать как описание sandbox ElyxCore: сам клиентский loader отсутствует в снимке ([obfuscate.py](https://github.com/Kangel-Plugins/ElyxBuilder/blob/b6db59093324dc5148f811c9058a6c1414fbb849/package/src/cmds/obfuscate.py#L1143-L1158), [obfuscate.py](https://github.com/Kangel-Plugins/ElyxBuilder/blob/b6db59093324dc5148f811c9058a6c1414fbb849/package/src/cmds/obfuscate.py#L1246-L1289)).

Команда `elyb script` разбирает `.edsl` через lexer/parser, затем импортирует `elyb.elyxdsl.interpreter.run`; соответствующего файла interpreter нет в pinned tree, поэтому выполнение DSL и его безопасность остаются неизвестными ([script.py](https://github.com/Kangel-Plugins/ElyxBuilder/blob/b6db59093324dc5148f811c9058a6c1414fbb849/package/src/cmds/script.py#L13-L51), [tree.json](../../raw/elyxbuilder-kangel/tree.json)).

## Рабочие приёмы и ограничения

- Для обычной source-сборки `elyb build --ast -v` проверяет синтаксис, а `elyb build -o` запускает обфускацию. Для bytecode используйте `--compile` с доступным Python 3.11 и помните, что `compilationIgnore` и `obfuscationIgnore` отвечают за разные преобразования.
- `watch` годится для локального автоматического build loop; передавайте build flags строкой `--args`. Polling/rename результата не подтверждают обработку всех быстрых сохранений и не являются server/hot reload.
- Используйте `latest_mapping.json` как подсказку при отладке только для схем, где имена видны в AST. Статический loader режим возвращает пустые `functions`/`classes`; mapping не является runtime stacktrace translator.
- Считайте obfuscation бета-функцией: README и RU docs явно требуют проверять результат; runtime и совместимость `.pyc`, шифрованного архива, loader stub и `BasePlugin` не проверялись.
- `-p` использует optional `pyzipper` для ZipCrypto или AES вариантов; без `-p` код использует стандартный ZIP. Наличие шифрования не является подтверждением поддержки такого архива конкретным клиентом ([build.py](https://github.com/Kangel-Plugins/ElyxBuilder/blob/b6db59093324dc5148f811c9058a6c1414fbb849/package/src/cmds/build.py#L58-L92)).

## Неразрешённые вопросы

| Тема | Подтверждено | Не установлено |
|---|---|---|
| Два одноимённых build tools | Kangel fork является самостоятельным источником и README ссылается на shareui | Совместимость выходных архивов с клиентом и эквивалентность поведения форков |
| Package/refmap | Builder требует перечисленные ключи и включает refmap/проектные файлы | Реальная schema validation ElyxCore и трактовка архивных форматов клиентом |
| Plugin imports/runtime | Scaffold содержит текстовый `BasePlugin` пример; loader stubs генерируются в obfuscator | Реальный import resolver, sandbox, lifecycle, hooks, account/thread semantics клиента |
| Resources/i18n | Scaffold записывает каталоги `res`, `assets`, `locales` и строки EN/RU | Runtime-API чтения ресурсов, формат переводов, fallback locale |
| Validation/tests | AST parse и Python bytecode compile реализованы; source tree без CI/tests | Поведение на реальном проекте, потребительская проверка приложения и регрессионное покрытие |
| DSL | Lexer/parser и CLI call-site присутствуют | `interpreter.py` отсутствует; семантика выполнения и безопасность неизвестны |
| Loader obfuscation | Code generator содержит `exec`, `__import__`, host lookup для dynamic key | Приём клиентом, надежность защиты, совместимость `LayoutHelper` разных версий |

Нет runtime-verified результатов: ни скачанный чужой код, ни пакет не запускались и не устанавливались.
