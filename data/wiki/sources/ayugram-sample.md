# AyuSamplePlugin

Репозиторий [MrCheatEugene/AyuSamplePlugin](https://github.com/MrCheatEugene/AyuSamplePlugin) — короткий пример C++ DLL-плагина для AyuGram Desktop Plugin Engine. Зафиксирован default branch `master` и commit [`76d0514da1210e5f913c8c239713c2532d42cfea`](https://github.com/MrCheatEugene/AyuSamplePlugin/tree/76d0514da1210e5f913c8c239713c2532d42cfea); snapshot получен 2026-09-27. Репозиторий помечен GPL-3.0, а в корне находится `LICENSE.txt` с текстом GNU GPL v3. Материалы сохранены под `raw/ayugram-sample/`; SHA-256 каждого полученного файла записан в `file-manifest.json`.

## Роль и границы

Это пример нативной Windows DLL для AyuGram Desktop PLEngine, а не SDK или Android-плагин ExteraGram: README указывает Desktop PLEngine, а `.vcxproj` задаёт `DynamicLibrary` для Win32/x64. README кратко описывает предполагаемые правила `DllMain`, `pluginInfo`, `internalLoop`, потоков и фильтрации, а `AyuPlugin.h` и `dllmain.cpp` показывают структуру метаданных и демонстрационные exports. Для независимого сравнения ABI сверены также отдельные снимки PLEngine commit `55feefdb6abd702e368b12431de97313441362a0`; они не закрепляют версию engine, против которой собирался sample commit `76d0514da1210e5f913c8c239713c2532d42cfea`. Сборка и запуск не выполнялись; фактическая совместимость с конкретным AyuGram Desktop build не установлена.

Локальный snapshot дерева содержит 13 файлов, и все 13 получены. Контрольные суммы см. в [file-manifest.json](../../raw/ayugram-sample/file-manifest.json). Внешние исходники AyuGram и реализация загрузчика/ABI не входят в сам sample snapshot; отдельный PLEngine snapshot использован только для ограниченного межисточникового сравнения. Runtime, готовые бинарники, CI, тесты и устройство не входят в покрытие.

## Контракт плагина и lifecycle

`AyuPlugin.h` определяет `AyuPlugin` как фиксированные массивы `wchar_t` для имени, описания и имени модуля плюс `MemData`. Последняя хранит целочисленные адреса `applicationAddr`, `activeUserPtr`, `activeSessionPtr` и функцию `addToQueue(const std::function<void()>&)`. Эти поля выглядят как передаваемые engine ссылки на объекты и очередь; правила владения, срок жизни адресов и потокобезопасность в этом репозитории не специфицированы. См. [объявления структуры](https://github.com/MrCheatEugene/AyuSamplePlugin/blob/76d0514da1210e5f913c8c239713c2532d42cfea/AyuPlugin.h#L23-L39).

Экспортная macro задаёт `extern "C" __declspec(dllexport)` при `AYUPLUGIN`; [pch.h определяет AYUPLUGIN](https://github.com/MrCheatEugene/AyuSamplePlugin/blob/76d0514da1210e5f913c8c239713c2532d42cfea/pch.h#L1-L6). README говорит, что DLL должна вернуть TRUE из `DllMain`, чтобы загрузиться; фактический `DllMain` выполняет пустой `switch` по четырём событиям и возвращает TRUE. Комментарий автора предостерегает от сложной логики в `DllMain`, потому что `MemData` ещё не имеет валидных значений при загрузке ([README](https://github.com/MrCheatEugene/AyuSamplePlugin/blob/76d0514da1210e5f913c8c239713c2532d42cfea/README.md#L5-L10), [реализация](https://github.com/MrCheatEugene/AyuSamplePlugin/blob/76d0514da1210e5f913c8c239713c2532d42cfea/dllmain.cpp#L211-L227)).

Есть важное противоречие в `pluginInfo`: README требует валидный указатель на структуру `AyuPlugin`, typedef объявлен как `AyuPlugin* (*)()`, но export написан `InternalPluginInfo pluginInfo()` и возвращает адрес объекта `_ppluginInfo`, приведённый к указателю на функцию. В отдельном PLEngine snapshot commit `55feefdb6abd702e368b12431de97313441362a0` загрузчик вызывает `pluginInfo` как `AyuPlugin* (*)()`; тот же snapshot задаёт `FilteredState`, `bool` и `bool` как типы результатов для filter, deletion и online callbacks. Это подтверждает несоответствие типов между sample definition и проверенным engine snapshot, но не устанавливает, что именно этот commit был целевой версией sample. Считать определения безопасным ABI-шаблоном нельзя ([sample header](https://github.com/MrCheatEugene/AyuSamplePlugin/blob/76d0514da1210e5f913c8c239713c2532d42cfea/AyuPlugin.h#L41-L56), [sample implementation](https://github.com/MrCheatEugene/AyuSamplePlugin/blob/76d0514da1210e5f913c8c239713c2532d42cfea/dllmain.cpp#L32-L50), [engine typedefs](https://github.com/MrCheatEugene/AyuGramDesktop-PLEngine/blob/55feefdb6abd702e368b12431de97313441362a0/Telegram/SourceFiles/AyuPlugin.h#L37-L53), [engine loader](https://github.com/MrCheatEugene/AyuGramDesktop-PLEngine/blob/55feefdb6abd702e368b12431de97313441362a0/Telegram/SourceFiles/plengine/PLEMains.cpp#L221-L245)).

README утверждает, что engine однократно вызывает `internalSetup`, непрерывно вызывает `internalLoop` и запускает плагины в отдельных потоках. Код содержит пустой `internalLoop`; отдельный цикл отсутствует. Сам sample не доказывает, как именно engine создаёт потоки, с какой частотой вызывает hook и как останавливает плагины ([README](https://github.com/MrCheatEugene/AyuSamplePlugin/blob/76d0514da1210e5f913c8c239713c2532d42cfea/README.md#L5-L10), [callbacks](https://github.com/MrCheatEugene/AyuSamplePlugin/blob/76d0514da1210e5f913c8c239713c2532d42cfea/dllmain.cpp#L52-L53)).

Наличие определения функции само по себе не доказывает, что hook зарегистрирован либо реально вызывается клиентом.

## Практические техники, показанные кодом

- **Передача main-thread работы.** В `internalSetup` lambda захватывает `app` и `s`, берёт `s->userPeerId()` (комментарий называет это shortcut к Saved Messages), получает `History`, проверяет null, формирует `Api::MessageToSend` с текстом и передаёт его через `s->api().sendMessage(std::move(message))`; затем lambda ставится в `memData.addToQueue`. Комментарий объясняет очередь тем, что sendMessage запускает анимацию и должен работать на main thread. Это рецепт из комментариев и source, не runtime-проверка ([код](https://github.com/MrCheatEugene/AyuSamplePlugin/blob/76d0514da1210e5f913c8c239713c2532d42cfea/dllmain.cpp#L67-L86)).
- **MTProto-вызовы.** Комментарий к демонстрации `account.updateProfile` предостерегает от `ApiWrap::request` внутри DLL и предлагает `session->api().instancePtr()->sendReq(...)`; пример оборачивает `MTPaccount_updateProfile` в `tl::boxed`. Однако lambda `y` не ставится в очередь. Отдельная lambda `z` показывает `MTPaccount_SaveMusic`, ожидая документ в последнем Saved Messages; `z` также не ставится в очередь. Эти примеры не доказывают успешный запрос и описанная автором причина не проверена независимо ([update profile](https://github.com/MrCheatEugene/AyuSamplePlugin/blob/76d0514da1210e5f913c8c239713c2532d42cfea/dllmain.cpp#L88-L112), [SaveMusic](https://github.com/MrCheatEugene/AyuSamplePlugin/blob/76d0514da1210e5f913c8c239713c2532d42cfea/dllmain.cpp#L114-L147)).
- **Изменение текста перед обработкой.** `doPreProcessMessageStd` записывает regex-преобразование строки из `in` в `out`; точное место и поведение hook подтверждены только комментариями/примером sample, а не кодом engine ([код](https://github.com/MrCheatEugene/AyuSamplePlugin/blob/76d0514da1210e5f913c8c239713c2532d42cfea/dllmain.cpp#L175-L179)).
- **Исключение удаления и online policy.** Sample предлагает фильтр по username и online-политику по idle time Windows. Из-за несоответствия typedefs фактическим возвращаемым типам обе реализации требуют сверки и не должны копироваться как ABI шаблоны ([deletion](https://github.com/MrCheatEugene/AyuSamplePlugin/blob/76d0514da1210e5f913c8c239713c2532d42cfea/dllmain.cpp#L181-L183), [online](https://github.com/MrCheatEugene/AyuSamplePlugin/blob/76d0514da1210e5f913c8c239713c2532d42cfea/dllmain.cpp#L185-L209)).

## Сборка и воспроизводимость

`AyuSamplePlugin.vcxproj` задаёт DLL (`DynamicLibrary`) для Debug/Release и Win32/x64, toolset v143 и Windows SDK 10.0.26100.0; в Release|x64 указан C++20. `AyuSamplePlugin.sln` — VS 17 solution, проектные файлы включают `dllmain.cpp`, `pch.cpp`, `AyuPlugin.h`, `framework.h`, `pch.h` ([solution](https://github.com/MrCheatEugene/AyuSamplePlugin/blob/76d0514da1210e5f913c8c239713c2532d42cfea/AyuSamplePlugin.sln#L2-L14), [project configurations](https://github.com/MrCheatEugene/AyuSamplePlugin/blob/76d0514da1210e5f913c8c239713c2532d42cfea/AyuSamplePlugin.vcxproj#L3-L55), [project items](https://github.com/MrCheatEugene/AyuSamplePlugin/blob/76d0514da1210e5f913c8c239713c2532d42cfea/AyuSamplePlugin.vcxproj#L170-L179)).

README прямо говорит, что для сборки нужно переопределить каталог AyuGram. Solution включает `L:\ayu\tdesktop\out\ALL_BUILD.vcxproj` и `ZERO_CHECK.vcxproj`, а project metadata ссылается на исходники и output по абсолютным путям `M:\ayu\...`, `L:\ayu\...` и `L:\Windows Kits\...`. В Release|x64 include paths содержат Qt 6.11.0, тогда как дополнительные библиотеки включают Qt 5.15.17; конфигурации имеют различающиеся пути. Поэтому опубликованная конфигурация привязана к окружению автора и выглядит внутренне неоднородной. README советует править solution и project; сборку на другом компьютере здесь не подтверждали ([README](https://github.com/MrCheatEugene/AyuSamplePlugin/blob/76d0514da1210e5f913c8c239713c2532d42cfea/README.md#L12-L14), [solution](https://github.com/MrCheatEugene/AyuSamplePlugin/blob/76d0514da1210e5f913c8c239713c2532d42cfea/AyuSamplePlugin.sln#L6-L14), [project](https://github.com/MrCheatEugene/AyuSamplePlugin/blob/76d0514da1210e5f913c8c239713c2532d42cfea/AyuSamplePlugin.vcxproj#L111-L143)).

## Противоречия и открытые вопросы

- README советует использовать `AyuPlugin->sharedFiltersEnabled`, но `AyuPlugin` в сохранённом заголовке состоит из name, description, moduleName и memData; поля `sharedFiltersEnabled` нет.
- `pluginInfo` в README описан как функция, возвращающая валидный указатель на `AyuPlugin`, но функция/typedef в исходнике фактически используют указатель на функцию и cast адреса объекта. Сопоставленный отдельный engine snapshot ожидает обычную функцию с результатом `AyuPlugin*`; точный target commit sample не известен.
- Callback return types `doFilterHistoryItem`, `doExcludeDeleted`, `doReturnIsOnline` не согласуются между typedef в заголовке и определениями в `dllmain.cpp`.
- README ссылается на отдельный engine guide и сообщает о thread/loop behavior, но sample не содержит loader, вызовов hook, доказательств порядка регистрации или runtime результатов.
- MTProto примеры `y` и `z` определены в `internalSetup`, но не вызываются и не ставятся в очередь.
- Не установлены минимальная версия клиента, точная версия AyuGram/PLEngine, экспортная таблица DLL из готового бинарника, рабочая конфигурация сборки и поведение при выгрузке.

Эти несогласованности зафиксированы как пробелы snapshot, а не исправлены предположением. Код не запускался и не собирался; утверждений `runtime-verified` нет.
