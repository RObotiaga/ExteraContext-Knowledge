# Altuskhins/AltyLib

Источник: [репозиторий Altuskhins/AltyLib](https://github.com/Altuskhins/AltyLib), снимок `f2674328a24fd24ebc01683f2f84b92ed8470630` (`main`, версия плагина `1.0.4`, `__min_version__ = 11.9.1`). Файлы зафиксированы локально в `raw/altylib`; ссылки ниже ведут на этот неизменяемый commit. В репозитории на этом SHA всего три файла. Это монолитный ExteraGram `.plugin`, который одновременно является устанавливаемым плагином и экспортируемым модулем-библиотекой.

## Роль и границы доказательств

AltyLib полезен как набор реализованных Python/JVM-обёрток и проектных идей. Для непосредственного использования нужны импортирование/загрузка плагина AltyLib и совместимая среда ExteraGram: код импортирует `base_plugin`, `client_utils`, `hook_utils`, Telegram Java-классы, Android UI и Pillow. Источник не демонстрирует независимый Python-пакет, сборку, тесты или проверку на конкретной версии клиента. Ни один API здесь не имеет статуса runtime-verified.

Радар предлагает переносить абстракции в собственную библиотеку, а не делать AltyLib обязательной runtime-зависимостью. Это рекомендация радара, не гарантия несовместимости. Metadata API указывает минимальную версию 11.9.1; текущая совместимость с более поздними сборками из файлов не устанавливается.

## Устройство и публичный интерфейс

`Altylib.plugin` объявляет `__id__ = "altylib"`, версию `1.0.4`, автора `@altyplugins` и `__min_version__ = "11.9.1"` ([код, строки 54–60](https://github.com/Altuskhins/AltyLib/blob/f2674328a24fd24ebc01683f2f84b92ed8470630/Altylib.plugin#L54-L60)). В `__all__` явно экспортируется широкий набор API: storage, настройки, события, commands, scheduler, RPC, helpers Telegram, хуки, rate-limit, Markdown, media, UI, NotificationCenter, CLI helpers и diagnostics ([код, строки 61–89](https://github.com/Altuskhins/AltyLib/blob/f2674328a24fd24ebc01683f2f84b92ed8470630/Altylib.plugin#L61-L89)).

`send_request` импортирован из `client_utils`, поэтому существует как атрибут модуля при прямом импорте, но не перечислен в `__all__`; это не самостоятельный AltyLib wrapper и `from Altylib import *` его не экспортирует. Аналогично `log` есть в файле, но отсутствует в `__all__`; README при этом использует `alty.log` в рецептах.

## Подтверждённые API и точное поведение

### Сохранение и кеши

* `JsonCacheFile(filename: str, default: Any, read_on_init=True)`: хранит JSON под `<каталог этого plugin-файла>/cache/<filename>`. Конструктор создаёт папку и по умолчанию читает файл. Если файла нет или JSON некорректен, `read()` вызывает `wipe()` и записывает default. `write()` подавляет только `PermissionError`; каталог общий для файлов AltyLib, а значения JSON должны сериализоваться штатным `json` ([код, строки 104–138](https://github.com/Altuskhins/AltyLib/blob/f2674328a24fd24ebc01683f2f84b92ed8470630/Altylib.plugin#L104-L138)).
* `KVStore(name, *, default=None, autosave=True)`: JSON-backed store под тем же cache-каталогом; к имени автоматически добавляется `.json`, если его ещё нет. Методы: `get(key, default=None)`, `set(key, value)`, `pop(key, default=None)`, `update(mapping)`, `items()`, `clear()`, `flush()`, `__getitem__`, `__setitem__`, `__contains__`, `__len__`. Значения копируются через `deepcopy`, операции защищены `RLock`; записи сразу сохраняются при `autosave=True`, иначе вызывайте `flush()`. `default or {}` означает, что пустой/ложный default заменяется `{}` ([код, строки 1262–1333](https://github.com/Altuskhins/AltyLib/blob/f2674328a24fd24ebc01683f2f84b92ed8470630/Altylib.plugin#L1262-L1333)).
* `store_global = KVStore("altylib_global_store")` — один общий JSON namespace для импортирующих тот же модуль пользователей, а не доказанный IPC-контракт между независимо загружаемыми плагинами ([код, строки 1413–1413](https://github.com/Altuskhins/AltyLib/blob/f2674328a24fd24ebc01683f2f84b92ed8470630/Altylib.plugin#L1413-L1413)).
* `shared_set(key, value)`, `shared_get(key, default=None)`, `shared_delete(key)`, `shared_all()` оперируют одним файлом `altylib_shared_store.json`. Доступ синхронизирован одним lock; чтение возвращает deepcopy, запись использует временный `.tmp` и `os.replace`. Это файловое общее хранилище без namespace владельца и без схемы миграций ([код, строки 735–783](https://github.com/Altuskhins/AltyLib/blob/f2674328a24fd24ebc01683f2f84b92ed8470630/Altylib.plugin#L735-L783)).
* `TTLCache(*, default_ttl=None, maxsize=256)` — только память процесса. `set(key,value,ttl=None)` задаёт истечение на `now + ttl`; ложный TTL (включая `0`) трактуется как отсутствие срока. `get()` и `pop()` чистят просроченные элементы, но `get()` не обновляет expiry: скользящего TTL нет. Чистка происходит при обращении, фоновой очистки нет. Размер ограничен удалением элемента из heap/FIFO-начала, несмотря на имя `_evict_lru`; полноценного LRU по последнему чтению нет. `get_or_set(key,loader,ttl=None)` синхронно запускает loader при промахе, но check/load/set не атомарны ([код, строки 1336–1410](https://github.com/Altuskhins/AltyLib/blob/f2674328a24fd24ebc01683f2f84b92ed8470630/Altylib.plugin#L1336-L1410)).

### DSL настроек

`create_settings_registry(namespace, **kwargs) -> SettingsRegistry`; параметры конструктора: `title=None`, `store=None`. По умолчанию данные лежат в `KVStore("settings_<namespace>")`. Доступны декораторы `switch(key=None, *, default=False, title=None, summary=None, on_change=None)`, `list(key=None, *, options=None, default=None, title=None, summary=None, on_change=None)` и `slider(key=None, *, min_value=0.0, max_value=1.0, step=1.0, default=0.0, title=None, summary=None, on_change=None)`. Ключ выводится из имени декорируемой функции либо передаётся явно. Декоратор возвращает `SettingHandle`, а не исходную функцию. Регистр задаёт default только при отсутствии ключа ([код, строки 1419–1586](https://github.com/Altuskhins/AltyLib/blob/f2674328a24fd24ebc01683f2f84b92ed8470630/Altylib.plugin#L1419-L1586)).

`SettingHandle.get(default=None)`, `.set(value)`, `.toggle()` (только `switch`, иначе `TypeError`), `.value`. У registry есть `keys()`, `get(key,default=None)`, `set(key,value)`, `as_dict()`, `open(*,title=None)`. `set` не валидирует тип, список допустимых значений или границы slider; вызывает callback только при фактическом изменении уже зарегистрированного ключа. UI — `AlertDialogBuilder` со списком опций, а slider также реализован как дискретный список чисел, не ползунок. При отсутствии Activity `open_settings_screen` логирует и возвращает без UI; пустой реестр показывает bulletin ([код, строки 1433–1458, 1578–1623, 1638–1756](https://github.com/Altuskhins/AltyLib/blob/f2674328a24fd24ebc01683f2f84b92ed8470630/Altylib.plugin#L1433-L1458)).

### EventBus, команды, scheduler и RPC

* EventBus: `events_subscribe(event, callback)`, `events_unsubscribe(event, callback)`, `events_publish(event, data=None, *, async_call=True)`. Это словарь callback в памяти модуля. Подписчик получает один аргумент `data`; по умолчанию публикация ставит каждый callback на `run_on_queue`, а `async_call=False` вызывает синхронно. Исключения callback логируются. Нет namespace плагина, persistence или автоматической отписки при unload; вызывать `events_unsubscribe` нужно явно. Межплагинность README не доказывает изолированную доставку между экземплярами runtime ([код, строки 1077–1113](https://github.com/Altuskhins/AltyLib/blob/f2674328a24fd24ebc01683f2f84b92ed8470630/Altylib.plugin#L1077-L1113)).
* Commands: `register_command(name, callback, description="")`, `get_registered_commands()`, `handle_outgoing_command(plugin_self, account, params)`. Callback получает `(plugin_self, args_str, params)`. Имена нормализуются в lowercase и глобально перезаписываются. Парсер обрабатывает только текст с начальным `.` и делит имя/аргументы по первому обычному пробелу. Callback-строка заменяет `params.message`; `HookResult` проходит напрямую; другой результат приводит к `HookResult(MODIFY, params)`. Неизвестная команда возвращает `None`. Аргумент `account` функции-помощника не используется. API снятия регистрации команды нет ([код, строки 1115–1174](https://github.com/Altuskhins/AltyLib/blob/f2674328a24fd24ebc01683f2f84b92ed8470630/Altylib.plugin#L1115-L1174)).
* Scheduler: `tasks_schedule(name, callback, interval_seconds, *, run_immediately=False)`, `tasks_cancel(name)`, `tasks_list()`. Один daemon-поток проверяет глобальный словарь раз в секунду и передаёт callback в `run_on_queue`. Имена общие и повторная регистрация заменяет задачу. Интервал в записи ограничен минимумом 1 секунду, но `next_ts` рассчитывается по исходному `interval_seconds`; нулевой/отрицательный ввод поэтому может вызывать постановку задачи каждую секунду. Callback не отменяется на unload автоматически; период не привязан к account; падение callback специально не перехватывается в scheduler-коде ([код, строки 1177–1233](https://github.com/Altuskhins/AltyLib/blob/f2674328a24fd24ebc01683f2f84b92ed8470630/Altylib.plugin#L1177-L1233)).
* RPC: `rpc_register(name, func)`, `rpc_call(name, *args, **kwargs)`. Реестр в памяти процесса; регистрация с тем же именем заменяет функцию, неизвестное имя вызывает `RuntimeError`, вызов синхронный. Нет unregister, идентификатора владельца, очереди или сериализации. Название «межплагинный RPC» в README шире доказанной реализации: код показывает только in-process dispatch ([код, строки 1236–1256](https://github.com/Altuskhins/AltyLib/blob/f2674328a24fd24ebc01683f2f84b92ed8470630/Altylib.plugin#L1236-L1256)).

### Hooks и lifecycle

`safe_hook(plugin, target, method_name, hook, *, signature=None, group=None, once=True)` принимает class-name строкой (разрешает через `find_class`) или class object. Поиск идёт через declared/public methods; если передана сигнатура, список имён Java-параметров сравнивается точно. Реестр-дедуп ключуется declaring class + имя + имена типов параметров. При совпадении и `once=True` возвращается существующая регистрация, переданный новый hook не ставится; опциональная группа получает существующую запись. Регистрация ставится через `plugin.hook_method` либо `hook.hook_method`. Ошибка разрешения/установки может проброситься ([код, строки 2025–2107](https://github.com/Altuskhins/AltyLib/blob/f2674328a24fd24ebc01683f2f84b92ed8470630/Altylib.plugin#L2025-L2107)).

`HookRegistration.cancel()` вызывает `hook.unhook()` при наличии метода и помечает запись inactive даже если unhook отсутствовал или завершился ошибкой. `HookGroup.add/cancel_all()` группирует registrations. `HookLifecycle.group(name)` создаёт/возвращает группу, `HookLifecycle.cancel_all()` отменяет их. `safe_unhook_all()` отменяет записи текущего глобального реестра. Важно: класс `AltyLib.on_plugin_unload()` в этом файле сохраняет задачи автодатера и останавливает updater; он не вызывает `safe_unhook_all()`, `HookLifecycle.cancel_all()`, очистку EventBus/command/RPC/scheduler или отписку NotificationCenter. Следовательно утверждение README об автоматическом снятии на `on_plugin_unload` требует явного кода владельца и не подтверждено как встроенная автоматическая связка. Возможен риск: hook key не включает plugin owner, так что dedup и группы глобальны, а группа второго владельца может сослаться на registration первого ([код lifecycle, строки 1973–2022](https://github.com/Altuskhins/AltyLib/blob/f2674328a24fd24ebc01683f2f84b92ed8470630/Altylib.plugin#L1973-L2022); [выгрузка AltyLib, строки 538–545](https://github.com/Altuskhins/AltyLib/blob/f2674328a24fd24ebc01683f2f84b92ed8470630/Altylib.plugin#L538-L545)).

### Telegram peer, отправка и requests

* `resolve_peer(peer_like)` принимает уже готовый `TL_inputPeer*`, объекты с `dialog_id`/`id`, int, числовую строку, отрицательную строку и `@username`. ID пропускается через `MessagesController.getInputPeer`, когда метод доступен. Username делает `TL_contacts_resolveUsername` через импортированный `send_request`, ждёт callback синхронно максимум 5 секунд, затем возвращает peer или `RuntimeError`. Username lookup — блокирующий; исключение сервера/таймаут сводятся к общей ошибке. Для chat результат строится отрицательным chat ID в обоих ветвях условия `megagroup`, поэтому тип/канал отдельно не дифференцирован. Иные строки вызывают `ValueError` ([код, строки 1758–1832](https://github.com/Altuskhins/AltyLib/blob/f2674328a24fd24ebc01683f2f84b92ed8470630/Altylib.plugin#L1758-L1832)).
* `current_dialog()` извлекает `getDialogId()` или fallback `getDialogIdLong()` у последнего fragment и затем вызывает `resolve_peer`; если fragment/ID отсутствуют — `None` ([код, строки 1835–1854](https://github.com/Altuskhins/AltyLib/blob/f2674328a24fd24ebc01683f2f84b92ed8470630/Altylib.plugin#L1835-L1854)).
* `pick_dialog(identifier=None, *, title="Выберите чат", on_result=None, allow_manual_input=True)`: при identifier синхронно разрешает peer и вызывает callback; без identifier показывает EditText для username/ID, если доступна Activity и разрешён ручной ввод. Возвращаемое значение в интерактивном случае — текущий peer на момент показа, а выбранное позже передаётся через callback. Это не picker списка чатов клиента. При `allow_manual_input=False` вернёт текущий peer или `None` ([код, строки 1857–1922](https://github.com/Altuskhins/AltyLib/blob/f2674328a24fd24ebc01683f2f84b92ed8470630/Altylib.plugin#L1857-L1922)).
* `send_text(peer, text, *, reply_to=None, entities=None, silent=False)` строит `TL_messages_sendMessage`, получает random ID, задаёт reply ID из int или `.id`, добавляет Java `ArrayList` entities best-effort, опционально выставляет `silent=True`, вызывает `send_request(req, lambda *_: None)` и возвращает random ID. Callback результата/ошибки не предоставляется; ожидания подтверждения доставки нет. `send_request` сам по себе импортирован SDK helper, отдельной функции AltyLib с таким именем нет ([код, строки 1925–1967](https://github.com/Altuskhins/AltyLib/blob/f2674328a24fd24ebc01683f2f84b92ed8470630/Altylib.plugin#L1925-L1967); import: [строка 42](https://github.com/Altuskhins/AltyLib/blob/f2674328a24fd24ebc01683f2f84b92ed8470630/Altylib.plugin#L42)).

### Форматирование и rate limiting

`md(text) -> (plain_text, Telegram_entities)` поддерживает markdown-ссылки `[label](url)`, `**bold**`, `__underline__`, `~~strike~~`, backtick/double-backtick `code`; offsets при создании entity переводятся в UTF-16 code units, чтобы учитывать supplementary Unicode. Парсер упрощённый, полного Markdown/escaping/nesting-контракта нет. `split_text(text, *, limit=4096)` делит по строкам и пробелам, но считает Python `len()` (code points), не UTF-16 длину; для emoji-heavy текста ограничение Telegram в UTF-16 таким образом не гарантируется ([код md, строки 2259–2361](https://github.com/Altuskhins/AltyLib/blob/f2674328a24fd24ebc01683f2f84b92ed8470630/Altylib.plugin#L2259-L2361); [split_text, строки 2364–2399](https://github.com/Altuskhins/AltyLib/blob/f2674328a24fd24ebc01683f2f84b92ed8470630/Altylib.plugin#L2364-L2399)).

`debounce(wait_seconds, *, leading=False)` возвращает декоратор на `threading.Timer`: trailing mode выполняет только последний вызов по истечении тишины; `leading=True` вызывает первый сразу и подавляет trailing callback до таймера. `throttle(interval)` немедленно выполняет допустимый вызов, иначе запоминает последние args/kwargs и запускает один отложенный вызов. Оба выполняют функции из timer-потока; автоматически на UI thread не переключают и не возвращают результат вызова. `RateLimiter(rate, per_seconds)` имеет `.acquire() -> wait_seconds` и `.run(func,*args,**kwargs)`. Несмотря на формулировку README «acquire блокирует», сам `.acquire()` только возвращает wait и учитывает будущий timestamp; блокирует только `.run()`, используя `time.sleep`. Это синхронный ограничитель, не Telegram FloodWait handler и не учёт серверных ошибок ([код, строки 2118–2217](https://github.com/Altuskhins/AltyLib/blob/f2674328a24fd24ebc01683f2f84b92ed8470630/Altylib.plugin#L2118-L2217)).

`priority_queue_worker() -> submit`: создаёт отдельный daemon worker с `PriorityQueue`; `submit(callback, *, priority=10)` добавляет работу (меньшее число имеет приоритет) и FIFO-связку через счётчик. Это общая утилита очереди, не специальный Telegram request queue ([код, строки 2220–2244](https://github.com/Altuskhins/AltyLib/blob/f2674328a24fd24ebc01683f2f84b92ed8470630/Altylib.plugin#L2220-L2244)).

### Media, UI, NotificationCenter и диагностика

`download_media(message, *, blocking=False, priority=FileLoader.PRIORITY_NORMAL)` обрабатывает только media `document`/`getDocument`, вычисляет путь, вызывает FileLoader и опционально ждёт наличие файла до ~10 секунд с опросом каждые 100 мс. Для фото-ветки отдельного пути не видно; в неблокирующем режиме путь возвращается до завершения загрузки. `save_to_gallery(path)` использует `Utilities.addMediaToGallery`, затем fallback `MediaController.saveFile`, ошибки только логируются. `with_image(path, fn)` открывает через Pillow, вызывает callback, и если callback вернул `Image`, перезаписывает исходный файл; иное возвращаемое значение только передаётся вызывающему ([код, строки 2402–2470](https://github.com/Altuskhins/AltyLib/blob/f2674328a24fd24ebc01683f2f84b92ed8470630/Altylib.plugin#L2402-L2470)).

Bulletin helpers (`bulletin_info/error/success`) планируют вызов через `run_on_ui_thread`; `success` fallback на `BulletinHelper.show` если нет `show_success`. Snackbar wrappers используют `show_info/show_warning/show_error`, а `snackbar_undo` — AlertDialog с кнопкой Undo, не нативный Snackbar undo. `show_spinner(text=None)` хранит только один global builder, повторный вызов ничего не меняет; `hide_spinner()` dismiss. `quick_list_pick(options, *, title="Выберите", on_select=None,cancel_text="Отмена")` и `show_bottom_sheet(options, *, title="Действия", on_select=None)` используют AlertDialog; bottom sheet best-effort включает `setUseBottomSheet`. Эти три dialog helpers требуют текущую Activity и вызываются на потоке вызывающего кода (автоматический UI dispatch в их функциях не виден). `copy_to_clipboard(text,label="AltyLib")` копирует и показывает snackbar ([код UI, строки 791–870, 2473–2578](https://github.com/Altuskhins/AltyLib/blob/f2674328a24fd24ebc01683f2f84b92ed8470630/Altylib.plugin#L791-L870)).

`@on(event_name, *, account=0)` находит event ID как поле `NotificationCenter`, регистрирует dynamic proxy у `getInstance(account)`, по количеству параметров вызывает callback как `(account,args)` либо `(args)`. Неизвестное имя — `ValueError`; observer удаляется `_clear_notification_observers()` через `atexit`, но в реестре нет владельца plugin и unload callback ([код, строки 2581–2648](https://github.com/Altuskhins/AltyLib/blob/f2674328a24fd24ebc01683f2f84b92ed8470630/Altylib.plugin#L2581-L2648)).

`install_crash_reporter(log_file=None)` устанавливает глобальный `sys.excepthook`, пишет traceback в файл и зовёт старый hook. `enable_hot_reload(*module_names)` только запоминает имена; `reload_current_plugin(*module_names)` применяет `importlib.reload` к модулям, уже найденным в `sys.modules`, затем показывает snackbar. Это не горячая перезагрузка `.plugin` самим клиентом и не пересоздание объектов/хуков. `features_register/has/clear_cache` — in-memory cache detector results; ошибки detector дают cached `False` до сброса ([код diagnostics, строки 2714–2823](https://github.com/Altuskhins/AltyLib/blob/f2674328a24fd24ebc01683f2f84b92ed8470630/Altylib.plugin#L2714-L2823)).

### Прочие экспортируемые утилиты

* `detect_client()` проверяет путь `ApplicationLoader.getFilesDir()` на строки ExteraGram/AyuGram; при любой неопознанной среде возвращает `"ayugram"`. Это эвристика по package path, а не надёжное обнаружение версии/API ([код, строки 548–570](https://github.com/Altuskhins/AltyLib/blob/f2674328a24fd24ebc01683f2f84b92ed8470630/Altylib.plugin#L548-L570)). `detect_language()` сначала читает `LocaleController`, затем Python locale, и по умолчанию отдаёт `"en"` ([код, строки 713–732](https://github.com/Altuskhins/AltyLib/blob/f2674328a24fd24ebc01683f2f84b92ed8470630/Altylib.plugin#L713-L732)).
* `get_plugins_dirs()` сначала пытается взять `PluginsManager._plugins_dir`, затем добавляет фиксированные `/data/user/0/.../files` каталоги для ExteraGram, Telegram Web и AyuGram. Это candidate directories, без проверки существования и без включения подкаталогов ([код, строки 873–897](https://github.com/Altuskhins/AltyLib/blob/f2674328a24fd24ebc01683f2f84b92ed8470630/Altylib.plugin#L873-L897)).
* `add_tg_alias(path, callback)` регистрирует префикс `tg://` и вызывает callback с исходным Intent на UI thread; `remove_tg_alias(path)` удаляет регистрацию. Hook для `LaunchActivity.handleIntent` ставится при загрузке AltyLib, но `_tg_hook_installed` остаётся true даже если поиск метода не удался, поэтому автоматическая повторная попытка не гарантирована ([код, строки 956–1075](https://github.com/Altuskhins/AltyLib/blob/f2674328a24fd24ebc01683f2f84b92ed8470630/Altylib.plugin#L956-L1075)).
* `hide_my_commands(plugin_id=None)` добавляет id (или id вызывающего plugin module) в глобальный список и пытается monkey-patch `command_list_by_mihailkotovski` CommandHarvester, фильтруя ключи команд по вхождению id/display name. Это best-effort интеграция с конкретным сторонним plugin, а не универсальный API host ([код, строки 594–712](https://github.com/Altuskhins/AltyLib/blob/f2674328a24fd24ebc01683f2f84b92ed8470630/Altylib.plugin#L594-L712)).
* `log(string)` пишет в Android logcat и внутренний FIFO-буфер максимум 500 строк; `get_logs(limit=200)` возвращает последние строки, `clear_logs()` очищает буфер. `log` не входит в `__all__`, хотя README обращается к нему как к `alty.log` ([код, строки 343–376](https://github.com/Altuskhins/AltyLib/blob/f2674328a24fd24ebc01683f2f84b92ed8470630/Altylib.plugin#L343-L376)).

### Автообновление, медиа и вспомогательные экспорты

Плагин AltyLib сам запускает `AutoUpdater` при `on_plugin_load()`: добавляет собственную задачу по каналу `AltyPlugins`, загружает сохранённые задачи, если автообновление включено, и проверяет их с интервалом из настройки `autoupdate_timeout` (по умолчанию 600 секунд). `add_autoupdater_task(plugin_id, channel_id, channel_username, message_id)` добавляет задачу или сохраняет её в `pending_tasks_cache`, если updater ещё не создан; `remove_autoupdater_task(plugin_id)` удаляет задачу по ID. Каждая запись ищет до 50 сообщений канала, затем выбирает указанное сообщение. `is_valid_plugin_message` принимает документ с первым атрибутом-именем файла, заканчивающимся на `.plugin`. Ошибка запроса или неподходящее сообщение удаляет задачу. При совпадающем `edit_date` обновление пропускается, если настройка `disable_ts_check` выключена; загруженный плагин передаётся в `PluginsController.loadPluginFromFile`. На `on_plugin_unload()` текущие задачи сохраняются в JSON и updater получает флаг остановки, но поток не join-ится; это не очищает другие module-global системы ([код, строки 149–272, 275–340, 380–419, 437–545](https://github.com/Altuskhins/AltyLib/blob/f2674328a24fd24ebc01683f2f84b92ed8470630/Altylib.plugin#L149-L272)). Это source inspection, а не проверка фактической доставки/установки обновления на клиенте.

`get_messages(channel_id, channel_username, callback)` запрашивает историю с `limit=50`; если `getInputPeer(channel_id)` не содержит `access_hash`, пробует разрешить канал по username. `get_message(messages, message_id)` сканирует Java-коллекцию и возвращает совпадение или `None`. `download_and_install_plugin(msg)` устанавливает уже скачанный документ, а если локального файла ещё нет — запускает `FileLoader.loadFile`; успешное завершение этой второй ветви само по себе не вызывает установку. `is_valid_plugin_message` предполагает наличие document attributes и обращается к первому атрибуту, поэтому пустой список атрибутов может привести к исключению вместо `False` ([код, строки 275–340](https://github.com/Altuskhins/AltyLib/blob/f2674328a24fd24ebc01683f2f84b92ed8470630/Altylib.plugin#L275-L340)).

`save_to_gallery(path)` требует существующий файл и сначала вызывает `Utilities.addMediaToGallery`, затем пробует `MediaController.saveFile`; если оба способа завершаются ошибкой, функция только логирует её. `get_current_activity()` возвращает parent Activity последнего fragment или `None`. `snackbar_info/warn/error` ищут соответствующие методы `BulletinHelper` и только логируют при отсутствии метода; `snackbar_undo` фактически показывает `AlertDialogBuilder` с кнопкой отмены. `copy_to_clipboard(text, label="AltyLib")` вызывает `Utilities.copyToClipboard`, затем показывает информационный snackbar; ошибка копирования подавляется с записью в log ([код, строки 791–801, 2443–2455, 2476–2507, 2573–2578](https://github.com/Altuskhins/AltyLib/blob/f2674328a24fd24ebc01683f2f84b92ed8470630/Altylib.plugin#L791-L801)).

Экспортируемые `list_recipes()` и `load_recipe(name)` дают три встроенных cookbook-записи (`auto_responder`, `media_autosave`, `quick_translate`): первый возвращает словарь описаний, второй — запись с `title`, `description`, `steps` и выбрасывает `KeyError` для неизвестного имени. Это статические подсказки, не готовые/проверенные реализации сценариев ([код, строки 2826–2868](https://github.com/Altuskhins/AltyLib/blob/f2674328a24fd24ebc01683f2f84b92ed8470630/Altylib.plugin#L2826-L2868)).

## Практические рецепты, выводимые из реализации

**JSON-настройки:** создать `registry = create_settings_registry("my_plugin", title="...")`; объявить `@registry.switch(default=False)` и `@registry.list(options=[("Label","value")], default="value")`; сохранить возвращённые `SettingHandle` в переменные; читать через `.get()`/`.value`, изменить `.set()`, UI вызвать `registry.open()`. Самостоятельно валидировать выбранные значения при чтении/записи, если важна схема.

**Hook с явным cleanup:** создать `life = HookLifecycle()`, `group = life.group("feature")`; вызвать `safe_hook(self, "fully.qualified.Class", "method", HookSubclass(), group=group, signature=[...])`; в `on_plugin_unload()` вызвать `life.cancel_all()`. Не полагаться на название lifecycle manager как на автоподключение. Проверить, что используемый MethodHook предоставляет `unhook()` в целевом SDK.

**Исходящая команда:** вызвать `register_command("echo", callback, description)` во время загрузки и в своём `on_send_message_hook` первым обработать `handle_outgoing_command(self, account, params)`; если вернулся не-None `HookResult`, вернуть его. Так как API снятия команды отсутствует, при reload/повторном импорте учитывать глобальную перезапись по имени.

**Кеш сетевого результата:** `cache = TTLCache(default_ttl=30, maxsize=128)`; считать чтение fixed-expiry, помнить что cache не сохраняется на диск, а `acquire()`/`get_or_set()` не предназначены для blocking I/O гарантий или конкурентного single-flight.
