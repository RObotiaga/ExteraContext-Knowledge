## Роль и граница источника

Это исходник одного пользовательского Android-плагина, а не SDK, шаблон общего назначения или доказательство публичного API ExteraGram. Он полезен как пример перехвата исходящего сообщения, асинхронного сетевого поиска, сохранения account/reply/thread-контекста, Android UI из Python и настраиваемого форматирования карточки. По `metainfo.yml` плагин заявляет `app_version >=12.8.1`, `sdk_version >=1.4.4.3`, версию `0.3.38` и пустой список `requirements`. Это метаданные проекта, не проверка совместимости. При этом `api.py` импортирует `requests`; наличие библиотеки в поставляемом клиенте или способ её упаковки снимок не объясняет.

Радар назвал репозиторий поисковым результатом, который не выглядит полноценным инструментом разработки. Изученный код уточняет это: перед нами интеграционный плагин поиска и отправки карточки, а не набор средств создания плагинов. Публичную совместимость его helper-вызовов со всеми версиями ExteraGram/AyuGram этот проект не устанавливает.

## Архитектура и call-sites

`refmap.yml` указывает `main.py` как entry point. `Anilist_Anime(BasePlugin)` инициализирует настройки/кэши, а `on_plugin_load()` регистрирует `add_on_send_message_hook(priority=100)`. Hook проверяет текст исходящего сообщения, собирает peer, reply и topic/thread-поля из `params`, затем уводит работу на `run_on_queue`. При результатах поиска popup создаётся через `run_on_ui_thread`; выбор из popup снова вызывает callback на рабочей очереди. Для пустого tag/search query и исключения до конца обработчика возвращается `HookResult()` без явного `CANCEL`; код не подтверждает, как целевой SDK интерпретирует этот default. В классе не найден отдельный `on_plugin_unload`; автоматическую очистку зарегистрированного hook host-приложением этот снимок не раскрывает. Потоковые вызовы и lifecycle семантика host SDK в исходнике не входят.

## Приёмы, подтверждённые кодом

- Отделяйте callback перехвата composer от сетевой работы: здесь hook фиксирует контекст и ставит `process_search`/`process_multi_search` на `run_on_queue`, а popup вызывается через `run_on_ui_thread`. При переносе сверяйте семантику очередей и отмены отправки с целевым SDK.
- Для воспроизводимой reply/topic-отправки храните `peer`, `replyToMsg`, `replyToTopMsg` и `messageThreadId` в одном `base` контексте и затем добавляйте только заполненные поля в параметры helper-а отправки. Код также передаёт отдельный `account`, чтобы не потерять аккаунт источника hook.
- Два провайдера можно держать за отдельным API/парсером и выбирать их независимо для обычного текстового поиска, поиска по ID и сезонного списка. В этом проекте индексы selector значений и fallback-ы `use_anilist`/`use_shikimori` определяют маршрутизацию; значения должны быть согласованы между UI и `update_settings()`.
- Списки жанров/тегов формируются относительно mapping: промо-теги с достаточным `rank` могут быть показаны среди жанров, genre-like tags исключаются из тегов, а флаги spoiler поступают в форматтер. Это пример политики отображения проекта, не контракт AniList API.
- При сетевой интеграции обрабатывайте timeout, общий HTTP error, forbidden/disabled и rate-limit отдельно. В реализации 403 превращается в `<tag>_disabled`, 429 повторяется ограниченное число раз, а остальные ошибки и исключения сворачиваются в `<tag>_error`; подробности API error body теряются.
- Ограничивайте сезонные запросы: AniList до четырёх страниц по 50 записей, с дедупликацией по media ID и остановкой по `hasNextPage`; Shikimori также ограничивает число страниц. Это политика данного плагина, а не гарантия полноты внешнего каталога.

## Технические детали

AniList queries статически описаны в `constants.py`: одиночный текстовый поиск и `Media(id:)`/`Media(idMal:)` выбирают anime и возвращают поля заголовков, synonyms, country/season/year/format, genres, tags с rank/spoiler, episodes/status/description, score/duration/studios, cover и next airing. Multi-search запрашивает до 50 элементов с меньшим набором полей; жанр/тег сортируется по популярности. Для расписания выбирается сезон календарного квартала в UTC, затем `RELEASING`, `isAdult:false`, popularity descending.

GraphQL helper выставляет фиксированные браузероподобные заголовки и JSON body. Статусы `403`, `429` и прочие `>=400` разделены; GraphQL `errors` без `data` дают ошибку, но ответ с `data` возвращается даже при наличии `errors`. При ошибке сети повторяется максимум трижды: пауза 0.5 с между исключениями, 1 с между повторными 429. Timeout — 10 с. Это описание кода; причина 403 в комментарии приписана Cloudflare, но независимая проверка причины не проводилась.

Плагин распознаёт настраиваемые команды поиска, тегов, ongoing и редактора шаблона. Приоритет длинных команд предотвращает перехват более короткого совпадения; чистые URL игнорируются. Пустой запрос-команда может использовать текст reply. Hook подготавливает base-контекст до ухода на очередь. Для `search_ui_mode == 0` результаты выбираются в popup; альтернативный режим принимает одну или несколько строк заголовков и пытается обработать до пяти кандидатов.

Mapping допускает URL или inline JSON из persisted setting. Загрузка HTTP использует timeout 8 с и User-Agent `ANI`; невалидный JSON/сетевая ошибка молча переводит карту в пустой объект. Псевдонимы AniList строятся из четырех секций (`main_genres`, `additional_genres`, `main_tags`, `additional_tags`), Shikimori — из ключей и русских вариантов в его разделе. Разделители могут иметь область `genres`, `tags`, `both` или `unknown`; включение, hash, underscore и comma-опции сохраняются в plugin settings.

Кэш поиска и mapping — поля объекта plugin в памяти. Есть дополнительное подавление одинакового исходящего текста на 5 секунд (ключ — hash первых 200 символов); записи подавления очищаются после 30 секунд. В `cleanup_old_cache` удаляются только tuple-значения с меткой времени старше 1800 секунд. Эти механизмы не являются постоянным хранилищем и не переживают перезапуск, судя по покрытому коду.

Форматтер выбирает несколько альтернативных ru/en заголовков, строит country/season/year, genre/tag, формат, целевую аудиторию и остальные переменные, затем подставляет их в настраиваемый template. Источник описания выбирается setting-ом между Shikimori и AniList; cover выбирается между AniList URL и Shikimori poster. Есть разделение отправки card и description, HTML/Markdown parse modes, preview/media placement options и переключатели наличия ссылок. Настройки и preview подтверждают наличие UI call-sites, но не их визуальную корректность на конкретной версии клиента.

## Ограничения и неразрешённые вопросы

1. Нет README, LICENSE, тестов, CI/build manifest или инструкции ручной сборки. Репозиторий metadata также не указывает SPDX license. Лицензия и полный install/build workflow остаются неизвестны.
2. Заявления `app_version >=12.8.1` и `sdk_version >=1.4.4.3` взяты из `metainfo.yml`; тесты на соответствующих или иных версиях ExteraGram не представлены. Нельзя распространять эти границы на AyuGram без свидетельств.
3. В коде используется `requests`, но `requirements: []`; dependency availability, bundling и import lifecycle не объяснены.
4. Никакая функция не `runtime-verified`: код и API не запускались в клиенте или Android эмуляторе. UI, очередь, системный popup, media send, сеть и команды остаются непроверенными на устройстве.
5. Заголовок User-Agent установлен на Chrome 128, а комментарий объясняет его обходом Cloudflare; нет capture или документа, доказывающего необходимость/эффективность этого поведения.
6. Mapping по умолчанию ссылается на отдельный репозиторий `Islite/mapping-genre-tag-list-ExteraGram` по плавающей `main`; в данной работе не закреплялся ни его commit, ни его актуальное содержимое. Локальный `mapping.json` закреплён commit AniList.co и не доказывает тождество внешнему mapping endpoint.
7. На старте отсутствие/ошибка mapping скрывается и принимается пустой объект; интерфейс имеет ручное обновление, но гарантии успешной синхронизации нет.
8. Внешние AniList/Shikimori API contracts, rate limits и политика доступа на дату работы отдельно не сверялись с официальной спецификацией. Описаны только запросы, реализованные в закреплённом коде.

TemplateEditor вставляет placeholders названий и полей карточки, позволяет менять видимость отдельных placeholders долгим нажатием, отображает preview и хранит до 20 состояний для undo/redo; сохранение пишет `card_template` через plugin settings и вызывает `update_settings()`. Настройки формата используют custom collapsible rows для групп полей/жанров/тегов и отдельный mode picker; код содержит Android UI calls, но эти окна не запускались на устройстве. Popup выбора также несёт account/base/send-options через callback; долгое нажатие включает multi-select, затем каждый выбранный результат ставится на очередь с общими контекстом и временными параметрами `card_send_mode`, `invert`, `no_link`, `temp_pos`. Эти overrides передаются callback-у и в UI локальны, а не записываются как persisted setting ([popup_ui.py](https://github.com/Islite/AniList.co/blob/69d542a692e13713a859869899679a80cb73eb55/anilist_anime/popup_ui.py#L331-L349), [send options](https://github.com/Islite/AniList.co/blob/69d542a692e13713a859869899679a80cb73eb55/anilist_anime/popup_ui.py#L838-L860)).
