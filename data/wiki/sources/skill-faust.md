## Технические сведения

### Формат и жизненный цикл плагина

README показывает metadata как простые top-level dunder-константы (`__id__`, `__name__`, `__description__`, `__author__`, `__version__`, `__icon__`, `__app_version__`, `__sdk_version__`, необязательный `__requirements__`) и класс от `BasePlugin`; текст утверждает, что metadata разбирается AST, `__id__` допускает 2–32 латинских символа/цифры/`_`/`-`, а файл должен быть ASCII ([строки 20–29, 102–126](https://github.com/faustyu1/exteragram-plugins-skill/blob/07ec5d517eeade413f0885339c5d50f9d0d7910f/README.md#L20-L29)). README называет `on_plugin_load` и `on_plugin_unload` точками включения/выключения, перечисляет `AppEvent.START/STOP/PAUSE/RESUME`, settings helpers `get_setting`, `set_setting`, `export_settings`, `import_settings` и `self.log` ([строки 130–161](https://github.com/faustyu1/exteragram-plugins-skill/blob/07ec5d517eeade413f0885339c5d50f9d0d7910f/README.md#L130-L161)). Гарантии момента вызова, сохранения настроек и поведения при восстановлении не сверялись с движком.

Текст описывает плагины в каталоге `/data/user/0/com.exteragram.messenger/files/plugins/`, где `__file__` якобы указывает на `.py`, а `os.path.dirname(__file__)` совпадает с `get_plugins_dir()` ([строки 31–42](https://github.com/faustyu1/exteragram-plugins-skill/blob/07ec5d517eeade413f0885339c5d50f9d0d7910f/README.md#L31-L42)). Схема импортов приведена как `base_plugin`, `ui.settings`, `client_utils`; README отдельно отвергает `exteraPlugin.*` и `jnius.autoclass` для описываемого SDK ([строки 20–27, 961–978](https://github.com/faustyu1/exteragram-plugins-skill/blob/07ec5d517eeade413f0885339c5d50f9d0d7910f/README.md#L961-L978)).

**Формат `.plugin` внутренне противоречив.** В начале говорится, что `.plugin` всегда является голым Python-файлом и ZIP не работает из-за чтения парсером как UTF-8/AST; далее тот же README описывает `calculator.plugin` как ZIP с `plugin.py` и `libcalc.so` и кодом распаковки через `zipfile` ([строки 22–23, 44–72](https://github.com/faustyu1/exteragram-plugins-skill/blob/07ec5d517eeade413f0885339c5d50f9d0d7910f/README.md#L22-L23), повтор запрета на ZIP — [строки 961–967](https://github.com/faustyu1/exteragram-plugins-skill/blob/07ec5d517eeade413f0885339c5d50f9d0d7910f/README.md#L961)). До разрешения этого конфликта формат контейнера нельзя считать установленным по данному источнику.
**Base64 также противоречит самому себе:** critical facts и Pitfalls запрещают вкладывать бинарник в исходник из-за AST-парсинга и заявленного сбоя/зависания около 4 MB, но отдельный раздел приводит пример декодирования `.so` из base64 ([строки 29, 922–936, 964–976](https://github.com/faustyu1/exteragram-plugins-skill/blob/07ec5d517eeade413f0885339c5d50f9d0d7910f/README.md#L29)). Это пример документации, его совместимость с парсером не проверялась.

### Hooks, меню и settings

Документ говорит регистрировать callbacks в `on_plugin_load`: `add_on_send_message_hook()` и `add_hook(request_name)`. Приведены `on_send_message_hook(account, params)`, `pre_request_hook(request_name, account, request)`, `post_request_hook(request_name, account, response, error)`, `on_update_hook(update_name, account, update)` и `on_updates_hook(container_name, account, updates)`. В примерах `HookResult()` оставляет данные без изменения, `MODIFY` возвращает изменённый `params`/`request`/`response`, `CANCEL` отменяет операцию, `MODIFY_FINAL` изменяет и останавливает дальнейшую обработку ([строки 165–215](https://github.com/faustyu1/exteragram-plugins-skill/blob/07ec5d517eeade413f0885339c5d50f9d0d7910f/README.md#L165-L215)).

Для меню показан `MenuItemData(menu_type, text, on_click, icon, subtext, priority)`, типы `MESSAGE_CONTEXT_MENU`, `DRAWER_MENU`, `CHAT_ACTION_MENU`, `PROFILE_ACTION_MENU` и context keys для account/dialog/user/chat/message; пример сохраняет id из `add_menu_item` и вызывает `remove_menu_item` в unload callback ([строки 219–248](https://github.com/faustyu1/exteragram-plugins-skill/blob/07ec5d517eeade413f0885339c5d50f9d0d7910f/README.md#L219-L248)).

`create_settings() -> List[Any]` в README возвращает строки `Header`, `Divider`, `Switch`, `Selector`, `Input`, `EditText`, `Text`, `Custom`; документ задаёт типы значений (`Switch.default: bool`, `Selector.default: int`, `Selector.items: List[str]`, `Input.default: str | None`) и перечисляет callbacks, nested page и параметры `Custom` ([строки 252–322](https://github.com/faustyu1/exteragram-plugins-skill/blob/07ec5d517eeade413f0885339c5d50f9d0d7910f/README.md#L252-L322)).

### Xposed, reflection и Java proxy

Пример Xposed API использует `MethodHook.before_hooked_method/after_hooked_method`, `MethodReplacement.replace_hooked_method`, `find_class`, Java reflection `getDeclaredMethod`/`setAccessible`, затем `hook_method`, `hook_all_methods`, `hook_all_constructors` и `unhook_method` ([строки 326–368](https://github.com/faustyu1/exteragram-plugins-skill/blob/07ec5d517eeade413f0885339c5d50f9d0d7910f/README.md#L326-L368)). `HookFilter` примеры позволяют фильтровать аргументы и результат, включая `ArgumentIsNull`, `ArgumentEqual`, `RESULT_NOT_NULL`, `ResultIsInstanceOf`, `Condition` и `Or`; `param` раскрывает `thisObject`, изменяемые `args`, `method`, `getResult()` и `setResult()` ([строки 370–400](https://github.com/faustyu1/exteragram-plugins-skill/blob/07ec5d517eeade413f0885339c5d50f9d0d7910f/README.md#L370-L400)). Это декларативные примеры, не гарантия наличия методов в каждой сборке.

`hook_utils` перечисляет `find_class`, `get_private_field`, `set_private_field` и static-варианты; README предупреждает проверять `None` и обрабатывать ошибки, называя reflection хрупкой ([строки 538–550](https://github.com/faustyu1/exteragram-plugins-skill/blob/07ec5d517eeade413f0885339c5d50f9d0d7910f/README.md#L538-L550)). `extera_utils.classes` описан как создание Java-классов через DexMaker: `java_subclass`, `joverride`, `joverload`, `jmethod`, `jfield`, `jconstructor`, `jpreconstructor`, MVEL helpers и `J`; пример различает Python peer `new_instance()` и сырой Java object `.java` ([строки 657–735](https://github.com/faustyu1/exteragram-plugins-skill/blob/07ec5d517eeade413f0885339c5d50f9d0d7910f/README.md#L657-L735)). Pitfalls заявляют, что `J(obj)` не различает overloads и `super()` работает только с `@joverride`/`@joverload` ([строки 961–978](https://github.com/faustyu1/exteragram-plugins-skill/blob/07ec5d517eeade413f0885339c5d50f9d0d7910f/README.md#L961-L978)).

`client_utils` каталогизирует очереди (`PLUGINS_QUEUE`, `GLOBAL_QUEUE`, `STAGE_QUEUE`, `CACHE_CLEAR_QUEUE`, `SEARCH_QUEUE`, `PHONE_BOOK_QUEUE`, `THEME_QUEUE`, `EXTERNAL_NETWORK_QUEUE`), `run_on_queue(func, queue, delay)` и controllers/getters ([строки 404–429](https://github.com/faustyu1/exteragram-plugins-skill/blob/07ec5d517eeade413f0885339c5d50f9d0d7910f/README.md#L404-L429)). Примеры показывают `send_request(TLObject, callback)`, текст/фото/документ/видео/аудио отправку с `parse_mode`, низкоуровневый `send_message(params, parse_mode)` и `edit_message(message_obj, ...)` ([строки 431–469](https://github.com/faustyu1/exteragram-plugins-skill/blob/07ec5d517eeade413f0885339c5d50f9d0d7910f/README.md#L431-L469)). `NotificationCenterDelegate.didReceivedNotification(id, account, args)` регистрируется через `get_notification_center().addObserver`; в примере снятие observer показано как комментарий ([строки 471–487](https://github.com/faustyu1/exteragram-plugins-skill/blob/07ec5d517eeade413f0885339c5d50f9d0d7910f/README.md#L471-L487)).

`android_utils` перечисляет `log`, `run_on_ui_thread(fn, delay=0)`, `copy_to_clipboard`, `R`, click/long-click listener proxies; README предписывает выполнять касающуюся UI работу через `run_on_ui_thread` ([строки 491–509](https://github.com/faustyu1/exteragram-plugins-skill/blob/07ec5d517eeade413f0885339c5d50f9d0d7910f/README.md#L491-L509)). `parse_text(text, parse_mode, is_caption)` демонстрируется для HTML/Markdown и возвращает словарь с текстом/caption и entity; поддерживаемые форматирующие формы перечислены далее ([строки 513–534](https://github.com/faustyu1/exteragram-plugins-skill/blob/07ec5d517eeade413f0885339c5d50f9d0d7910f/README.md#L513-L534)).

`file_utils` перечень включает каталоги plugins/cache/files/images/videos/audios/documents и `ensure_dir_exists`, `list_dir`, `write_file`, `read_file`, `delete_file`; пример специально создаёт директорию прежде записи и указывает, что `write_file` её сам не создаёт ([строки 554–574](https://github.com/faustyu1/exteragram-plugins-skill/blob/07ec5d517eeade413f0885339c5d50f9d0d7910f/README.md#L554-L574)). Для UI README даёт `AlertDialogBuilder` с message/loading/spinner, кнопками, списком и progress, и `BulletinHelper` для info/error/success/undo и иных уведомлений; утверждается, что helper bulletin автоматически выполняет на UI thread ([строки 578–653](https://github.com/faustyu1/exteragram-plugins-skill/blob/07ec5d517eeade413f0885339c5d50f9d0d7910f/README.md#L578-L653)).

### Пакеты, классы Telegram и примеры

Для `__requirements__` README допускает только pure-Python `none-any.whl`, отвергает перечисленные native extensions (`numpy`, `pandas`, `scipy`, `cryptography`, `opencv`), перечисляет разрешённые примеры и предустановленные `beautifulsoup4`, `debugpy`, `lxml`, `packaging`, `pillow`, `requests`, `PyYAML` ([строки 739–750](https://github.com/faustyu1/exteragram-plugins-skill/blob/07ec5d517eeade413f0885339c5d50f9d0d7910f/README.md#L739-L750)). Доступность пакетов в установленном приложении не проверялась.

Справочник перечисляет Telegram-классы и FQCN для LaunchActivity, ProfileActivity, ChatActivity, MessageObject, ChatMessageCell, AndroidUtilities, controllers/helpers, BulletinFactory, AlertDialog и TLRPC; схема TL дана внешней ссылкой `corefork.telegram.org/schema` ([строки 754–771](https://github.com/faustyu1/exteragram-plugins-skill/blob/07ec5d517eeade413f0885339c5d50f9d0d7910f/README.md#L754-L771)).

Полный образец `CalcPlugin` регистрирует outgoing hook, settings, распознаёт `.calc `, фильтрует выражение регулярным выражением, вызывает `eval` с ограниченным словарём и затем либо посылает ответ + возвращает `CANCEL`, либо меняет `params.message` и возвращает `MODIFY` ([строки 775–842](https://github.com/faustyu1/exteragram-plugins-skill/blob/07ec5d517eeade413f0885339c5d50f9d0d7910f/README.md#L775-L842)). Это код-пример в документации, не тестировалось; безопасность фильтра/`eval` не подтверждена анализом Python sandbox и не должна пониматься как audited safe-eval recipe.

### Go cdylib и доставка

README демонстрирует сборку Go `c-shared` для Android arm64 через `GOOS=android`, `GOARCH=arm64`, `CGO_ENABLED=1` и NDK clang уровня API 26; Python загружает `.so` через `ctypes.CDLL`, задаёт `argtypes/restype`, а Go экспортирует C-функцию через `import "C"` и `//export` ([строки 74–89, 846–901](https://github.com/faustyu1/exteragram-plugins-skill/blob/07ec5d517eeade413f0885339c5d50f9d0d7910f/README.md#L846-L901)). В README есть неодинаковые утверждения об управлении памятью возвращённой Go-строки: один пример предлагает `FreeString`, другой пишет, что Go GC освободит строку; это не согласовано и не проверено. Сборка не выполнялась.

Описанный ADB flow предлагает копировать `.plugin` на `/sdcard/`, затем импортировать через UI; прямой push в app-private `/data/user/0/...` указан как требующий root/debuggable build ([строки 91–98, 912–920](https://github.com/faustyu1/exteragram-plugins-skill/blob/07ec5d517eeade413f0885339c5d50f9d0d7910f/README.md#L91-L98)). Между ними приведён без оговорки прямой push самого плагина и `.so` в тот же app-private каталог ([строки 903–908](https://github.com/faustyu1/exteragram-plugins-skill/blob/07ec5d517eeade413f0885339c5d50f9d0d7910f/README.md#L903-L908)), что прямо расходится с ограничением выше. В fact layer это оставлено одним конфликтом ADB, без превращения ни одного из маршрутов в проверенную инструкцию.

## Ограничения и открытые вопросы

- Требование задания изучить именно `plugin-development/SKILL.md` и support files невозможно выполнить на зафиксированном снимке: полное дерево содержит один `README.md`; ожидаемые пути не существуют. Не выдавать содержимое других repo/веток за часть этого SHA.
- README одновременно утверждает, что `.plugin` всегда bare Python, и описывает ZIP container; одновременно запрещает base64 payload, а затем предлагает его; ADB direct-to-appdata описан как запрещённый, но later example делает такой push. Разрешение всех трёх конфликтов отсутствует.
- README ссылается на отсутствующий `references/go-cdylib-ctypes-pattern.md`, `templates/calculator_plugin.py` и `templates/calc.go`; их актуальность и содержимое неизвестны.
- Не приложены implementation, tests, build/CI, package/license metadata. Не было установки, выполнения команд, сборки Go, теста плагина или проверки на устройстве. Runtime status отсутствует; все API — `docs`.
- Утверждения о parser failures на ZIP/файлах 4 MB+, plugin directory, API availability, app minimum, package support, UI-thread dispatch, reflection, hooks и применимости к текущему клиенту не подтверждены первичным SDK/client source.
- Calculator sample включает `eval`; его filtering/safe globals не аудитировались и пример не является подтверждением безопасного вычислителя.
