## Установка, модель и lifecycle

Вводная требует импортировать zwylib после установки библиотеки; пример ловит ImportError и ModuleNotFoundError и завершает работу исключением с просьбой установить ZwyLib ([index.mdx, строки 5–20](https://github.com/Zwylair/zwylib-docs/blob/69d56b4b64e5e61b47646282eb5ec749415ac142/content/index.mdx#L5-L20)). Это документированный способ обнаружить отсутствующую зависимость, но страница не описывает управление версиями пакета.

Ключевой lifecycle — явная регистрация в on_plugin_load и очистка в on_plugin_unload: пример системы команд удаляет dispatcher при выгрузке, а пример hook снимает сохранённый Unhook. При этом документация отдельно обещает, что задачи AsyncManager отменяются автоматически при выгрузке плагина; подписка смены языка тоже снимается автоматически. Для dispatcher и hook примеры требуют ручного cleanup. Не следует распространять одну из этих гарантий на все глобальные реестры ZwyLib без реализации ([commands.mdx, строки 14–38](https://github.com/Zwylair/zwylib-docs/blob/69d56b4b64e5e61b47646282eb5ec749415ac142/content/commands.mdx#L14-L38), [hooks.mdx, строки 12–22](https://github.com/Zwylair/zwylib-docs/blob/69d56b4b64e5e61b47646282eb5ec749415ac142/content/hooks.mdx#L12-L22), [async.mdx, строки 38–45](https://github.com/Zwylair/zwylib-docs/blob/69d56b4b64e5e61b47646282eb5ec749415ac142/content/async.mdx#L38-L45), [localization.mdx, строки 68–75](https://github.com/Zwylair/zwylib-docs/blob/69d56b4b64e5e61b47646282eb5ec749415ac142/content/localization.mdx#L68-L75)).

## Применимые рецепты

1. **Запустить сетевую работу из синхронного hook.** Определить async-функцию с await Requests..., а из hook вызвать async_manager.run_task(coro) и сразу вернуть нужный HookResult. Документация обещает plugin-scoped cancellation при unload.
2. **Вызывать callback-style Java API как coroutine.** Создать Java delegate, получить marker через async_manager.as_callback(delegate, "onSuccess", "onError"), затем await async_manager.wrap_java_call(activity.someMethod, marker). Передавать marker ровно в один аргумент метода.
3. **Регистрировать команды безопасно при reload.** Создавать dispatcher и команды при on_plugin_load; в on_plugin_unload вызвать command_manager.remove_dispatcher(__id__). Sync handler принимает params и account и возвращает HookResult. Async handler не возвращает HookResult и немедленно отменяет исходное сообщение.
4. **Сохранять hook только на время жизни plugin.** При on_plugin_load найти Java member через reflection helper и сохранить handle HookUtils.hook_before/after/replace; при выгрузке вызвать HookUtils.unhook(handle). При Plugins Safe Mode регистрация может вернуть None.
5. **Объявлять настройки на уровне модуля.** Создать SettingEntry в теле plugin-модуля и отдавать as_input/as_selector/as_switch из create_settings. Для строковых или испорченных значений использовать safe_get(int, ...); set() перезагружает экран.
6. **Не читать attachment до завершения скачивания.** В async-функции вызвать await zwylib.ensure_media_downloaded(msg_obj) и только при True обращаться к файлу. async_download_and_install_plugin применяет этот шаг с повтором попыток max_tries.
7. **Различать локально доступный peer и публичный peer без access hash.** Для локально доступного чата использовать open_message; иначе в coroutine вызвать await safe_open_message(peer_id, msg_id, chat_username=...). Без username успех разрешения недоступного peer не гарантирован.

## Сеть, хранение, UI и безопасность

Requests описывает Telegram TL API, а не произвольный HTTP-клиент: raw request несёт TL-схему и дополнительные поля. Документация советует async_send для coroutine-сценариев; отдельные методы покрывают администрирование, поиск/получение сообщений и участников. Публичные методы могут менять серверное состояние (удаление сообщений, ban/unban, slow mode). Авторизация, rate limits и подтверждение опасных операций здесь не специфицированы.

Файловое хранение cache-папки plugin и per-plugin SettingsManager имеет разную роль. CacheFile описан как простой cache, включая wipe/delete; SettingEntry — как persistent settings, связанные с экраном настроек. Нет документированных гарантий атомарности, шифрования, синхронизации потоков, account namespace или сохранения cache при обновлении/очистке данных.

Некоторые coroutine API показывают native UI и зависят от активного клиента: picker, dialogs и post navigation. Для pick_chat отмена — exception, тогда как text/selector dialogs возвращают None. Документация описывает общий фоновый loop, но не объясняет, какие UI вызовы переключать на main thread; из этого нельзя выводить безопасность любого UI-вызова с любого потока.

## Версии, сборка и тестирование

В снимке не указана версия самой ZwyLib и нет lock/manifest зависимости, которая связывает документацию с релизом библиотеки. version 1.0.0 в package.json относится к веб-проекту документации; Next/Nextra/React не являются зависимостями Android plugin runtime. package.json содержит scripts dev/build/start/lint для сайта, но не test script. Сайт и чужие команды не запускались. В дереве нет Android build-конфигурации, test-suite, changelog или матрицы совместимости; сборка SDK и runtime поведение не подтверждены.

## Границы и остаточные вопросы

- Утверждения о сигнатурах и поведении имеют статус docs; нет кода SDK, тестов и независимой runtime проверки.
- Нет заявленной минимальной версии ZwyLib/ExteraGram для каждого API, release tag или changelog; примеры версий не являются общей политикой поддержки.
- Нет контрактов произвольных событий/обсерверов, межплагинной коммуникации, account ownership request, UI потоков, сетевого TLS/HTTP, хранения секретов или миграции настроек.
- README отсутствует; radar-urls.json пуст. Факты радара о SyncProfile/ZwyLib и портируемости принадлежат другим источникам и здесь не приписаны библиотеке.
- exteraGram, Java/Xposed, Android View, Chaquopy и Telegram TL указывают на Android-контекст; перенос API на iOS/Desktop этим источником не подтверждён.
- hooks.mdx ссылается на внешний BasePlugin.hook, settings/logging — на внешние docs компонентов. Эти внешние источники в данном сборе отдельно не фиксировались.
