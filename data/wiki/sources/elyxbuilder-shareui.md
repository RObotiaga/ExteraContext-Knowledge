# shareui/ElyxBuilder — сборщик и упаковщик Elyx-плагинов

Источник: [shareui/ElyxBuilder](https://github.com/shareui/ElyxBuilder), снимок зафиксирован на `e45963fe787938ebc9a8abb3a3794b232fb72e97` (ветка `main`, SHA из снимка от 2026-09-27). В `package/pyproject.toml` указана версия пакета `0.6.2`; лицензия репозитория — MIT. ElyxBuilder — CLI для генерации каркаса плагина, предварительной проверки Python, необязательной компиляции/обфускации и упаковки файлов проекта в архив `.eaf` или иной заданный ZIP-суффикс. Это developer tool, не клиентский SDK и не реализация загрузчика плагина.

Код и документация прочитаны по сохранённому снимку. Ничего не запускалось, не собиралось и не устанавливалось; клиент ExteraGram/ElyxCore и архивы на устройстве не проверялись. Описания команд из docs имеют статус документации, а поведение упаковки и CLI подтверждено кодом указанного SHA. Радар только предлагает ElyxBuilder как сравниваемый build tool рядом с другим форком; конкретных контрактов ElyxBuilder там нет ([radar-context](../../raw/elyxbuilder-shareui/radar-context.md), строки 2326–2331).

## Назначение и workflow

README описывает последовательность `elyb new` → `elyb build -c -v`, Python ≥3.10 для CLI, Python 3.11 для компиляции и `pyzipper` только для encryption ([README, строки 3–33](https://github.com/shareui/ElyxBuilder/blob/e45963fe787938ebc9a8abb3a3794b232fb72e97/README.md#L3-L33)). `pyproject.toml` закрепляет `elyb = elyb.cli:main`, версию `0.6.2`, обязательную зависимость `pyyaml>=6.0` и Python ≥3.10 ([pyproject.toml, строки 5–29](https://github.com/shareui/ElyxBuilder/blob/e45963fe787938ebc9a8abb3a3794b232fb72e97/package/pyproject.toml#L5-L29)). Команды ожидают запуск из корня проекта с `refmap.yml` по документации; реализация `build`, `cached`, `script` ищет `refmap.yml`, затем `refmap.yaml`, затем `refmap.json` в текущем каталоге ([build.py, строки 23–30](https://github.com/shareui/ElyxBuilder/blob/e45963fe787938ebc9a8abb3a3794b232fb72e97/package/src/cmds/build.py#L23-L30)).

`elyb new` в interactive-пути создаёт директорию плагина с `.elyxbuilder/config.yml`, `src/main.py`, `res/`, `locales/strings_en.json`, `locales/strings_ru.json`, `meta.yml`/`.json` и `refmap.yml`/`.json`. Генерируемый файл импорта содержит `from base_plugin import BasePlugin` и `from android_utils import log`, а callbacks — `on_plugin_load` и `on_plugin_unload` ([new.py, строки 619–710](https://github.com/shareui/ElyxBuilder/blob/e45963fe787938ebc9a8abb3a3794b232fb72e97/package/src/cmds/new.py#L619-L710)). В `--gen` parser принимает `--zipformat`, но CLI dispatch передаёт это значение третьим аргументом в `runNew`, объявленную с двумя аргументами; по статическому сопоставлению сигнатур fast-generation ветка содержит ошибку вызова. Interactive-ветка вызывает `runInteractive()` и отдельно доходит до `writePlugin`. Кроме того, README quick start `elyb new "My Plugin" myname` не соответствует parser, который не объявляет позиционные аргументы ([cli.py, строки 18–22, 76–82](https://github.com/shareui/ElyxBuilder/blob/e45963fe787938ebc9a8abb3a3794b232fb72e97/package/src/cli.py#L18-L22), [new.py, строки 590–601](https://github.com/shareui/ElyxBuilder/blob/e45963fe787938ebc9a8abb3a3794b232fb72e97/package/src/cmds/new.py#L590-L601)). Команды не запускались. Это только шаблон кода и пути: ElyxBuilder не разрешает эти imports, не проверяет наличие методов в SDK и не загружает плагин. Начальные поля `sdkVersion`, `appVersion`, `elyxVersion` читаются из поставляемого `config.json` (`>=1.4.3.2`, `>=12.5.1`, `>=0.9.2b`); это defaults каркаса данной версии инструмента, не утверждение о текущем SDK клиента ([config.json, строки 1–5](https://github.com/shareui/ElyxBuilder/blob/e45963fe787938ebc9a8abb3a3794b232fb72e97/package/src/config.json#L1-L5)).

Каркас содержит YAML/JSON-альтернативы для `refmap` и metainfo. refmap указывает `metainfo`, `main`, `assets`, `strings`, `elyxbuilder`; сборщик реально использует `elyxbuilder` и `metainfo`, а каталог плагина вычисляет как родителя builder directory. При упаковке он добавляет сам refmap и обходит каталог плагина целиком, сохраняя относительные пути от родителя каталога плагина ([new.py, строки 691–710](https://github.com/shareui/ElyxBuilder/blob/e45963fe787938ebc9a8abb3a3794b232fb72e97/package/src/cmds/new.py#L691-L710), [build.py, строки 336–350, 395–403, 422–424, 575–594](https://github.com/shareui/ElyxBuilder/blob/e45963fe787938ebc9a8abb3a3794b232fb72e97/package/src/cmds/build.py#L336-L350)). Упаковщик не парсит пути `main`, `assets` или `strings` для соответствующей загрузки; их значения нужны как convention/refmap для потребителя. Снимок не содержит consumer-side кода, который доказал бы это поведение клиента.

## Сборка, archive и ресурсы

`elyb build` сначала валидирует текущий каталог, `elyxbuilder` в refmap, каталог builder, `.elyxbuilder/config.yml`, `zipFormat`, шаблон имени архива, `metainfo` и поля метаданных, подставляемые в имя. Для compiled режима нужен также `buildNameCompiled`; результат пишет в `builds/` ([build.py, строки 319–420](https://github.com/shareui/ElyxBuilder/blob/e45963fe787938ebc9a8abb3a3794b232fb72e97/package/src/cmds/build.py#L319-L420)). `--ast` и `--compile` взаимоисключаются в CLI. AST-проверка проверяет `.py` только в `source` и завершает сборку на первом `SyntaxError` ([cli.py, строки 32–35](https://github.com/shareui/ElyxBuilder/blob/e45963fe787938ebc9a8abb3a3794b232fb72e97/package/src/cli.py#L32-L35), [build.py, строки 301–317](https://github.com/shareui/ElyxBuilder/blob/e45963fe787938ebc9a8abb3a3794b232fb72e97/package/src/cmds/build.py#L301-L317)). Это проверка синтаксиса, а не import resolution или проверки API Elyx.

При обычной упаковке сборщик кладёт каталог плагина в ZIP; `ignoreAll` сопоставляется с полным архивным путём через `fnmatch`. `--no-assets` исключает только точные имена архивных entries из `optionalAssets`; список подготавливается из config лишь когда включён флаг. `--no-folder` прекращает обход `.elyxbuilder`, а не удаляет весь tooling-каталог по произвольному критерию ([build.py, строки 368–375, 582–603](https://github.com/shareui/ElyxBuilder/blob/e45963fe787938ebc9a8abb3a3794b232fb72e97/package/src/cmds/build.py#L368-L375), [там же, строки 582–603](https://github.com/shareui/ElyxBuilder/blob/e45963fe787938ebc9a8abb3a3794b232fb72e97/package/src/cmds/build.py#L582-L603)). `compilationIgnore` выполняет другую роль: игнорируемые `.py` остаются исходниками даже при `--compile`, а остальные исходники заменяются `.pyc` ([build.py, строки 605–620](https://github.com/shareui/ElyxBuilder/blob/e45963fe787938ebc9a8abb3a3794b232fb72e97/package/src/cmds/build.py#L605-L620)). Поэтому пути/маски для трёх ignore lists не взаимозаменяемы.

Перед компиляцией проверяется наличие Python 3.11 одним из имён `python3.11`, `python3`, `python` (на Windows также `py`); вызов `py_compile` выполняется отдельным процессом. Кэш `.elyx/cache/python311/manifest.json` хранит для обычных файлов `mtime`, размер и уровень оптимизации, а hit требует также существующий `.pyc`. Обфусцируемые файлы не используют cache hit и компилируются снова ([build.py, строки 94–109, 194–294](https://github.com/shareui/ElyxBuilder/blob/e45963fe787938ebc9a8abb3a3794b232fb72e97/package/src/cmds/build.py#L94-L109), [build.py, строки 238–294](https://github.com/shareui/ElyxBuilder/blob/e45963fe787938ebc9a8abb3a3794b232fb72e97/package/src/cmds/build.py#L238-L294)). `--reset` требует `--compile` и удаляет этот cache directory перед повторной компиляцией ([build.py, строки 323–325, 508–520](https://github.com/shareui/ElyxBuilder/blob/e45963fe787938ebc9a8abb3a3794b232fb72e97/package/src/cmds/build.py#L323-L325)). `elyb cached` использует те же manifest-поля, но также не запускается без `refmap`, config и ключа `source` ([cached.py, строки 54–87, 94–124](https://github.com/shareui/ElyxBuilder/blob/e45963fe787938ebc9a8abb3a3794b232fb72e97/package/src/cmds/cached.py#L54-L87)).

Для encryption используется стандартный `zipfile` без флага; с `-p` реализация импортирует необязательный `pyzipper`, выбирает ZipCrypto или AES-128/192/256, кодирует пароль в bytes и задаёт шифрование при создании архива ([build.py, строки 51–92](https://github.com/shareui/ElyxBuilder/blob/e45963fe787938ebc9a8abb3a3794b232fb72e97/package/src/cmds/build.py#L51-L92)). Код сообщает об отсутствии `pyzipper` и возвращает из команды без сборки. README перечисляет `pyzipper` как optional encryption dependency; runtime-совместимость шифрованных архивов не установлена.

## Дополнительные CLI-команды и обфускация

`add-ignore`/`del-ignore` используют refmap и обновляют один из трёх config-списков; обратные слеши нормализуются, повторная запись существующего пути пропускается, удаление проверяет целочисленный индекс и его диапазон ([ignore.py, строки 20–104](https://github.com/shareui/ElyxBuilder/blob/e45963fe787938ebc9a8abb3a3794b232fb72e97/package/src/cmds/ignore.py#L20-L104)). `stats builds` читает счётчики `.elyxbuilder/stats.yml`; `lines` и `size` по умолчанию считают `.py` в `source`, `files` — файлы каталога плагина. `--all` расширяет область, `--additional` добавляет каталоги относительно cwd; `lines`/`size` пропускают известные бинарные расширения. Это инструменты подсчёта, не проверки корректности сборки или runtime ([stats.py, строки 16–238](https://github.com/shareui/ElyxBuilder/blob/e45963fe787938ebc9a8abb3a3794b232fb72e97/package/src/cmds/stats.py#L16-L238), [cli.py, строки 87–145](https://github.com/shareui/ElyxBuilder/blob/e45963fe787938ebc9a8abb3a3794b232fb72e97/package/src/cli.py#L87-L145)).

Код расходится с обеими языковыми obfuscation docs: docs используют ключ `obfuscation` и утверждают, что `removeLogs` действует также без обфускации; код читает `obfuscationConfig`, мигрирует defaults и удаляет legacy `RemoveLogs`, а pipeline вызывается только если выбран `--obfuscation` ([build.py, строки 122–154, 461–500](https://github.com/shareui/ElyxBuilder/blob/e45963fe787938ebc9a8abb3a3794b232fb72e97/package/src/cmds/build.py#L122-L154), [new.py, строки 619–630](https://github.com/shareui/ElyxBuilder/blob/e45963fe787938ebc9a8abb3a3794b232fb72e97/package/src/cmds/new.py#L619-L630), [docs/ru/obfuscation.md, строки 113–130](https://github.com/shareui/ElyxBuilder/blob/e45963fe787938ebc9a8abb3a3794b232fb72e97/docs/ru/obfuscation.md#L113-L130), [docs/en/en.md, строки 501–517](https://github.com/shareui/ElyxBuilder/blob/e45963fe787938ebc9a8abb3a3794b232fb72e97/docs/en/en.md#L501-L517)). Поэтому docs config example нельзя считать contract конкретного SHA.

## Метаданные, imports и localization

`buildMetaInfo(...)` читает metainfo, формирует `elyxbuilder` с `compiled`, `buildNum`, датой, `pythonVer`, SHA-256 от содержимого Python-файлов под директорией метаданных и версией установленного пакета (или `unknown`), а затем сериализует в исходный YAML/JSON-формат. При желании добавляет `staticVer` и `client` ([build.py, строки 157–192](https://github.com/shareui/ElyxBuilder/blob/e45963fe787938ebc9a8abb3a3794b232fb72e97/package/src/cmds/build.py#L157-L192)). Метаданные патчатся только во время записи ZIP; `meta.yml` на диске остаётся прежним, а `--no-info` отключает вставку целиком ([build.py, строки 621–624](https://github.com/shareui/ElyxBuilder/blob/e45963fe787938ebc9a8abb3a3794b232fb72e97/package/src/cmds/build.py#L621-L624), [cli.py, строки 19–20](https://github.com/shareui/ElyxBuilder/blob/e45963fe787938ebc9a8abb3a3794b232fb72e97/package/src/cli.py#L19-L20)). Документация `docs/ru/build.md` показывает отдельные поля на верхнем уровне блока, тогда как код записывает их вложенно в `elyxbuilder`; при точном формате следует ориентироваться на реализацию этого SHA.

README/генератор заявляют `locales/strings_en.json` и `strings_ru.json`, а refmap записывает каталог `strings`. ElyxBuilder просто создаёт эти JSON-файлы и пакует их; отдельного механизма чтения переводов, проверки ключей, резервного языка или вызова `get_string` в этом репозитории нет ([new.py, строки 632–640, 691–710](https://github.com/shareui/ElyxBuilder/blob/e45963fe787938ebc9a8abb3a3794b232fb72e97/package/src/cmds/new.py#L632-L640)). Аналогично импорт `BasePlugin` — лишь текст заглушки `main.py`; зависимости SDK не перечислены как package dependencies и импорты не валидируются перед архивированием. Это утверждения о границе функций репозитория, не о поведении Elyx клиента.

## Watch, ошибки и сценарии

Watch определяет success по `SystemExit` status и эвристическим текстовым шаблонам `error:`, `compilation failed:` и `failed to complete build:`. Например, `resolveEncryption` при отсутствии optional `pyzipper` печатает `pyzipper is required for encryption.` без этих маркеров и возвращает отказ штатно; watch может посчитать команду успешной, не найти archive output и всё равно показать fallback label `builds/latest.eaf` ([watch.py, строки 223–263](https://github.com/shareui/ElyxBuilder/blob/e45963fe787938ebc9a8abb3a3794b232fb72e97/package/src/cmds/watch.py#L223-L263), [build.py, строки 66–76, 330–334](https://github.com/shareui/ElyxBuilder/blob/e45963fe787938ebc9a8abb3a3794b232fb72e97/package/src/cmds/build.py#L66-L76)). Это вывод по коду, не выполненный сценарий.

`elyb watch <seconds>` реализует polling developer workflow, не HTTP/dev server. Каждый цикл обходит cwd, исключая все скрытые директории, и сравнивает набор путей вместе с `mtime`; добавление/удаление/изменение триггерит `runBuild`. Вывод сборки перехватывается, ошибки сводятся к первой строке `error:` или последней строке, удачный архив копируется как `builds/latest.<ext>`. В интерфейсе есть Q для выхода и P для паузы ([watch.py, строки 25–44, 122–165, 168–189, 191–290](https://github.com/shareui/ElyxBuilder/blob/e45963fe787938ebc9a8abb3a3794b232fb72e97/package/src/cmds/watch.py#L25-L44), [watch.py, строки 191–290](https://github.com/shareui/ElyxBuilder/blob/e45963fe787938ebc9a8abb3a3794b232fb72e97/package/src/cmds/watch.py#L191-L290)). Документация предлагает прокидывать аргументы build через `--args`, в том числе `-c -v` ([watch.md, строки 1–17](https://github.com/shareui/ElyxBuilder/blob/e45963fe787938ebc9a8abb3a3794b232fb72e97/docs/ru/watch.md#L1-L17)). Так как watcher сканирует сам cwd и собирает новый snapshot после сборки, результат зависит от наблюдаемого дерева/mtime; гарантии обработки быстрых последовательных правок или атомарной записи нет.

`build` выдаёт ранние понятные ошибки на отсутствующий refmap, ключи `elyxbuilder`/`metainfo`, конфиг, папку builder и отсутствующие шаблоны имён; на них инкрементируется failed build counter, когда расположение stats доступно. AST и compile failures также считают ошибку сборки; для синтаксиса печатается исключение, для py_compile — stderr дочернего процесса ([build.py, строки 336–410, 301–317, 283–294, 352–355](https://github.com/shareui/ElyxBuilder/blob/e45963fe787938ebc9a8abb3a3794b232fb72e97/package/src/cmds/build.py#L336-L410)). `elyb script NAME [ARGS...]` ищет `.elyxbuilder/scripts/NAME.edsl`, пропускает содержимое через lexer/parser и затем пытается импортировать interpreter; parse/runtime exceptions выводятся и завершают процесс с кодом 1, а `exit(code)` переносит код в `SystemExit` ([script.py, строки 13–51](https://github.com/shareui/ElyxBuilder/blob/e45963fe787938ebc9a8abb3a3794b232fb72e97/package/src/cmds/script.py#L13-L51)). Однако `elyxdsl/interpreter.py` отсутствует в pinned tree, поэтому исполнение DSL, встроенные функции из AST и его безопасность остаются неизвестными.

## Практические рецепты и caveats

- Для рабочего каркаса запускайте CLI из каталога, в котором будет лежать `refmap`; путь `elyxbuilder` задаёт каталог `.elyxbuilder`, а `metainfo` указывает metadata-файл. Сначала сверяйте schema с SDK/клиентом отдельно: builder здесь только архивирует и не проверяет consumer semantics.
- Для обычной отладки можно использовать `elyb build --ast -v`; для отправки скомпилированного варианта — `elyb build -c -v`, учитывая обязательный Python 3.11. Сравнивать кэш можно командой `elyb cached`; её состояния получаются из manifest `mtime` и размера, а не из хеша исходника ([cached.py, строки 107–124](https://github.com/shareui/ElyxBuilder/blob/e45963fe787938ebc9a8abb3a3794b232fb72e97/package/src/cmds/cached.py#L107-L124)).
- Разделяйте исключение по назначению: `ignoreAll` исключает архивный путь всегда; `optionalAssets` — лишь при `--no-assets`; `compilationIgnore` сохраняет `.py` вместо `.pyc`. Документы описывают flags в [build.md, строки 23–39](https://github.com/shareui/ElyxBuilder/blob/e45963fe787938ebc9a8abb3a3794b232fb72e97/docs/ru/build.md#L23-L39), реализация — в ссылках раздела «Сборка».
- Считайте obfuscation beta и экспериментируйте на копии плагина: docs предупреждает про runtime-регрессии и перечисляет защищаемые имена/сигнатуры, но реальную совместимость с внешним Elyx/Java bridge этот репозиторий не устанавливает. zlib compression документирован как несовместимый с `.pyc` compilation ([obfuscation.md, строки 3–18, 34–47, 77–88](https://github.com/shareui/ElyxBuilder/blob/e45963fe787938ebc9a8abb3a3794b232fb72e97/docs/ru/obfuscation.md#L3-L18)). Это документационное предписание, не результат запуска.
- Русская и английская документация говорят, что аргументы отдельных obfuscation files относительны к project root. В коде имя каждого `.py` рассчитывается от `sourceDir` и сравнивается напрямую с переданным аргументом, так что фактически сравниваемый путь относителен к `source` ([build.py, строки 461–491](https://github.com/shareui/ElyxBuilder/blob/e45963fe787938ebc9a8abb3a3794b232fb72e97/package/src/cmds/build.py#L461-L491), [docs/en/en.md, строки 389–402](https://github.com/shareui/ElyxBuilder/blob/e45963fe787938ebc9a8abb3a3794b232fb72e97/docs/en/en.md#L389-L402), [docs/ru/obfuscation.md, строки 6–14](https://github.com/shareui/ElyxBuilder/blob/e45963fe787938ebc9a8abb3a3794b232fb72e97/docs/ru/obfuscation.md#L6-L14)).
- `watch` можно использовать как локальный auto-build loop; это polling по mtime файлов внутри cwd, а не сервер с live reload, endpoint или plugin runtime. Передавайте build options одной строкой `--args`.
