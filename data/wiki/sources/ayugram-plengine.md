## Роль и границы источника

Это Windows DLL engine, встроенный в форк AyuGram Desktop, а не переносимый ExteraGram SDK. Он фиксирует экспортируемый C++ ABI, набор динамически обнаруживаемых callbacks, точки их вызова в клиенте, доступ плагина к структурам Telegram Desktop, и дополнительный локальный HTTP API. README — описание автора; приведённые ниже детали поведения уточнены по C++ этого снимка. Код не собирался и не запускался, runtime-поведение не проверялось. Сэмпл-плагин в AyuSamplePlugin лишь упомянут, его репозиторий не исследовался.

Таблица покрытия перечисляет все локально полученные материалы по этой задаче; после независимой проверки дополнительно получены 8 кандидатов на точку вызова popup hook, итого 45 файлов. Зона `Telegram/SourceFiles/plengine` изучена полностью (18 файлов), вместе с контрактом в `AyuPlugin.h`, таблицами callback, точками вызова, стартом приложения, APIWrap/MTProto, CMake inclusion и наиболее вероятными message/context-menu call-sites. В остальной части форка изучались только перечисленные связанные файлы, не весь Telegram upstream. Снимок дерева содержит 6 704 записей.

## Архитектура и жизненный цикл

- `main()` вызывает `MainInject()` сразу после `Core::Launcher::Create(...)` и перед `launcher->exec()`. Это стартовая интеграция данного форка, не механизм загрузки, применимый к сторонним Telegram Desktop сборкам. См. [`main.cpp`](https://github.com/MrCheatEugene/AyuGramDesktop-PLEngine/blob/55feefdb6abd702e368b12431de97313441362a0/Telegram/SourceFiles/main.cpp#L18-L22), [`PLEMains.cpp`](https://github.com/MrCheatEugene/AyuGramDesktop-PLEngine/blob/55feefdb6abd702e368b12431de97313441362a0/Telegram/SourceFiles/plengine/PLEMains.cpp#L475-L539).
- `MainInject` создает `%cwd%\plugins`, перечисляет все файлы в ней без фильтра расширения, запускает отложенный автозагрузчик, HTTP listener, polling онлайн-hook и worker главной очереди как отсоединенные потоки. Автозагрузка сначала ждет 5 секунд, затем `Core::App().wasRan`; после этого каждый найденный файл передается в отдельный detached thread. README называет это внутренним loader. Код не показывает unload/reload или lifecycle cleanup.
- `processDLL` формирует путь внутри каталога plugins, вызывает `LoadLibrary`, требует экспорт `pluginInfo` и затем обнаруживает optional exports по именам (`internalSetup`, `internalLoop`, hooks). При неудаче загрузки или `pluginInfo == nullptr` показывает MessageBox. Получает плагиноописание, записывает callback указатели в глобальные векторы, заполняет `MemData`, добавляет карточку в UI-данные. Результат `GetProcAddress` для `pluginInfo` напрямую вызывается без проверки на отсутствующий символ — хотя README описывает ошибку структуры, код явно не защищает от null function pointer.
- `internalSetup()` вызывается один раз после загрузки указателей и регистрации hooks. Если `internalLoop()` экспортирован, `processDLL` вызывает его в бесконечном цикле на том же выделенном потоке. Следовательно, блокирующий setup задерживает начало loop, а завершение loop не реализовано как штатная выгрузка. Фраза README «все выполняется в отдельном потоке» слишком общая: callbacks UI работают из UI страницы, а online hook — отдельный polling thread.
- ABI в [`AyuPlugin.h`](https://github.com/MrCheatEugene/AyuGramDesktop-PLEngine/blob/55feefdb6abd702e368b12431de97313441362a0/Telegram/SourceFiles/AyuPlugin.h) использует `extern "C" __declspec(dllexport)` только при определенном `AYUPLUGIN`; структура `AyuPlugin` содержит `wchar_t name[128]`, `description[255]`, `moduleName[128]` и `MemData`. В `MemData`: сырые `uintptr_t` адреса приложения, активного пользователя и session, плюс `ExAddToQueue` (`void (*)(const std::function<void()>&)`). Это ABI с C++ типами и зависимыми заголовками, поэтому `extern "C"` именует экспортные функции, но не превращает содержимое в стабильный C ABI. README требует использовать имя экспорта `pluginInfo`.
- Runtime `MemData.activeUserPtr` и `activeSessionPtr` заполняются текущей активной учетной записью при `processDLL`; код не обновляет поля уже загруженной DLL при переключении аккаунта. Отдельный `SharedMemHelper` наполняет `applicationAddr`, `activeUserPtr`, `currentAccountName`, `isSharingScreen` и queue callback потоком опроса с интервалом `pollingRate`. Публичные HTTP endpoints `runtime/load`, `runtime/export`, `runtime/setPolling` запускают/управляют этим помощником; README иногда называет его `MemHelper`.
- Фоновый queue worker берет `std::function<void()>` из защищенной mutex/condition-variable очереди и вызывает `dispatchToMainThread(task)`. Документация рекомендует оборачивать API/session/UI цепочки, особенно `ApiWrap`, и передавать closure через `memData.addToQueue`; это устраняет прямой вызов Qt/UI объектов из потока плагина лишь при правильном захвате/времени жизни данных. Само утверждение о безопасности не является гарантией безопасного владения captured pointers.
- `doDrawGUI` вызывается из построителя раздела Loaded plugins при нажатии на plugin button. Этот call-site находится в коде UI; README прямо утверждает main thread. Для UI callback поддерживаются `Settings::Builder::SectionBuilder`, `Settings::AyuBuilder::AyuSectionBuilder`, `Settings::PLEPlugins*`, но README предупреждает, что часть builder функций не экспортирована и принудительное линкование может приводить к access violation. Это экспериментальный API конкретной сборки.

## Прямой доступ к API AyuGram

- README описывает два пути. Ограниченный `ApiWrap` доступ может требовать дополнительных экспортированных классов; предпочтительный автором путь для запросов — `s->api().instancePtr()->sendReq(...)`. В `mtp_instance.h` `MTP::Instance::sendReq(...)` объявлен с `__declspec(dllexport)`. Схема запроса передается boxed (`tl::boxed<T>`) если generated `scheme.h` еще не объявляет тип boxed. Пример README с `MTPaccount_updateProfile` — docs, compile/link/runtime не подтверждены.
- Пример README для `ApiWrap::sendMessage`: получить `history`, сформировать `Api::MessageToSend`, задать `textWithTags`, затем вызвать `s->api().sendMessage(std::move(message))`. Этот вызов проходит через message preprocess hooks. Набор реально доступных классов и ABI-зависимость от точной AyuGram revision ограничивают переносимость.
- Настройки PLEngine (`PLESettings`) включают console, HTTP API, «Disable security features», certificate и key. UI хранит их через `setx`/изменения HKCU environment и просит перезапуск для применения. HTTP endpoint listener читает переменные окружения при старте. Здесь опасная опция выключения trust-checks соответствует `AYUPL_DISABLESECURITYFEATURES=1`.

## HTTP API и доверие

README перечисляет `/api/ping`, `/api/runtime/setPolling?rate=INT`, `/api/runtime/load?name=module.dll`, `/api/runtime/export`, `/api/session/get`. Код подтверждает их, но уточняет, что `listenHTTP()` берет host/certificate/key из `AYUPL_HOST`, `AYUPL_SSL_CERT`, `AYUPL_SSL_KEY`, а port из `AYUPL_PORT`; при отсутствующем/невалидном порте listener выключен. После этой проверки стоит fallback `ms.Listen(... : 8080)`, однако до него выполнение не доходит при невалидном порте. Поэтому документированный default `127.0.0.1:8080` не равен режиму по умолчанию в данном коде; settings UI включает API через порт 8081 и host `127.0.0.1`. Явно задавайте порт и проверяйте реальный конфиг целевой сборки ([README](https://github.com/MrCheatEugene/AyuGramDesktop-PLEngine/blob/55feefdb6abd702e368b12431de97313441362a0/README-pluginEngine.md#http-api), [listener](https://github.com/MrCheatEugene/AyuGramDesktop-PLEngine/blob/55feefdb6abd702e368b12431de97313441362a0/Telegram/SourceFiles/plengine/PLEMains.cpp#L322-L434), [settings](https://github.com/MrCheatEugene/AyuGramDesktop-PLEngine/blob/55feefdb6abd702e368b12431de97313441362a0/Telegram/SourceFiles/plengine/PLESettings.h#L55-L75)).

Все endpoints кроме `ping` получают `User-Agent` и требуют пользовательского одобрения по одному из trust scopes: `runtime`, `session`, `events`. Одобрение сохраняется в памяти текущего процесса в vector, постоянного хранилища для него в изученной реализации нет. Кодовый bypass `AYUPL_DISABLESECURITYFEATURES=1` автоматически разрешает все scopes; сам README признает этот trust wall слабым. API запускается без TLS, если заданные certificate/key не существуют; локальный loopback не является аутентификацией.

`/api/runtime/load` принимает имя DLL из query string, вызывает `processDLL` в detached thread и возвращает JSON c адресом `memHelper`; README называет это remote code execution trust space. `/api/runtime/export` включает polling и возвращает адрес той же структуры. `setPolling` требует уже включенный `memHelper`, ограничивает rate снизу значением 10 мс. `/api/session/get` выдает сведения о каждой активной сессии, включая текущий auth key в hex, DC, id и имена/username. Следовательно это чувствительный локальный API; не открывать его наружу и не отключать trust checks без осознанной причины. Отдельное событие авторизации пользователя не проверено.

Документация описывает ответ `{"ok":"true/false", "error":..., "result_json":"..."}`, однако C++ сериализует `ok` как JSON boolean, а `result_json` как строку. Формат endpoint-level payloads отличается (например, `session/get` сериализует массив accounts внутрь строки `result_json`, тогда как runtime endpoints кладут туда адрес helper как строковое число). Клиентам следует разбирать именно JSON implementation, а не строки из примера README ([README response example](https://github.com/MrCheatEugene/AyuGramDesktop-PLEngine/blob/55feefdb6abd702e368b12431de97313441362a0/README-pluginEngine.md#http-api), [serializer and endpoints](https://github.com/MrCheatEugene/AyuGramDesktop-PLEngine/blob/55feefdb6abd702e368b12431de97313441362a0/Telegram/SourceFiles/plengine/PLEMains.cpp#L32-L55), [listener](https://github.com/MrCheatEugene/AyuGramDesktop-PLEngine/blob/55feefdb6abd702e368b12431de97313441362a0/Telegram/SourceFiles/plengine/PLEMains.cpp#L322-L434)).

## Практические правила для разработчика плагина

1. Собирайте DLL против той же версии AyuGram Desktop, используйте точные заголовки и экспорт `pluginInfo`; это не межклиентский ABI.
2. Экспортируйте только необходимые callbacks. Используйте `doPreProcessMessageStd`; legacy `char*` hook обозначен как проблемный.
3. Для функций с глубокими `Session`/`ApiWrap` структурами и всех операций, цепочка которых меняет UI, передавайте работу через `memData.addToQueue`. В closure проверяйте срок жизни и актуальность захваченных объектов.
4. Долгие задачи не ставьте в `internalLoop` без паузы/механизма завершения: engine вызывает callback в tight loop, а поддержки остановки/выгрузки плагина код не показывает.
5. Hook `doFilterHistoryItem` возвращает одно из трех enum значений, не `bool`; учитывайте, что первый решающий hook перекрывает остальные hooks и штатную логику filters.
6. `doDrawGUI` используйте с оглядкой на частично экспортированный builder API; конкретный доступный набор надо сверять с DLL/import lib именно своей версии.
7. Прямые MTProto запросы оформляйте в тип, ожидаемый `sendReq`; проверяйте сгенерированное объявление схемы на boxed тип, а не оборачивайте повторно вслепую.
8. Для разработки из README: включить `/DEBUG`, загрузить debug symbols, исследовать call stack и раскладывать подозрительное выражение на промежуточные значения. Engine пишет minidumps в `tdata/dumps/*.dmp` при crash. Это инструкции документа, фактический crash workflow не проверялся.
9. HTTP API рассматривать как привилегированный control plane: держать loopback, ограничить доступ к портам, не пересылать `/api/session/get` данные, проверять UA/trust scopes, не выставлять API наружу и не включать security bypass как замену разрешению доступа.

## Расхождения, ограничения и неизвестное

- README говорит о DLL и main-thread queue, однако точное распределение потоков зависит от callback: setup/loop — DLL worker; hook callbacks синхронно происходят в вызвавшем их клиентском пути; online callbacks идут с периодом 2 секунды; UI builder callback — при открытии UI.
- README заявляет endpoint default `127.0.0.1:8080`, но код отключает listener при пустом/невалидном `AYUPL_PORT`; следующий fallback на 8080 после `return` недостижим. Настройки клиента записывают 8081. Это значимое расхождение документа и реализации.
- В README формат `ok` показан строкой, в коде bool. README утверждает «If it RETURNS TRUE» для enum hook — неверно/неясно.
- HTTP trust vectors и callback vectors — изменяемые глобальные структуры; параллельная регистрация/обращение может быть race-prone. Код не показывает synchronization для hook registration и thread cleanup. Это наблюдение кода, риск не воспроизводился.
- В загрузке не видно валидации подписи/издателя DLL, sandbox, удаления/выгрузки модуля, ограничения размера/пути имени модуля или API authentication кроме UA prompt. `GetProcAddress(pluginInfo)` не проверяется до вызова. Это существенные ограничения модели доверия.
- `SharedMemHelper.activeUserPtr` обновляется периодически, но его чтение извне не защищено; raw pointer и C++ `std::function` через DLL ABI требуют совпадающего компилятора/runtime.
- `doDrawPopup` имеется в контракте и loader, но call-site hook не найден ни в `history_view_context_menu.cpp`, ни в дополнительных полученных AyuGram history/context-menu файлах. Поскольку весь upstream не сканировался, точка вызова остается scoped gap.
- Нет runtime-verified фактов, сборки/тестирования, анализа сэмпл-плагина, инсталляции, выгрузки DLL или проверки совместимости с ExteraGram. Документация не устанавливает Android/iOS plugin API.
