# Kangel/Plugins-Store на Codeberg — отдельное состояние каталога KPM

Источник: [Codeberg: Kangel/Plugins-Store](https://codeberg.org/Kangel/Plugins-Store), default branch `main`, commit [`3a9417b85597127d843b0411792721f111297a0a`](https://codeberg.org/Kangel/Plugins-Store/commit/3a9417b85597127d843b0411792721f111297a0a), проверен 2026-09-28. Репозиторий определяется как `Kangel/Plugins-Store`; Codeberg API указывает default branch `main`, профиль владельца называет GitHub-аккаунт `ArThirtyFour`, а workflow содержит отдельные операции отправки в GitHub, Codeberg и GitVerse. Это отдельный snapshot/ref, а не доказательство побайтового тождества GitHub-каталогу. В метаданных Codeberg `mirror` равен `false`: здесь не включено нативное зеркало Forgejo. Сохранённые метаданные и файлы доступны в [raw snapshot](../../raw/plugins-store-codeberg/snapshot.json), [repository metadata](../../raw/plugins-store-codeberg/repository.json), [tree](../../raw/plugins-store-codeberg/tree.json) и [SHA-256 manifest](../../raw/plugins-store-codeberg/file-manifest.json); радарные упоминания приложены в том же каталоге.

## Роль и границы

README описывает репозиторий как место хранения плагинов для Kangel Plugins Manager. Главная полезность этого источника для разработчика — собственное текущее состояние `store.json` и опубликованный `.eaf` менеджера KPM. Архив менеджера в этом Codeberg commit совпадает побайтно с архивом GitHub snapshot `513e29a07858e5dec3a8dcdc6a860fe4296f1d43` (SHA-256 `554815b906a155210f02fdd4de76c66ce4cf1fcba34b4e4651f143bc0b216625`), но каталог расходится: Codeberg содержит 700 ID против 698 в GitHub snapshot; 2 ID есть только в Codeberg. Если исключить только верхнеуровневый `url`, у 257 общих записей различается поле `legacy_version`; при исключении URL на всех уровнях 255 этих различий оказываются только переписанными ссылками. Содержательные расхождения остаются у `plugin_guard` и `camera_enhancer`: отличаются текущие `version`, `hash`, `signature`, а у `camera_enhancer` также `min_version`; в `legacy_version` у них тоже есть различия в хешах/подписях. Workflow намеренно переписывает URL для каждой площадки.

Поэтому сведения о структуре менеджера ниже относятся к тому же двоичному `.eaf`, но версия каталога и все изменяемые download URL должны оставаться привязанными к Codeberg commit. Содержимое пользовательских плагинов каталога построчно не анализировалось; учтены только записи и агрегированные поля JSON. Изучение исходников статическое, KPM и плагины не запускались; runtime-поведение и совместимость не подтверждены.

## Документированные соглашения репозитория

`AGENTS.md` описывает обычный `.plugin` как один Python-файл, а Elyx `.eaf`/`.elyx` — как ZIP с корневым `refmap`, ссылающимся на метаданные, `main`, строки и assets; для метаданных перечислены JSON/YAML варианты и запасной поиск по архиву. Это документация репозитория, не спецификация SDK. Документ задаёт SHA-256 по байтам файла и правило архивации старых версий: версионированное имя, существующие файлы не перезаписываются, при коллизии хеша добавляется `_1` и далее. Список полей в `AGENTS.md` — описательная схема, а не полный перечень фактической записи: например, все 700 текущих записей также содержат `signature`, хотя поле не перечислено в этом документе. Документационный пример URL ведёт на GitHub; Codeberg `store.json` использует собственные Codeberg URL.

## Каталог и зеркало

- `store.json` — JSON object, где ключ является ID, а значение содержит URL артефакта и метаданные. В 700 записях на этом ref есть `name`, `version`, `author`, `status`, `hash`, `signature`, а также часто встречаются `min_version`, `app_version`, `icon`, `legacy_version`, `dependencies`, `requirements` и локализованные `description_*`. Наличие в каталоге не доказывает, что плагин подходит любой версии клиента.
- Записи содержат Codeberg URL вида `https://codeberg.org/Kangel/Plugins-Store/raw/branch/main/Plugins/<file>`. Это изменяемая ссылка на branch; для воспроизводимого анализа надо закреплять commit и сверять metadata/hash с фактическими байтами.
- Два ID, отсутствовавшие в сохранённом GitHub snapshot: `custom_gifts` и `spam_collapse`. У 257 общих ID отличается значение `legacy_version`, если сравнивать записи после удаления только верхнего URL. После удаления URL также из вложенных `legacy_version` 255 таких отличий пропадают: это различия ссылок, ожидаемые при переписывании хоста. Содержательные изменения остаются у `plugin_guard` и `camera_enhancer`: у обоих различаются версия, хеш и подпись, у `camera_enhancer` также `min_version`; в архивных версиях этих двух записей расходятся хеш/подпись. Это показывает, что Codeberg-состояние полезно сверять отдельно, даже при наличии автоматизации зеркалирования.
- Workflow запускается на push в `main` либо вручную. Он от исходного checkout переписывает Forgejo raw URL на URL целевой площадки и делает force-push на GitHub, затем на Codeberg, затем GitVerse. Это свидетельствует о намеренной зеркальной публикации и нормализации ссылок, но не о гарантии синхронности snapshots или успешном выполнении workflow.
- API Codeberg описывает репозиторий как созданный 2026-09-27 и `mirror:false`; значит, его нельзя представлять как нативный зеркальный clone Forgejo. Workflow репозитория задаёт собственную push-схему, а каталоги уже наблюдаемо различаются.

## Пакет KPM и используемые вызовы

`Plugins/kangel_plugins_manager.eaf` — ZIP-пакет с `refmap.json`; `kpmplugin/metainfo.json` задаёт ID `kangel_plugins_manager`, версию `1.5.4`, `app_version >=12.9.0` и `sdk_version >=1.4.5.3`. В `.elyxbuilder/config.yml` задан `zipFormat: eaf` и исходный каталог `kpmplugin/src`; метаданные описывают build 92 от 2026-09-20 как `compiled:false`, а соседний `stats.yml` содержит 91 uncompiled builds и 0 compiled/failed. Описание самой записи в `store.json` заявляет поддержку ExteraGram от 12.9.0 и отдельно говорит, что AyuGram пока не поддерживается. Это метаданные автора, а не тест на этих клиентах.

## Что осталось неизвестным

Не исследованы 700 файлов каталога по отдельности, состояние GitVerse/Forgejo mirrors, выполнение Actions и работа менеджера на устройстве. Recursive tree API обрезан на 1 000 элементов; полное дерево и локальные raw provenance для Codeberg не сохранены. Сравнение каталогов относится только к Codeberg ref `3a9417b...` и имеющемуся GitHub snapshot `513e29a...`; оно не доказывает постоянное расхождение или невозможность последующей синхронизации.
