## Роль источника и границы

Nagram — Android-клиент Telegram, основанный на NekoX и изменённый своими функциями. Это репозиторий приложения, не публичного plugin SDK. В полном рекурсивном tree snapshot нет отдельной plugin engine, каталога plugin API или документации внешнего plugin lifecycle. Поэтому внутренние классы ниже полезны как примеры реализации функций в исходниках клиента, но не задают стабильный API для ExteraGram/AyuGram-плагина. Статус `code` подтверждает наличие в снимке, а не выполнение в установленном приложении; README-факты помечены `docs`, вывод об отсутствии SDK — `inference`.

README отделяет список дополнительных функций Nagram от унаследованного списка NekoX/Nekogram. Это важно при поиске происхождения конкретной идеи. Здесь собраны собственные классы Nagram и несколько базовых точек Telegram-клиента, через которые к ним подключается UI. README благодарит Nullgram, но это не подтверждает происхождение конкретных API. NagramX (отдельный source id `nagramx`) и Nullgram (`qwq233/Nullgram`) остаются самостоятельными источниками; NagramXTurbo (`temporaryna/NagramXTurbo`) — ещё один отдельный fork. Сходные названия/фичи и secondary radar mention о переносе Live Photo не объединялись с фактами Nagram без собственной line evidence.

## Факты и применимые приёмы

### UI и настройки

* Для настраиваемого контекстного меню `MessageMenuCompact` держит blacklist действий, которым требуются подменю, mutable subtext или специальная разметка; остальные option-id допускаются к compact-виду. Отдельный список управляет скрытием. Значения лежат как CSV числовых option-id в `NaConfig`, а не как интерфейс внешнего SDK. В `ChatActivity.createMenu` host сначала отбрасывает скрытые actions, затем спрашивает compact-state и выбирает число колонок. См. [`MessageMenuCompact.kt`](https://github.com/NextAlone/Nagram/blob/b8db62a65e1e4dee34d92bff412548ef628ddb06/TMessagesProj/src/main/java/xyz/nextalone/nagram/helper/MessageMenuCompact.kt#L14) и [точку интеграции в `ChatActivity`](https://github.com/NextAlone/Nagram/blob/b8db62a65e1e4dee34d92bff412548ef628ddb06/TMessagesProj/src/main/java/org/telegram/ui/ChatActivity.java#L32840).
* `ItemOptionsPatch.kt` добавляет Kotlin extension-функции над Telegram `ItemOptions`: заголовок, radio-item и список radio-items. Временный список ячеек привязан к владельцу через `WeakHashMap`; radio-check снимает отметку с прежнего элемента, callback остаётся у caller. Этот подход пригоден для клиентского патча UI при наличии исходников, но не обещает, что такой builder доступен плагину. См. [`ItemOptionsPatch.kt`](https://github.com/NextAlone/Nagram/blob/b8db62a65e1e4dee34d92bff412548ef628ddb06/TMessagesProj/src/main/kotlin/xyz/nextalone/nagram/ui/ItemOptionsPatch.kt#L15).
* `NaConfig` — реестр `ConfigItem(key, type, default)` с загрузкой разных примитивных типов из SharedPreferences. Перед чтением вызывается миграция. Пример split migration переводит прежний общий double-tap setting на incoming/outgoing keys, не перезаписывая уже существующие и не перенося неподходящий incoming Edit. При добавлении настройки нужны запись в реестр, загрузка/дефолт и миграция старого контракта, если ключ меняет смысл. См. [`NaConfig.kt`](https://github.com/NextAlone/Nagram/blob/b8db62a65e1e4dee34d92bff412548ef628ddb06/TMessagesProj/src/main/kotlin/xyz/nextalone/nagram/NaConfig.kt#L1408).
* `DoubleTap.getAction(message)` выбирает действие по входящему/исходящему сообщению, а `ChatActivity` перед фактическим выполнением учитывает тип ячейки и режим экрана (selection, secret chat, schedule, preview и quick reply). Практический шаблон: вынести preference policy из host UI и отдельно валидировать доступность операции в текущем контексте. См. [`DoubleTap.kt`](https://github.com/NextAlone/Nagram/blob/b8db62a65e1e4dee34d92bff412548ef628ddb06/TMessagesProj/src/main/kotlin/xyz/nextalone/nagram/helper/DoubleTap.kt#L31) и [`ChatActivity`](https://github.com/NextAlone/Nagram/blob/b8db62a65e1e4dee34d92bff412548ef628ddb06/TMessagesProj/src/main/java/org/telegram/ui/ChatActivity.java#L2017).

### События, аккаунты и тексты

* `NotificationCenter.getInstance(account)` адресует события одному аккаунту; `getGlobalInstance()` отдельно предназначен для глобальных событий. `ObserversGroup` собирает регистрации delegate и удаляет их вместе. `listen(view, id, callback)` подписывает при attach, отписывает при detach и возвращает cleanup `Runnable`; add/remove требуют main thread в debug-режиме. Это API внутреннего клиента, а не Nagram plugin hook. Для UI-кода извне оно применимо только если конкретная целевая платформа официально предоставляет этот слой. См. [`NotificationCenter.java`](https://github.com/NextAlone/Nagram/blob/b8db62a65e1e4dee34d92bff412548ef628ddb06/TMessagesProj/src/main/java/org/telegram/messenger/NotificationCenter.java#L424).
* `EntitiesHelper.parseMarkdown` работает с Android `Spannable`, не захватывает уже существующие code/mono spans, собирает source/destination замены перед их применением и создаёт Telegram style/url spans. Для форматирующего парсера полезно сохранять чужие spans и применять преобразования после обхода matcher. См. [`EntitiesHelper.java`](https://github.com/NextAlone/Nagram/blob/b8db62a65e1e4dee34d92bff412548ef628ddb06/TMessagesProj/src/main/java/xyz/nextalone/nagram/helper/EntitiesHelper.java#L32).
* `DialogsRecentForwardHelper.buildRecentDialogs` фильтрует recent id по allow-list, исключает нули и дубликаты, сохраняя порядок входного списка; при отсутствии полного объекта строит минимальный `TL_dialog`. Это пример изоляции чистой выборочной логики в helper-функции, отдельно от экранного кода. См. [`DialogsRecentForwardHelper.java`](https://github.com/NextAlone/Nagram/blob/b8db62a65e1e4dee34d92bff412548ef628ddb06/TMessagesProj/src/main/java/xyz/nextalone/nagram/helper/DialogsRecentForwardHelper.java#L14).

### Сеть, диагностика и медиа

* Внутренний `NetworkClient` строится поверх Ktor/OkHttp; сетевой вызов может быть обёрнут `NetworkLoggingInterceptor.executeWithLogging`, который измеряет время, фиксирует статус/ошибку и сохраняет запись в `finally`. Клиентская реализация настраивает JSON negotiation, таймауты и retry-on-connection-failure. Это пример приложения, не объявленный Nagram API для plugins. См. [`NetworkLoggingInterceptor.kt`](https://github.com/NextAlone/Nagram/blob/b8db62a65e1e4dee34d92bff412548ef628ddb06/TMessagesProj/src/main/java/xyz/nextalone/nagram/network/NetworkLoggingInterceptor.kt#L20) и [`NetworkClient`](https://github.com/NextAlone/Nagram/blob/b8db62a65e1e4dee34d92bff412548ef628ddb06/TMessagesProj/src/main/java/xyz/nextalone/nagram/network/NetworkLogManager.kt#L431).
* Диагностический журнал использует ObjectBox, пишет и чистит записи на IO dispatcher и удерживает максимум 1000 элементов. Сам interceptor сохраняет заголовки и request body, а response body ограничивает 5000 символами. В просмотренной реализации не видно redaction заголовков или request body — при переносе подобного механизма токены и личные данные нужно маскировать до сохранения. См. [`NetworkLogDb.java`](https://github.com/NextAlone/Nagram/blob/b8db62a65e1e4dee34d92bff412548ef628ddb06/TMessagesProj/src/main/java/xyz/nextalone/nagram/network/NetworkLogDb.java#L14) и [`NetworkLoggingInterceptor.kt`](https://github.com/NextAlone/Nagram/blob/b8db62a65e1e4dee34d92bff412548ef628ddb06/TMessagesProj/src/main/java/xyz/nextalone/nagram/network/NetworkLoggingInterceptor.kt#L76).
* `LyricsHelper` хранит до 16 LRU-значений в памяти, использует cache-файл для lyrics и разбирает LRC timestamps, дробные доли секунды и offset; одинаковые timestamps сортируются стабильно. Это применимо как шаблон ограниченного cache и parsing для локальных media metadata, но зависит от app cache/FileLoader. См. [`LyricsHelper.kt`](https://github.com/NextAlone/Nagram/blob/b8db62a65e1e4dee34d92bff412548ef628ddb06/TMessagesProj/src/main/kotlin/xyz/nextalone/nagram/helper/LyricsHelper.kt#L12).

## Дополнительные клиентские реализации

README перечисляет функции под буквальным заголовком `Additional feature over Nagram`, в том числе voice enhance, но это **документационные заявления**. В снимке найдено подтверждение voice processing: `AudioEnhance` по пользовательской настройке подключает поддерживаемые Android `AutomaticGainControl`, `AcousticEchoCanceler` и `NoiseSuppressor` к `AudioRecord`; `MediaController` вызывает init/release в пути записи. Это внутренний recorder integration point, не plugin API. [Helper](https://github.com/NextAlone/Nagram/blob/b8db62a65e1e4dee34d92bff412548ef628ddb06/TMessagesProj/src/main/kotlin/xyz/nextalone/nagram/helper/AudioEnhance.kt#L17-L67) · [call sites](https://github.com/NextAlone/Nagram/blob/b8db62a65e1e4dee34d92bff412548ef628ddb06/TMessagesProj/src/main/java/org/telegram/messenger/MediaController.java#L4816).

`MotionPhotoHelper` проверяет наличие/формат исходных файлов и делегирует упаковку выбранному по производителю `LivePhotoCreator`; `ChatActivity` обрабатывает результат. В `createMotionPhoto` после `embedMotionPhotoMetadata` проверка отсутствующего output вложена внутрь `if (data)`, поэтому `false` пропускает проверку и далее возвращается `Success`. Это статически видимая вероятная ошибка обработки, не результат runtime-проверки. [Helper](https://github.com/NextAlone/Nagram/blob/b8db62a65e1e4dee34d92bff412548ef628ddb06/TMessagesProj/src/main/kotlin/xyz/nextalone/nagram/helper/MotionPhotoHelper.kt#L108-L153) · [writer dispatch](https://github.com/NextAlone/Nagram/blob/b8db62a65e1e4dee34d92bff412548ef628ddb06/TMessagesProj/src/main/kotlin/xyz/nextalone/nagram/helper/livephoto/MotionPhotoWriter.kt#L17-L53) · [host UI](https://github.com/NextAlone/Nagram/blob/b8db62a65e1e4dee34d92bff412548ef628ddb06/TMessagesProj/src/main/java/org/telegram/ui/ChatActivity.java#L34666).

`ExternalStickerCacheHelper` копирует cached WebP stickers в настроенный SAF tree URI и выполняет файловую работу через coroutine на `Dispatchers.IO`. Helper подписывается на account-scoped sticker notifications; `LaunchActivity` снимает эти наблюдатели до смены account и добавляет для выбранного account после неё. Это требует учёта разрешения на SAF URI и lifecycle подписки. [Helper](https://github.com/NextAlone/Nagram/blob/b8db62a65e1e4dee34d92bff412548ef628ddb06/TMessagesProj/src/main/kotlin/xyz/nextalone/nagram/helper/ExternalStickerCacheHelper.kt#L254-L273) · [account switch](https://github.com/NextAlone/Nagram/blob/b8db62a65e1e4dee34d92bff412548ef628ddb06/TMessagesProj/src/main/java/org/telegram/ui/LaunchActivity.java#L1354-L1384).

`SystemAiServiceHelper` gates OEM AI dispatch on the local setting and HyperOS/ColorOS detection, then routes message text or a `Uri` through vendor-specific helpers; `ChatActivity` calls it from the message menu. `LocalPeerColorHelper` separately stores four self-user color/emoji overrides as JSON in `NaConfig`; its UI caller не входит в просмотренные host call-sites. `MessageHelper` exposes an internal FileProvider URI path and converts selected media to WebP for clipboard use. `StickerSetHelper.copyStickerSet` constructs a Telegram `TL_stickers_createStickerSet` request from sticker documents; its invoking UI caller в выбранном наборе файлов не установлен. Все эти seams принадлежат исходникам клиента и не объявляются внешними plugin API.

Детальный экран журнала показывает сохранённые request parameters/headers/body и response headers/body; поэтому вывод об отсутствии redaction относится и к persisted diagnostic UI surface, а не только к сети. Поиск и очистка выполняются внутренними `NetworkLogActivity` и `NetworkLogDb`; фактическая приватность устройства/доступа не проверялась. [Detail UI](https://github.com/NextAlone/Nagram/blob/b8db62a65e1e4dee34d92bff412548ef628ddb06/TMessagesProj/src/main/java/xyz/nextalone/nagram/network/NetworkLogDetailActivity.java#L96-L118).

## Пробелы и ограничения

* В снимке не найден документированный public plugin SDK, plugin lifecycle, manifest, permission model, dynamic loading contract или стабильные hooks. Перенос этих функций на ExteraGram/AyuGram требует отдельного подтверждения целевой платформой.
* Большие host-классы просматривались только вокруг релевантных call-sites; полный diff Nagram относительно upstream не анализировался.
* `README.NekoX.md` — унаследованная документация. Она не доказывает, что каждая перечисленная NekoX-функция всё ещё работает или присутствует в Nagram.
* Ни сборка, ни тесты, ни runtime приложения не запускались. Все code findings описывают только commit `b8db62a…`.
* Пересечения с выводами NagramX и Nullgram намеренно не импортировались без отдельного provenance.

Машинные факты: [`facts/nagram.json`](../facts/nagram.json), 34 уникальные записи с URL, путём, line evidence и статусом.
