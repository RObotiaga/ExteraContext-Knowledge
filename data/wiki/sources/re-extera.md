# fossSquad/re-extera

Источник: [репозиторий fossSquad/re-extera](https://github.com/fossSquad/re-extera), зафиксированный снимок `3be81ef0c25e842f3a8be669c235e783839c4716` (`master`, 2026-09-27). Лицензия по `repository.json` и `LICENSE` — GPL-3.0. GitHub обозначает репозиторий как `fork: false`; README называет его портом функций AyuGram для exteraGram и благодарит @bleizix за исходную идею/реализацию. Это самостоятельный репозиторий плагина, а не форк клиентского репозитория Telegram. Точный исходный код AyuGram-плагина, от которого произошёл ранний вариант, снимком не предоставлен, поэтому построчный diff с ним не делался.

Уровень доказательств: публичные сигнатуры loader и Java-контракты ниже извлечены из кода этого SHA. README даёт отдельные инструкции и заявления `docs`. Ни DEX, ни `.plugin`, ни клиент не запускались/не собирались/не устанавливались; результаты не являются `runtime-verified`. Текущая версия Python metadata внутри снимка — `2.9.0`, заявленный минимум exteraGram — `12.8.1`; это metadata loader, не универсальная гарантия совместимости с любым клиентом.

## Архитектура и developer workflow

README описывает двухчастную поставку: `.plugin` loader и отдельный `classes.dex`, который loader скачивает и загружает во время работы клиента. В коде Python `Plugin(BasePlugin)` является точкой входа ExteraGram; `on_plugin_load()` создаёт `Loader` с host context, а `on_plugin_unload()` вызывает DEX `onUnload()`. Публичная часть Android-модуля находится в `ni.shikatu.re_extera.Main`. Java и Python взаимодействуют через reflection по имени `ni.shikatu.re_extera.Main`, а не через общий исходниковый интерфейс ([metadata.py](https://github.com/fossSquad/re-extera/blob/3be81ef0c25e842f3a8be669c235e783839c4716/loader/metadata.py#L1-L7), [plugin.py](https://github.com/fossSquad/re-extera/blob/3be81ef0c25e842f3a8be669c235e783839c4716/loader/plugin.py#L318-L330), [dex.py](https://github.com/fossSquad/re-extera/blob/3be81ef0c25e842f3a8be669c235e783839c4716/loader/dex.py#L44-L84)).

README указывает Android SDK, JDK 17 и Python 3.x, команды `python3 loader/build.py` и `./gradlew buildDex`, а также install/update flow через loader ([README](https://github.com/fossSquad/re-extera/blob/3be81ef0c25e842f3a8be669c235e783839c4716/README.md#L27-L52)). Pinned Gradle Wrapper настроен на Gradle 8.14. Фактический модуль собирает Android library с `minSdk 26`, `compileSdk 35` и Java 11, применяет `d8` из build-tools версии `36.0.0`; `compileOnly` перечисляет локальные JAR из `libs`, Aliuhook 1.1.3 и AndroidX/Material ([build.gradle](https://github.com/fossSquad/re-extera/blob/3be81ef0c25e842f3a8be669c235e783839c4716/build.gradle#L41-L106), [gradle-wrapper.properties](https://github.com/fossSquad/re-extera/blob/3be81ef0c25e842f3a8be669c235e783839c4716/gradle/wrapper/gradle-wrapper.properties#L1-L6)). Следовательно, README JDK 17 и Gradle Java source/target 11 — разные настройки, а не противоречащие требования. `compileOnly` декларации сами по себе не устанавливают, доступны ли эти классы в runtime host classloader.

`Main.start()` открывает БД, инициализирует shadowban cache и regex patterns, подготавливает drawable для маркеров, локализует UI и затем регистрирует hooks. `initAndStart()` пропускает повторный старт, пока `hooks != null`; `onUnload()` проходит по каждому `XC_MethodHook.Unhook` и вызывает `unhook()`. Loader сначала пробует `InMemoryDexClassLoader` с classloader приложения, затем при ошибке пробует закэшированный `classes.dex` через `DexClassLoader`. Если локальный override файл существует, `load_and_start()` передаёт его байты в `start_from_bytes()` и затем безусловно возвращается. До class loading этот метод записывает те же байты в channel cache, а ошибки class loading перехватывает внутри себя. Поэтому повреждённый или несовместимый local DEX может перезаписать прежний cache и подавить fallback на cache/download и auto-update. Reflection вызывает `initAndStart()`; в старой версии есть fallback `getInstance().start()` ([Main.java](https://github.com/fossSquad/re-extera/blob/3be81ef0c25e842f3a8be669c235e783839c4716/src/main/java/ni/shikatu/re_extera/Main.java#L76-L88), [Main.java](https://github.com/fossSquad/re-extera/blob/3be81ef0c25e842f3a8be669c235e783839c4716/src/main/java/ni/shikatu/re_extera/Main.java#L131-L186), [HookInit.java](https://github.com/fossSquad/re-extera/blob/3be81ef0c25e842f3a8be669c235e783839c4716/src/main/java/ni/shikatu/re_extera/hooks/HookInit.java#L303-L322), [dex.py](https://github.com/fossSquad/re-extera/blob/3be81ef0c25e842f3a8be669c235e783839c4716/loader/dex.py#L44-L120)).

### Точки вмешательства и устойчивость к версии клиента

`HookInit` использует Aliuhook/Xposed-подобный контракт `XposedBridge.hookMethod(Method, XC_MethodHook)`. Точный helper `tryHook(name, clazz, methodName, hook, parameterTypes...)` находит объявленный метод по типам параметров. Два дополнительные resolver-пути ищут совпадение только по числу аргументов или минимальному числу; `HookLookup` выбирает первый подходящий `getDeclaredMethods()` результат. Это облегчает адаптацию к signature drift, но счётчик аргументов не различает overloads одного arity и не гарантирует правильную перегрузку ([HookInit.java](https://github.com/fossSquad/re-extera/blob/3be81ef0c25e842f3a8be669c235e783839c4716/src/main/java/ni/shikatu/re_extera/hooks/HookInit.java#L109-L161), [HookLookup.java](https://github.com/fossSquad/re-extera/blob/3be81ef0c25e842f3a8be669c235e783839c4716/src/main/java/ni/shikatu/re_extera/utils/HookLookup.java#L10-L43)).

Hook graph включает `ConnectionsManager.sendRequestInternal`, `MessagesController` (обновления, удаление, диалоги, no-forward), `MessagesStorage` (сохранение/deletion), `SendMessagesHelper`, `ChatActivity`, `ChatMessageCell`, `NotificationCenter`, `DialogsActivity`, профиль и Extera-specific menu/settings. Для Telegram 12.9.0 deletion storage signature в комментариях помечена как изменённая; код регистрирует новые варианты и fallback-варианты, включая range deletion. Optional Extera классы `MainMenuHelper`, drawer и navigation settings ищутся через `Class.forName`; недостающий `MainMenuHelper` пишет лог и оставляет legacy hooks. Каждый неудачный hook из общего helper логируется и не прерывает остальные регистрации ([HookInit.java](https://github.com/fossSquad/re-extera/blob/3be81ef0c25e842f3a8be669c235e783839c4716/src/main/java/ni/shikatu/re_extera/hooks/HookInit.java#L115-L161), [HookInit.java](https://github.com/fossSquad/re-extera/blob/3be81ef0c25e842f3a8be669c235e783839c4716/src/main/java/ni/shikatu/re_extera/hooks/HookInit.java#L164-L200), [HookInit.java](https://github.com/fossSquad/re-extera/blob/3be81ef0c25e842f3a8be669c235e783839c4716/src/main/java/ni/shikatu/re_extera/hooks/HookInit.java#L225-L290)).

### Ghost Mode, account scope и callbacks

`SendRequest.beforeHookedMethod()` получает account через `AccountUtils.getCurrentAccount(param.thisObject)` и классифицирует `TLObject` по типу. `Defaults.readingRequests`, `typingRequests`, `storiesRequests` и `onlineRequests` — явные списки request-классов. При блокировке read request код имитирует completion исходному `RequestDelegate` на `Utilities.stageQueue` (`TL_messages_affectedMessages` с `pts=-1`, `pts_count=0`) и прекращает исходный вызов через `param.setResult(null)`. Запросы чтения stories аналогично получают `TL_boolTrue`. Это внутренняя реализация этого проекта, не общий API ExteraGram plugin SDK ([Defaults.java](https://github.com/fossSquad/re-extera/blob/3be81ef0c25e842f3a8be669c235e783839c4716/src/main/java/ni/shikatu/re_extera/Defaults.java#L12-L42), [SendRequest.java](https://github.com/fossSquad/re-extera/blob/3be81ef0c25e842f3a8be669c235e783839c4716/src/main/java/ni/shikatu/re_extera/hooks/connectionsmanager/SendRequest.java#L25-L66)).

Для каждого dialog в БД может быть режим `ALWAYS=1`, `GLOBAL_VALUE=0`, `NEVER=-1`. Глобальное правило ghost исключает отдельно PM, group и channel; per-dialog override имеет приоритет. В `afterHookedMethod` после отправки сообщения плагин может запланировать на `globalQueue` запрос `TL_account.updateStatus(offline=true)` через секунду. Отправка сетевого запроса и UI callback не равны подтверждённому результату сервера; runtime-поведение тут не проверялось ([Defaults.java](https://github.com/fossSquad/re-extera/blob/3be81ef0c25e842f3a8be669c235e783839c4716/src/main/java/ni/shikatu/re_extera/Defaults.java#L12-L42), [SendRequest.java](https://github.com/fossSquad/re-extera/blob/3be81ef0c25e842f3a8be669c235e783839c4716/src/main/java/ni/shikatu/re_extera/hooks/connectionsmanager/SendRequest.java#L25-L119), [SendRequest.java](https://github.com/fossSquad/re-extera/blob/3be81ef0c25e842f3a8be669c235e783839c4716/src/main/java/ni/shikatu/re_extera/hooks/connectionsmanager/SendRequest.java#L160-L200)).

`ServerReadTracker` хранит позицию inbox-read как `Map<account, Map<dialogId,maxId>>`; `update()` продвигает только max ID, а `seed()` записывает стартовую позицию лишь при отсутствии значения. Hook `MessagesController.processUpdates` получает серверные `TL_updateReadHistoryInbox`/`TL_updateReadChannelInbox` и обновляет видимые message cells. Это специально отделяет серверную позицию от локального `MessagesController.dialogs_read_inbox_max`, который может сдвигаться локальным открытием чата ([ServerReadTracker.java](https://github.com/fossSquad/re-extera/blob/3be81ef0c25e842f3a8be669c235e783839c4716/src/main/java/ni/shikatu/re_extera/utils/ServerReadTracker.java#L8-L59), [ProcessUpdates.java](https://github.com/fossSquad/re-extera/blob/3be81ef0c25e842f3a8be669c235e783839c4716/src/main/java/ni/shikatu/re_extera/hooks/messagescontroller/ProcessUpdates.java#L132-L151), [MeasureTime.java](https://github.com/fossSquad/re-extera/blob/3be81ef0c25e842f3a8be669c235e783839c4716/src/main/java/ni/shikatu/re_extera/hooks/chatmessagecell/MeasureTime.java#L145-L247)).

### Database, filters и feature extension

`ReExteraDb` поднимается из Android application context, создаёт отдельный handler/database thread; async writes queue туда, чтобы hooks не выполняли SQLite операции на UI path. DB содержит message-deletion records, сериализованные TL message versions (original + edit history), dialog ghost/filter exceptions, regex filters, shadowban entries, read dates/last-online. Для повторного чтения есть memory caches; версии БД и migration находятся в `ReExteraDb.onUpgrade()` ([ReExteraDb.java](https://github.com/fossSquad/re-extera/blob/3be81ef0c25e842f3a8be669c235e783839c4716/src/main/java/ni/shikatu/re_extera/db/ReExteraDb.java#L45-L149), [ReExteraDb.java](https://github.com/fossSquad/re-extera/blob/3be81ef0c25e842f3a8be669c235e783839c4716/src/main/java/ni/shikatu/re_extera/db/ReExteraDb.java#L408-L515), [ReExteraDb.java](https://github.com/fossSquad/re-extera/blob/3be81ef0c25e842f3a8be669c235e783839c4716/src/main/java/ni/shikatu/re_extera/db/ReExteraDb.java#L1233-L1292)).

`MessageUtils.updatePatterns()` поддерживает compiled regex cache, `getMatchingFilters(text)` возвращает совпавшие шаблоны, а `shouldFilterMessage(MessageObject)` — интеграционный predicate. Новый фильтр из message context menu предварительно проходит `Pattern.compile`; обычный текст выбранного сообщения переводится в литеральный regex через `Pattern.quote(trimmedText)`, который пользователь может изменить. Встроенные hooks в `ChatMessageCell` скрывают filtered row и добавляют в menu show/check/add shortcuts. Import/export helper валидирует шаблоны и форматирует JSON/plain text ([MessageUtils.java](https://github.com/fossSquad/re-extera/blob/3be81ef0c25e842f3a8be669c235e783839c4716/src/main/java/ni/shikatu/re_extera/utils/MessageUtils.java#L184-L243), [ProcessSelectedOption.java](https://github.com/fossSquad/re-extera/blob/3be81ef0c25e842f3a8be669c235e783839c4716/src/main/java/ni/shikatu/re_extera/hooks/chatactivity/menuhook/ProcessSelectedOption.java#L91-L155), [FilterImportExportUtils.java](https://github.com/fossSquad/re-extera/blob/3be81ef0c25e842f3a8be669c235e783839c4716/src/main/java/ni/shikatu/re_extera/utils/FilterImportExportUtils.java#L17-L111)).

Полезные integration examples: удалённые сообщения ищутся и сохраняются вокруг `MessagesStorage.markMessagesAsDeleted`/`MessagesController.processUpdates`; `MeasureTime.afterHookedMethod` модифицирует time span видимой `ChatMessageCell`; `MessageForwarder.sendMessageCopy(AccountInstance, ArrayList<MessageObject>, peer, notify, scheduleDate, replyToTopMsg)` вручную готовит текст/медиа для restricted-forward сценария. Эти примеры показывают глубокую работу с host internals, но не дают стабильного public contract для сторонних плагинов ([MarkMessagesAsDeletedInternal.java](https://github.com/fossSquad/re-extera/blob/3be81ef0c25e842f3a8be669c235e783839c4716/src/main/java/ni/shikatu/re_extera/hooks/messagesstorage/MarkMessagesAsDeletedInternal.java#L20-L144), [MeasureTime.java](https://github.com/fossSquad/re-extera/blob/3be81ef0c25e842f3a8be669c235e783839c4716/src/main/java/ni/shikatu/re_extera/hooks/chatmessagecell/MeasureTime.java#L49-L144), [MessageForwarder.java](https://github.com/fossSquad/re-extera/blob/3be81ef0c25e842f3a8be669c235e783839c4716/src/main/java/ni/shikatu/re_extera/utils/MessageForwarder.java#L65-L115)).

## Применимые техники

1. Для исследования или расширения DEX lifecycle проследить обе стороны контракта: Python `Plugin.on_plugin_load/unload` → `Loader.load_and_start/unload` → Java `Main.initAndStart/onUnload`. Запуск проверить отдельно на целевой сборке host; просмотр исходника не проверяет runtime reflection/DEX classloader. Python `create_settings()` формирует host settings из `Text`, `Divider`, `Selector`; это пример UI DSL данного host SDK, а не независимое API этого репозитория ([plugin.py](https://github.com/fossSquad/re-extera/blob/3be81ef0c25e842f3a8be669c235e783839c4716/loader/plugin.py#L32-L85), [imports.py](https://github.com/fossSquad/re-extera/blob/3be81ef0c25e842f3a8be669c235e783839c4716/loader/imports.py#L1-L23)).
2. Новые hooks добавлять через `HookInit` и сохранять возвращённый `Unhook`, чтобы `onUnload()` действительно снял hook. Предпочитать exact parameter types; arg-count resolver использовать только если проверены overloads конкретного host SHA. Логировать отсутствие optional-класса/метода и продолжать регистрацию других hooks.
3. В network hook сначала извлечь правильный account из фактического host object, затем классифицировать request-класс; блокируя запрос, учитывать ожидание вызывающего кода от `RequestDelegate`. Пример `SendRequest` демонстрирует synthetic completion, но его семантика должна быть заново проверена для новых Telegram TL request.
4. UI обновлять на UI thread, SQLite writes направлять на `ReExteraDb` queue, а per-account server state хранить по паре `(account, dialogId)`. Код с `MessagesController` и `ServerReadTracker` иллюстрирует эти границы.
5. Для regex фильтра брать сообщение в context menu как предложенный literal, превращать его `Pattern.quote(text.trim())`, валидировать новый пользовательский шаблон через `Pattern.compile`, затем пересобрать matcher cache посредством `MessageUtils.updatePatterns()`.
6. Для build output понимать две раздельные задачи: README и CI сначала получают `.plugin` через Python concatenation, и DEX через Gradle AAR → `d8`; CI кладёт оба файла в artifact/release. Выполнение build в рамках этого сбора не производилось.

## Network, settings и build caveats

Loader проверяет GitHub REST endpoints для releases и Actions runs, nightly.link zip для dev artifacts, затем скачивает `.dex` и иногда новый `loader.plugin`. Dev checks по умолчанию не чаще раза в 60 секунд; запросы release/dev metadata имеют `timeout=5`, downloads — `timeout=60`. Конфигурация в app files dir хранит channel, версии по channel и last-check, а DEX-кэш раздельный (`release`/`dev`). Local override path жёстко задан как `/storage/emulated/0/Android/media/com.exteragram.messenger/classes.dex`; наличие этого файла при старте имеет приоритет и пропускает auto-update check ([constants.py](https://github.com/fossSquad/re-extera/blob/3be81ef0c25e842f3a8be669c235e783839c4716/loader/constants.py#L1-L25), [config.py](https://github.com/fossSquad/re-extera/blob/3be81ef0c25e842f3a8be669c235e783839c4716/loader/config.py#L1-L54), [dex.py](https://github.com/fossSquad/re-extera/blob/3be81ef0c25e842f3a8be669c235e783839c4716/loader/dex.py#L86-L121), [dex.py](https://github.com/fossSquad/re-extera/blob/3be81ef0c25e842f3a8be669c235e783839c4716/loader/dex.py#L154-L259), [dex.py](https://github.com/fossSquad/re-extera/blob/3be81ef0c25e842f3a8be669c235e783839c4716/loader/dex.py#L261-L417)). В inspected updater пути не обнаружены подписи или checksum verification скачанного DEX; это граница просмотренной реализации, не security audit всего client/plugin runtime. `_fetch_cached()` вызывает callback сразу при cache hit или прямо из созданного `threading.Thread`; callers, меняющие UI, должны отдельно поставить работу через `AndroidUtilities.runOnUIThread`. Сохранённый callback сам по себе UI-thread callback не гарантирован ([plugin.py](https://github.com/fossSquad/re-extera/blob/3be81ef0c25e842f3a8be669c235e783839c4716/loader/plugin.py#L7-L21), [plugin.py](https://github.com/fossSquad/re-extera/blob/3be81ef0c25e842f3a8be669c235e783839c4716/loader/plugin.py#L173-L223)).

`Settings` кэширует Android `SharedPreferences("re_extera", 0)`; ключи обычно не кодируют account, а отдельный premium-cache включает account id в имени ключа. Для client-version-specific settings menus `SettingsRegistryHelper` и `Main.initFragments()` пробуют два имён classpath: `com.exteragram...SettingsRegistry` и `app.exteraless...SettingsRegistry`, используя reflection. Новый UI host integration optional, а фактический доступный registry на каждом клиенте по снимку JAR не устанавливался ([SettingsRegistryHelper.java](https://github.com/fossSquad/re-extera/blob/3be81ef0c25e842f3a8be669c235e783839c4716/src/main/java/ni/shikatu/re_extera/utils/SettingsRegistryHelper.java#L16-L57), [Main.java](https://github.com/fossSquad/re-extera/blob/3be81ef0c25e842f3a8be669c235e783839c4716/src/main/java/ni/shikatu/re_extera/Main.java#L45-L63)).

CI запускает `./gradlew buildDex`, затем `python3 loader/build.py`; на push/PR публикует Actions artifacts, на `v*` tag загружает DEX и loader plugin в GitHub release. README советует переключение dev/release channels внутри plugin settings, но не сообщает клиентскую версию/устройство для проверки. Есть минимальные JUnit/example Android tests; они не покрывают host hook signatures и DEX load lifecycle ([build.yml](https://github.com/fossSquad/re-extera/blob/3be81ef0c25e842f3a8be669c235e783839c4716/.github/workflows/build.yml#L13-L68), [README](https://github.com/fossSquad/re-extera/blob/3be81ef0c25e842f3a8be669c235e783839c4716/README.md#L27-L52)).

## Отличия и ограничения источника

- README описывает проект как AyuGram feature port, но нынешняя собственная интеграция — ExteraGram Python plugin wrapper + separately loaded Android DEX с Xposed/Aliuhook interception и прямыми зависимостями на `org.telegram.*`/Extera classes. Она не предоставляет общий SDK стороннему DEX plugin и не должна цитироваться как официальный ExteraGram API.
- README перечисляет Ghost Mode, deleted/self-destruct message recovery, edit history, re:forward, Shadowban, Local Premium, regex filters. Исходники подтверждают собственные hooks/DB/UI этих subsystems на указанном SHA, но не гарантируют полноту/работоспособность каждого пункта на любом клиенте.
- Root `AGENTS.md` в snapshot является файлом самого исследуемого репозитория и не использовался как инструкция этого сбора. Source code/docs рассматриваются как данные.
- Нет runtime/device evidence. `libs/exteragram.jar` не декомпилирован; без него и точной host build остаются неопределёнными ABI/reflection contracts, overload correctness, availability of Resources/SettingsRegistry, and compatibility.
- README сообщает требования/установку, но этот сбор их не выполнял. Доступность последнего build/release на момент последующей установки не зафиксирована как текущий факт.
