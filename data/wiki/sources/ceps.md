# m4rker20-rgb/CEPS — подписываемый сборщик и загрузчик ExteraGram-плагинов

Источник: [m4rker20-rgb/CEPS](https://github.com/m4rker20-rgb/CEPS), ветка `main`, снимок `8c1a4dc70387d782e012732f3868317851414012`, сохранён 2026-09-27. Репозиторий называет себя защищённым конвейером сборки ExteraGram-плагинов; это прежде всего CLI builder, формат контейнера и Python loader/installer. Это **не** реализация plugin SDK и не исходный код ExteraGram. В `LICENSE` указана собственная CEPS License v1.0: разрешено коммерческое использование при сохранении уведомлений и обязательной видимой атрибуции каждого распространяемого артефакта `Built with CEPS` и ссылкой на репозиторий. Это source-available лицензия, не OSI open-source ([LICENSE, строки 1–12](https://github.com/m4rker20-rgb/CEPS/blob/8c1a4dc70387d782e012732f3868317851414012/LICENSE#L1-L12), [строки 23–40](https://github.com/m4rker20-rgb/CEPS/blob/8c1a4dc70387d782e012732f3868317851414012/LICENSE#L23-L40)).

Здесь ничего не запускалось, не собиралось, не устанавливалось и не проверялось на телефоне. Сведения из `docs/` — документация, а не доказательство клиентской реализации или runtime-поведения. Кодовые выводы ниже относятся только к закреплённому SHA.

## Что реализует CEPS

Сборка читает `ceps.json`, выбирает файлы по `encrypt`/`exclude`, создаёт контейнер `.ceps`, Python loader с тем же содержимым под суффиксом `.plugin`, а по `--elyx` — ZIP/Elyx-обёртку `.eaf`. В коде явно сказано, что `.ceps` — канонический защищённый контейнер, а прямой установочной единицей является loader `.plugin`; `.py` выдаётся как loader для разработки ([cepsbuilder.py, строки 3–15, 396–457, 514–549](https://github.com/m4rker20-rgb/CEPS/blob/8c1a4dc70387d782e012732f3868317851414012/CEPSbuilder/cepsbuilder.py#L3-L15)). Следовательно, `.ceps`, `.plugin` и `.eaf` — разные роли артефактов, хотя README перечисляет все как build outputs.

В реализации сборщик генерирует случайный 32-байтовый master, разделяет его на XOR-доли, выводит файловые ключи из `SHA256(master || logical_path)`, шифрует ChaCha20 с 12-байтовым nonce и вычисляет HMAC-SHA256 от plaintext под отдельным master-derived ключом. В `enc_v2` контейнер не несёт старую магическую строку и не публикует plaintext SHA как замену HMAC ([cepsbuilder.py, строки 103–122, 343–345, 441–455](https://github.com/m4rker20-rgb/CEPS/blob/8c1a4dc70387d782e012732f3868317851414012/CEPSbuilder/cepsbuilder.py#L103-L122), [test_memenc.py, строки 46–54](https://github.com/m4rker20-rgb/CEPS/blob/8c1a4dc70387d782e012732f3868317851414012/CEPSbuilder/test_memenc.py#L46-L54)). Структурная верификация проверяет размер и SHA доставленных файлов, Merkle root, связность блоков hash-chain и Ed25519 подпись последнего блока; `verify_files` затем выводит master (из долей или env-slots), расшифровывает payload и проверяет HMAC/старый plaintext hash ([ceps_rt.py, строки 261–276, 344–407, 410–465](https://github.com/m4rker20-rgb/CEPS/blob/8c1a4dc70387d782e012732f3868317851414012/CEPSbuilder/ceps_rt.py#L261-L276)). Hash-chain обнаруживает переписывание уже связанной истории лишь при сохранённой доверенной точке/подписанном последнем блоке; сама цепочка не является серверным журналом публикаций.

CEPS-3 использует `env_classes`: loader ищет Android/Telegram классы через `hook_utils.find_class`, хеширует отсортированные публичные имена из `dir(cls)`, применяет KDF слота, затем расшифровывает обёрнутый master. Слоты пробуются по порядку, пропавший класс даёт шанс следующему. Для scrypt реализация задаёт параметры из слота (defaults N=16384, r=8, p=1) и при недоступности поднимает `CepsError`, без fallback на PBKDF2; PBKDF2 остаётся отдельным режимом. `verify_structure` позволяет проверить подпись/целостность env-архива без получения master, но не раскрывает payload ([ceps_rt.py, строки 296–341, 344–407](https://github.com/m4rker20-rgb/CEPS/blob/8c1a4dc70387d782e012732f3868317851414012/CEPSbuilder/ceps_rt.py#L296-L341)). Коллектор `collect-env` — временный plugin: снимает сигнатуры перечисленных классов на телефоне и копирует JSON в буфер обмена ([cepsbuilder.py, строки 821–900](https://github.com/m4rker20-rgb/CEPS/blob/8c1a4dc70387d782e012732f3868317851414012/CEPSbuilder/cepsbuilder.py#L821-L900)). Это привязка к форме API классов клиента, не Android permission/Keystore API и не уникальный секрет устройства.

Loader требует guard table и её печать и сверяет digest таблицы перед проверкой архива и исполнением entry. Дополнительное сравнение переданного seal с `EXPECTED_GUARD_SEAL` вшивается builder только в режиме `--rt-pyc`; при обычном исходном runtime глобальное значение остаётся `None`, поэтому эта вторая проверка пропускается. Anti-debug, если включён, выполняется до чтения архива; runtime проверяет `TracerPid` из `/proc/self/status` и TCP localhost-порты 27042–27045, а ошибки чтения `/proc` игнорирует ([ceps_rt.py, строки 499–548](https://github.com/m4rker20-rgb/CEPS/blob/8c1a4dc70387d782e012732f3868317851414012/CEPSbuilder/ceps_rt.py#L499-L548), [builder, строки 317–332](https://github.com/m4rker20-rgb/CEPS/blob/8c1a4dc70387d782e012732f3868317851414012/CEPSbuilder/cepsbuilder.py#L317-L332), [ceps_rt.py, строки 468–493](https://github.com/m4rker20-rgb/CEPS/blob/8c1a4dc70387d782e012732f3868317851414012/CEPSbuilder/ceps_rt.py#L468-L493)). Это не обнаружение всех отладчиков и не общий сетевой транспорт.

После расшифровки Python entry исполняется в namespace `ceps_payload` (или `marshal`-кодом для `--pyc`). При заданном `target_dir` Python-файлы не пишутся на диск, но остальные payload-файлы материализуются в `.ceps_cache/<id>` с исходной структурой. Для `mem_dex` имеющийся в payload `.dex` остаётся в памяти; `ceps_dex` в namespace — callable, возвращающий его байты, либо `None`, если DEX не найден. `ceps_files()` сообщает пути материализованных ресурсов. Эти имена — вспомогательные значения CEPS loader, не стандартные API ExteraGram ([ceps_rt.py, строки 553–606](https://github.com/m4rker20-rgb/CEPS/blob/8c1a4dc70387d782e012732f3868317851414012/CEPSbuilder/ceps_rt.py#L553-L606), [test_memenc.py, строки 56–84](https://github.com/m4rker20-rgb/CEPS/blob/8c1a4dc70387d782e012732f3868317851414012/CEPSbuilder/test_memenc.py#L56-L84)). Без `mem_dex` расшифрованные `.dex`, `.so`, `.pyc` и данные могут оказаться на диске в кэше; шифрование контейнера не означает encrypted-at-rest кэш.

Installer-шаблон регистрирует расширение `ceps` через `FilesController.register(...)` при `on_plugin_load`, снимает регистрацию при `on_plugin_unload`, проверяет файл против пользовательского списка доверенных Ed25519 ключей, показывает подтверждение и записывает loader как `<id>.py` в plugin directory. Настройки позволяют добавить/удалить trusted keys и запретить перезапись существующего файла. Для env-архива installer проверяет только структуру, подпись и целостность; ключ расшифровки на установке не нужен ([installer_template.py, строки 44–89](https://github.com/m4rker20-rgb/CEPS/blob/8c1a4dc70387d782e012732f3868317851414012/CEPSbuilder/installer_template.py#L44-L89), [строки 110–129, 146–229](https://github.com/m4rker20-rgb/CEPS/blob/8c1a4dc70387d782e012732f3868317851414012/CEPSbuilder/installer_template.py#L110-L129)). Снимок содержит также generated `ceps_installer.py` с тем же installer flow; `make_installer.py` показывает, что файл собирается из шаблона и вшитой копии runtime. `FilesController` и `file_utils` — host/client API, которые использует отдельный CEPS plugin installer, а не функция самого формата `.ceps` ([ceps_installer.py, строки 96–132, 193–212](https://github.com/m4rker20-rgb/CEPS/blob/8c1a4dc70387d782e012732f3868317851414012/ceps_installer.py#L96-L132), [make_installer.py, строки 1–27](https://github.com/m4rker20-rgb/CEPS/blob/8c1a4dc70387d782e012732f3868317851414012/CEPSbuilder/make_installer.py#L1-L27)).

`embed_shares` по умолчанию включён: builder кладёт доли в manifest обычного, не env-архива. Если его отключить, `.ceps` без env slots содержит данные для структурной проверки, но installer откажет в установке из-за отсутствия долей; direct loader может получить shares отдельно. Для env-архивов installer идёт по отдельной ветви `verify_structure` ([cepsbuilder.py, строки 124–143, 484–487](https://github.com/m4rker20-rgb/CEPS/blob/8c1a4dc70387d782e012732f3868317851414012/CEPSbuilder/cepsbuilder.py#L124-L143), [installer_template.py, строки 44–85](https://github.com/m4rker20-rgb/CEPS/blob/8c1a4dc70387d782e012732f3868317851414012/CEPSbuilder/installer_template.py#L44-L85)).

## ExteraGram API из встроенных docs (статус `docs`)

Справочник `docs/plugin-class.txt` описывает metadata как простые top-level константы, поскольку host loader читает их AST-ом; обязательны `__id__` и `__name__`. Там документированы `on_plugin_load`, `on_plugin_unload`, `on_app_event`, `create_settings`, а для хуков — `pre_request_hook`, `post_request_hook`, `on_update_hook`, `on_updates_hook`, `on_send_message_hook`. `self.add_hook(name, match_substring=False, priority=0)` и `self.add_on_send_message_hook(priority=0)` надо вызывать для регистрации; результаты управляются `HookResult` и `HookStrategy` (`DEFAULT`, `CANCEL`, `MODIFY`, `MODIFY_FINAL`) ([plugin-class.txt, строки 5–53, 95–155, 265–377](https://github.com/m4rker20-rgb/CEPS/blob/8c1a4dc70387d782e012732f3868317851414012/docs/plugin-class.txt#L5-L53)). CEPS proxy кода оборачивает/делегирует lifecycle, UI и пять hook callbacks (`on_send_message_hook`, request pre/post и updates), но эта прокладка не реализует Telegram request interception сама: обработку событий обеспечивает plugin engine host ([ceps_rt.py, строки 832–891, 941–1040](https://github.com/m4rker20-rgb/CEPS/blob/8c1a4dc70387d782e012732f3868317851414012/CEPSbuilder/ceps_rt.py#L832-L891)).

Документы UI описывают `create_settings() -> List[Any]` с объектами `ui.settings`, включая простые `Header`, `Switch`, `Input`, `Text`, `Selector`, подстраницы и `Custom`/`SimpleSettingFactory`; custom factory разделяет создание view, bind и click callbacks. Для dialog callbacks документы отдельно советуют Android UI thread. Это примеры host SDK, не функции сборщика CEPS ([plugin-settings.txt, строки 5–7, 197–239, 241–375](https://github.com/m4rker20-rgb/CEPS/blob/8c1a4dc70387d782e012732f3868317851414012/docs/plugin-settings.txt#L5-L7), [alert-dialog-builder.txt, строки 126–130](https://github.com/m4rker20-rgb/CEPS/blob/8c1a4dc70387d782e012732f3868317851414012/docs/alert-dialog-builder.txt#L126-L130)). `BasePlugin.get_setting/set_setting/export_settings/import_settings` документированы как plugin settings storage; CEPS installer использует эти helpers для trusted keys и overwrite preference. Документы не заявляют secure secret storage.

`client-utils.txt` описывает `run_on_queue(func, queue=PLUGINS_QUEUE, delay=0)` для тяжёлой работы вне UI callback, `send_request(request, fn, account=...)` для сырого Telegram `TLObject` через `ConnectionsManager`, и account-scoped методы/контроллеры. Hook и request callback получают account; вызов helper без account по документации использует selected UI account, поэтому multi-account обработчик должен применять `self.client(account)` или передавать `account=...` ([client-utils.txt, строки 14–75, 77–114, 279–323](https://github.com/m4rker20-rgb/CEPS/blob/8c1a4dc70387d782e012732f3868317851414012/docs/client-utils.txt#L14-L75), [multi-account.txt, строки 3–75](https://github.com/m4rker20-rgb/CEPS/blob/8c1a4dc70387d782e012732f3868317851414012/docs/multi-account.txt#L3-L75)). Это client internals/wrappers, а не CEPS transport API. Для внешнего HTTP docs перечисляют `requests` среди preinstalled libraries и советуют pure-Python зависимости; PIP-пакеты загружаются с PyPI, делят общее хранилище и могут конфликтовать по версиям ([available-libraries.txt, строки 7–21](https://github.com/m4rker20-rgb/CEPS/blob/8c1a4dc70387d782e012732f3868317851414012/docs/available-libraries.txt#L7-L21), [pip.txt, строки 7–47](https://github.com/m4rker20-rgb/CEPS/blob/8c1a4dc70387d782e012732f3868317851414012/docs/pip.txt#L7-L47)). CEPS не добавляет отдельную permission declaration в `ceps.json`; его документация не определяет plugin permission model, а правила Android network permissions/политики клиента этим источником не установлены.

Reflection/hooking материалы также относятся к ExteraGram/Android host: `hook_utils.find_class`, `get_private_field`, Xposed/LSPosed `MethodHook`/`MethodReplacement`, Java методы и Android classes. CEPS использует `hook_utils.find_class` лишь в CEPS-3 env-signature helper/collector; документация не делает эти функции CEPS API ([hook-utils.txt, строки 1–31](https://github.com/m4rker20-rgb/CEPS/blob/8c1a4dc70387d782e012732f3868317851414012/docs/hook-utils.txt#L1-L31), [xposed-hooking.txt, строки 1–18](https://github.com/m4rker20-rgb/CEPS/blob/8c1a4dc70387d782e012732f3868317851414012/docs/xposed-hooking.txt#L1-L18), [ceps_rt.py, строки 296–303](https://github.com/m4rker20-rgb/CEPS/blob/8c1a4dc70387d782e012732f3868317851414012/CEPSbuilder/ceps_rt.py#L296-L303)).

### Версии, build, distribution, testing

CLI в этом SHA содержит `keygen`, `new`, `build`, `watch`, `verify`, `selftest`, `collect-env`; `build` поддерживает `--elyx`, `--obf/--no-obf`, `--zlib`, `--pyc`, `--rt-pyc`, `--allow-envsim` и verbose. Python 3.10+ заявлен для обычного builder; Python 3.11 требуется для payload/runtime marshal `.pyc`. Defaults, создаваемые builder, — app `>=12.5.1` и SDK `>=1.4.5.0` ([README.md, строки 107–180](https://github.com/m4rker20-rgb/CEPS/blob/8c1a4dc70387d782e012732f3868317851414012/README.md#L107-L180), [cepsbuilder.py, строки 124–143, 178–205, 907–975](https://github.com/m4rker20-rgb/CEPS/blob/8c1a4dc70387d782e012732f3868317851414012/CEPSbuilder/cepsbuilder.py#L124-L143)). Встроенные plugin docs расходятся сами с собой: `plugin-class.txt`, `setup.txt`, `first-plugin.txt` дают SDK `>=1.4.4.3`, тогда как multi-account notes требуют `>=1.4.5.0`, а CEPS builder/installer defaults — `>=1.4.5.0`. Выбирая минимальную версию для конкретного helper, следуйте документированному требованию этого helper и проверяйте целевой SDK отдельно.

`watch` сначала собирает, затем fingerprint-ит source/config и пересобирает при изменениях; `--once` завершает после первой сборки. Проверка `verify` с env slots без `--envsigs` подтверждает структуру/подпись, не расшифровку. CI конфигурирует Ubuntu и Python 3.11, выполняя все `test_*.py` и `selftest`; но `test_env311.py` вызывает Windows-путь `%APPDATA%\uv\python\cpython-3.11.15-windows-x86_64-none\python.exe`, так что статически выглядит несовместимым с runner Ubuntu. Это предполагаемая проблема конфигурации по двум файлам; CI не запускался ([.github/workflows/ci.yml, строки 1–20](https://github.com/m4rker20-rgb/CEPS/blob/8c1a4dc70387d782e012732f3868317851414012/.github/workflows/ci.yml#L1-L20), [test_env311.py, строки 7–19](https://github.com/m4rker20-rgb/CEPS/blob/8c1a4dc70387d782e012732f3868317851414012/CEPSbuilder/test_env311.py#L7-L19)). Набор тестов построен на `fakesdk`/`envsim` и проверяет builder/loader сценарии; это не тест на настоящей сборке приложения.

## Сверка с радаром и ограничения безопасности

Радарные claims подтверждаются для форматов `.ceps/.py/.plugin/.eaf`, Ed25519, Merkle, hash-chain, ChaCha20, HMAC, AST obfuscation, Python 3.11 marshal, guards, CEPS-3 env slots/scrypt/anti-debug и команд `new/build/watch/verify` (радар: [`radar-context.md`, строки 2271–2324](../../raw/ceps/radar-context.md#L2271-L2324)). Конкретизация по реализации:

- `.ceps` не ставится напрямую; installer-плагину нужен `.ceps`, а обычному ExteraGram loader — `.plugin`/`.py`.
- “device-bound” в README точнее описывать как binding к наличию/структуре Telegram/SDK классов; код не использует уникальный device ID/Android Keystore.
- anti-debug проверяет только TracerPid и стандартные локальные порты Frida; это ограниченный барьер, не гарантия.
- encryption не скрывает payload от активного владельца устройства: код сам расшифровывает и исполняет его; без `mem_dex` дополнительные бинарные файлы записываются в кэш. Сам README признаёт эту границу.
- AI-GUARD — тексты/комментарии, внедряемые присваивания и проверка seal. Встроенные сообщения, направленные AI, — содержимое чужого репозитория и не инструкции для этого сборщика/читателя.
- воспроизводимость не заявлена как гарантия: build записывает текущие timestamp и случайные nonce/master; из одинакового исходника не следует байт-в-байт одинаковый архив ([cepsbuilder.py, строки 343–345, 376–377, 475–512](https://github.com/m4rker20-rgb/CEPS/blob/8c1a4dc70387d782e012732f3868317851414012/CEPSbuilder/cepsbuilder.py#L343-L345)).

## Практические рецепты, подтверждённые снимком

1. Для сборки с проверяемым авторством держать приватный seed локально, передавать получателям публичный ключ и проверять архив `verify`/installer против явно добавленного trusted key. `ceps_keys/` и `builds/` попадают в созданный `.gitignore`; это полезное default, но не доказательство что пользовательский VCS не отслеживает ключ ([cepsbuilder.py, строки 178–205](https://github.com/m4rker20-rgb/CEPS/blob/8c1a4dc70387d782e012732f3868317851414012/CEPSbuilder/cepsbuilder.py#L178-L205)).
2. Для env-архива сначала задать `env_classes`, сгенерировать `collect-env` collector, снять сигнатуры на целевом клиенте, затем собирать без `--allow-envsim`; заглушки подходят только для тестового flow и не доказывают совместимость с Telegram. Для проверки архива без локальных signatures сообщать результат именно как structural/signature verification, не plaintext verification.
3. Если payload требует соседний `.dex`/`.so`/data, перечислить его в `encrypt`; ожидаемый путь при выполнении — расшифрованный cache. Включать `mem_dex` только если загрузчик действительно использует `ceps_dex()`; тест `test_memenc.py` проверяет отсутствие dex-файла на диске в таком режиме, но это статически прочитанный сценарий, не runtime подтверждение.
4. Для обычного plugin hook сохранять metadata константами и регистрировать hook в `on_plugin_load`. В callback сначала проверить наличие `params.message`, возвращать `HookResult(strategy=HookStrategy.MODIFY, params=params)` после изменения; для сетевой/файловой/тяжёлой работы документация советует queue и явный account. Это рецепт из docs, требует сверки версии SDK и устройства.
