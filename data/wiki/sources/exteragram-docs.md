# yearningss/exteraGram-docs

Источник: [репозиторий yearningss/exteraGram-docs](https://github.com/yearningss/exteraGram-docs), default branch `main`, снимок `341db43686bfb3212e1ecf3cddcc8b8fcfd885f3`, зафиксированный 2026-09-27. Автор описывает клиент `12.10.1`, build `70389`, канал Full Beta Universal; заявленная версия Elyx SDK — `1.4.5.5`. Документы — результат анализа сборки, а не исходный код клиента или официальный reference SDK. В метаданных репозитория лицензия не указана. Runtime-проверок не проводилось.

## Роль и границы доказательств

Это полезный обзор архитектуры одной конкретной сборки и пользовательских экранов, включая Python-плагины, Elyx, ExteraHook, конфигурацию, сеть и локальную БД. Все утверждения, относящиеся к устройству клиента, имеют статус `docs`: снимок не содержит APK, Java/Kotlin/Python реализаций ExteraGram или тестов. Поэтому названия пакетов, точные версии библиотек, маршруты API, дефолты настроек и поведение хуков нельзя считать независимо подтверждёнными.

API-поверхность сверена с доступными типовыми декларациями [`exteragram-utils` 0.1.3](../../raw/exteragram-utils/files/base_plugin.py#L123) и с документами официального SDK, захваченными отдельно. Это только перекрёстная проверка внешнего описания/объявлений: stub не является реализацией клиента и не доказывает работу на указанной сборке. Обнаружено существенное расхождение lifecycle: здесь примеры зовут `on_load`/`on_unload`, тогда как объявления `BasePlugin` в stub используют `on_plugin_load`/`on_plugin_unload`; пример официального SDK также использует вторую пару. До проверки на фактической целевой сборке рецепт из этой страницы нельзя брать как готовый исполняемый шаблон.

## Версия и плагиновая среда

README называет пакет `com.exteragram.messenger`, Android Min SDK 24 / Target SDK 36, 7 DEX, 42 ELF-библиотеки, CPython 3.11 через Chaquopy, Elyx 1.4.5.5, Room schema v5 и backend URL. Это паспорт описанной сборки, а не универсальное требование ко всем версиям клиента ([README, строки 34–48](https://github.com/yearningss/exteraGram-docs/blob/341db43686bfb3212e1ecf3cddcc8b8fcfd885f3/README.md#L34-L48)). Архитектурный документ повторяет версию/сборку и заявляет размещение Chaquopy в `classes7.dex` ([architecture, строки 1–28](https://github.com/yearningss/exteraGram-docs/blob/341db43686bfb3212e1ecf3cddcc8b8fcfd885f3/docs/architecture.md#L1-L28)).

В SDK-руководстве описаны два формата: одиночный `.py` с верхнеуровневыми metadata и архив `.elyx`/`.eaf`; для archive показаны `metainfo.yml`, `refmap.yml`, `src/`, `assets/`, `strings/`, `wheels/`, а также фасад `elyx.assets/metainfo/refmap/settings/strings` ([plugins-and-sdk, строки 16–82](https://github.com/yearningss/exteraGram-docs/blob/341db43686bfb3212e1ecf3cddcc8b8fcfd885f3/docs/plugins-and-sdk.md#L16-L82)). Структура и `__min_sdk__` примера — документационные утверждения; отдельная страница официального SDK описывает AST metadata с другими ключами (`__sdk_version__`, `__app_version__`) и не подтверждает `metainfo.yml`/`refmap.yml` как фактический loader-контракт.

Материалы расходятся по требованиям к SDK и именам metadata: README и руководство называют Elyx `1.4.5.5`; YAML-пример задаёт `min_sdk: 1.4.5.5`, а однофайловый пример — `__min_sdk__ = "1.4.0"`. Захваченная отдельно документация официального SDK описывает поверхность 1.4.4.3 и keys `__sdk_version__`/`__app_version__` (с legacy `__min_version__`), а не подтверждает YAML/`__min_sdk__` контракт. Это сопоставление разных версий и источников, а не доказательство ошибки runtime одного из них; политика совместимости и принятия ключей не описана ([README, строки 44–47](https://github.com/yearningss/exteraGram-docs/blob/341db43686bfb3212e1ecf3cddcc8b8fcfd885f3/README.md#L44-L47); [plugins-and-sdk, строки 3, 27–40, 60–70](https://github.com/yearningss/exteraGram-docs/blob/341db43686bfb3212e1ecf3cddcc8b8fcfd885f3/docs/plugins-and-sdk.md#L3-L70); [official SDK Plugin Class](https://plugins.exteragram.app/docs/plugin-class#metadata)).

### Жизненный цикл, потоки и хуки

Оба inline-примера — и single-file, и archive — наследуются от `base_plugin.BasePlugin` и вызывают `on_load()`; первый также показывает `on_unload()`, а таблица модулей перечисляет `on_load()`, `on_unload()` и `on_stop()` ([plugins-and-sdk, строки 20–40, 73–82, 86–93](https://github.com/yearningss/exteraGram-docs/blob/341db43686bfb3212e1ecf3cddcc8b8fcfd885f3/docs/plugins-and-sdk.md#L20-L40)). Доступная декларация `BasePlugin` для версии вспомогательного пакета 0.1.3 содержит `on_plugin_load()` и `on_plugin_unload()`, без указанных здесь имён; отдельно захваченная документация официального SDK также показывает пару `on_plugin_*`. Это расхождение документаций/версий, а не runtime-проверка; использовать пример `on_load` без проверки нельзя. Этот docs-source не задаёт точную семантику повторной загрузки/остановки, порядка callbacks или потоковой гарантии для самих callbacks.

Документация утверждает, что фоновые вызовы Python автоматически синхронизируются с Android UI Thread через `Handler` и `AndroidUtilities.runOnUIThread()`; архитектура описывает JNI bridge как средство трансляции типов, исключений и потоков ([plugins-and-sdk, строки 7–12](https://github.com/yearningss/exteraGram-docs/blob/341db43686bfb3212e1ecf3cddcc8b8fcfd885f3/docs/plugins-and-sdk.md#L7-L12); [architecture, строки 21–28](https://github.com/yearningss/exteraGram-docs/blob/341db43686bfb3212e1ecf3cddcc8b8fcfd885f3/docs/architecture.md#L21-L28)). Не названы сигнатуры функции переключения потока, правила синхронизации, background executor и доступность UI context; это нельзя превращать в гарантию thread-safety любого Android API.

`docs/exterahook.md` заявляет раннюю инициализацию через `ExteraHookInitProvider` до `Application.onCreate()`, затем вызовы `JniBridgeBindings.unsealHiddenApi()` и `disableArtProfileSaver()` ([exterahook, строки 7–21](https://github.com/yearningss/exteraGram-docs/blob/341db43686bfb3212e1ecf3cddcc8b8fcfd885f3/docs/exterahook.md#L7-L21)). В том же документе Xposed-подобный `XC_MethodHook.MethodHookParam` имеет `method`, `thisObject`, `args`, `result`, `throwable`, `setResult()` и `setThrowable()`; `beforeHookedMethod` меняет аргументы или подавляет оригинал через `setResult`, а `afterHookedMethod` преобразует результат; для Python заявлен callback через `hook_utils` ([exterahook, строки 23–64](https://github.com/yearningss/exteraGram-docs/blob/341db43686bfb3212e1ecf3cddcc8b8fcfd885f3/docs/exterahook.md#L23-L64)). Это утверждения документа, а не подтверждённый манифестом/JNI/ART кодом runtime. Типовой stub подтверждает лишь наличие Xposed-style деклараций и методов `hook_method`/`hook_all_methods`/`unhook_method`, но не внутренности `dev.exterahook` или `hook_utils`; точные сигнатуры Python `hook_utils` в этом репозитории не приведены.

### API, UI, данные и сеть

Для host UI руководство отдельно перечисляет `PluginsActivity` с закреплением установленных расширений и переходами в настройки/сведения, `PluginsInfoActivity` с полями требований к Elyx SDK и встроенным `PluginFileViewer`, а также принудительный Hot Reload и удаление. Это действия, описанные для интерфейса клиента, не публичные вызовы SDK ([ui-screens, строки 192–207](https://github.com/yearningss/exteraGram-docs/blob/341db43686bfb3212e1ecf3cddcc8b8fcfd885f3/docs/ui-screens.md#L192-L207)). Полный список относящихся к разработке настроек плагинного движка включает `pluginsEngine`, `pluginsSafeMode`, `pluginsUnknownSources`, `pluginsDevMode`, `pluginsCompactView`, `pluginsDisableArtOpts`, `pluginsPySdkAutoUpdate`, `pluginsPySdkBetaVersions`, `pinnedPlugins` и `sdkUpdateScheduleTimestamp`; доступ к ним из кода плагина в этом source не описан ([settings-reference, строки 157–170](https://github.com/yearningss/exteraGram-docs/blob/341db43686bfb3212e1ecf3cddcc8b8fcfd885f3/docs/settings-reference.md#L157-L170)).

Список модулей, заявленных для Elyx: `base_plugin.BasePlugin`, `hook_utils`, `client_utils`, `file_utils`, `plugin_settings`, `ui.alert`, `ui.bulletin`, `ui.settings`, `extera_utils`, `dev_server`. Назначение `client_utils` описано как доступ к `AccountInstance`, `UserConfig`, `MessagesController`; точные функции, аргументы, выбор активного аккаунта и thread/account routing отсутствуют ([plugins-and-sdk, строки 86–101](https://github.com/yearningss/exteraGram-docs/blob/341db43686bfb3212e1ecf3cddcc8b8fcfd885f3/docs/plugins-and-sdk.md#L86-L101)). Нет здесь ни API тредов форума, ни метода получения текущего чата/аккаунта, ни примера отправки запроса. Не подменять этими названиями контракт из другого SDK-снимка.

Для UI документы называют alert/bulletin и custom RecyclerView settings cells, однако не приводят вызываемые сигнатуры этих модулей ([plugins-and-sdk, строки 90–101](https://github.com/yearningss/exteraGram-docs/blob/341db43686bfb3212e1ecf3cddcc8b8fcfd885f3/docs/plugins-and-sdk.md#L90-L101)). Экран плагинов описывает перечисленные выше host-side controls, а не публичные вызовы SDK ([ui-screens, строки 192–207](https://github.com/yearningss/exteraGram-docs/blob/341db43686bfb3212e1ecf3cddcc8b8fcfd885f3/docs/ui-screens.md#L192-L207)).

Под `PipController` заявлена изолированная установка PyPI-пакетов в каталог данных приложения; перечислены `requests`, `urllib3`, Pillow, lxml, BeautifulSoup, PyYAML и debugpy с версиями ([plugins-and-sdk, строки 105–115](https://github.com/yearningss/exteraGram-docs/blob/341db43686bfb3212e1ecf3/docs/plugins-and-sdk.md#L105-L115)). Здесь нет ABI/Android wheel-совместимости, политики источников, lock-файла, удаления пакета или API вызова контроллера. Не считать перечисление гарантированным содержимым другой сборки.

Сеть клиента описана как HTTPS REST JSON к `api.exteragram.app/api/v1/`, с «заголовками клиентской сессии» и User ID; названы endpoints профилей, дифференциального обновления, now-playing и Boosty. Ответы, согласно тексту, попадают в Room `ExteraDatabase` schema v5, а периодический `SyncWorker` использует WorkManager и ETag/If-None-Match, с остановкой опросов при неактивном приложении ([backend-and-sync, строки 7–62](https://github.com/yearningss/exteraGram-docs/blob/341db43686bfb3212e1ecf3cddcc8b8fcfd885f3/docs/backend-and-sync.md#L7-L62)). Серверная auth-схема не раскрыта, поэтому описание не является безопасным рецептом аутентификации для стороннего плагина. Room schema клиента не следует путать с persistent storage отдельного плагина.

Другая часть сети — AI-модуль: `AiController` заявлен как управляющий очередью/контекстом, HTTP-клиент как async с SSE; перечислены Gemini, OpenAI, OpenRouter и произвольный совместимый API, а в UI есть действия над сообщениями, черновиком и Instant View ([ai-integration, строки 7–48](https://github.com/yearningss/exteraGram-docs/blob/341db43686bfb3212e1ecf3cddcc8b8fcfd885f3/docs/ai-integration.md#L7-L48)). Это функция самого клиента, не API для плагина; в источнике нет network-client SDK или auth-посредника. Указанные в файле конкретные модели могут устаревать.

### Storage, UI и вспомогательные пользовательские потоки

Справочник `ExteraConfig` заявляет 146 настроек, реактивные `BasePref` и хранение app settings в `SharedPreferences` (`exteraconfig.xml`) ([settings-reference, строки 1–3](https://github.com/yearningss/exteraGram-docs/blob/341db43686bfb3212e1ecf3cddcc8b8fcfd885f3/docs/settings-reference.md#L1-L3)). `file_utils` отдельно описан лишь общими словами, как безопасный доступ к cache/user files; точной директории и границ namespace плагина документация не раскрывает. Не использовать app `SharedPreferences` как доказательство plugin storage contract.

Среди пригодных примеров Android UI есть экспорт чатов в HTML/JSON в папку через Storage Access Framework `OPEN_DOCUMENT_TREE`; камера использует Camera 1/2/CameraX, QR UI использует `ACTION_WIFI_SETTINGS`/`ACTION_SEND`, а меню описывает действия с сообщениями ([ui-screens, строки 95–137, 177–182](https://github.com/yearningss/exteraGram-docs/blob/341db43686bfb3212e1ecf3cddcc8b8fcfd885f3/docs/ui-screens.md#L95-L137); [dialogs-and-features, строки 35–41, 73–89](https://github.com/yearningss/exteraGram-docs/blob/341db43686bfb3212e1ecf3cddcc8b8fcfd885f3/docs/dialogs-and-features.md#L35-L41)). Это примеры поведения хост-приложения, а не опубликованные методы SDK.

Стеганографическая backup-функция заявляет сериализацию полной конфигурации в символы нулевой ширины, AES-GCM-256, PBKDF2 и ссылку `t.me/exteraSettings`; после распознавания открывается окно сравнения/применения настроек ([steganography-and-backup, строки 7–42](https://github.com/yearningss/exteraGram-docs/blob/341db43686bfb3212e1ecf3cddcc8b8fcfd885f3/docs/steganography-and-backup.md#L7-L42)). Нет параметров derivation, nonce format, кодека payload и test vectors; не использовать как криптографическую спецификацию или API хранилища плагина.

## Практические выводы

1. Для проектирования плагина используйте страницу как карту модулей и возможностей, но lifecycle/API берите из конкретного установленного SDK и перепроверяйте целевую сборку: `on_load` в тексте расходится с доступным `BasePlugin` stub. Не переносьте эту разницу молча.
2. Учитывайте только версию, указанную для целевой сборки: `12.10.1 / 70389` и Elyx `1.4.5.5` относятся к описанному автором образцу. Общая совместимость или политика минимальных версий этим snapshot не установлена.
3. Для многопоточности требуйте явного переключения на UI thread для операций Android UI, пока SDK не докажет обратное. Описание общего JNI synchronization не задаёт контракты конкретных функций.
4. Не используйте перечисленные backend routes, Room tables и AI endpoints как API плагина: документы описывают внутренности клиента. В частности, не извлекайте формат аутентификации по фразе «client-session headers and User ID».
5. Перед использованием `.elyx/.eaf`, `metainfo.yml`, `refmap.yml`, resource facade, `PipController` или debug server подтвердите поддержку в целевом SDK; в данном репозитории отсутствуют loader и исполняемый пример.

## Пробелы и противоречия

- Встроенные sample callbacks (`on_load`/`on_unload`) противоречат доступным SDK декларациям и другим документации SDK (`on_plugin_load`/`on_plugin_unload`). Пока не известно, ошибка ли это текста, устаревший alias или другой runtime contract.
- Версии в источнике непоследовательны: Elyx 1.4.5.5 против собственного single-file `__min_sdk__ = "1.4.0"`; отдельная документация официального SDK говорит о baseline 1.4.4.3.
- Нет исходников целевого APK и его манифеста, тестов, lock/build/CI, версии ExteraHook, changelog, release tags или runtime logs. Утверждения об API 28–36, раннем ContentProvider, hidden-API bypass, профилях ART и семантике хуков не подтверждены исходниками.
- Нет точных плагиновых функций для текущего чата, текущего аккаунта, thread/forum topic, отправки запросов, storage namespace, settings persistence, UI thread dispatch или регистрации callback. Сам факт перечисления `AccountInstance` не определяет многопользовательский lifecycle.
- Детали endpoint auth, Room schema/DAO, backend policies и технические параметры AES-GCM/PBKDF2 не раскрыты.
- `radar-urls.json` пуст; дополнительные исторические ссылки отсутствуют. Repository metadata не содержит license.
- Разделы перечисляют модели Gemini/OpenAI без временной пометки свежести; названия и параметры API могли измениться относительно даты снимка.
- Ни один факт не имеет статуса `runtime-verified`.
