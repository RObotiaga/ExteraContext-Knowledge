## Роль и границы покрытия

Полезная сторона этого клиента для ExteraGram — примеры конкретных изменений Telegram-кода на стыке локального состояния, UI и сетевых запросов. Ни один найденный внутренний класс Mercurygram не является ExteraGram plugin API. Локальные папки и дополнительные закрепления особенно показательны как клиентские фичи, но в виде обычного плагина потребовали бы перехватывать несколько глубоко связанных путей.

## Технические факты

### Локальные папки и синхронизация

Клиент представляет локальную папку обычным `DialogFilter` с отрицательным ID; серверные папки занимают положительные ID от 2, а `-1` зарезервирован UI как placeholder. Новый локальный ID выбирается случайно в диапазоне не меньше `-2`, чтобы два устройства могли независимо создать папку до синхронизации. При переносе папки между локальным и серверным пространством тот же объект получает новый ID: старая storage-запись и ключ карты фильтров удаляются до сохранения нового ключа, затем обновляется порядок. Это клиентская стратегия, а не обман сервера и не новый Telegram API. [Код: `MgFolders.java`](https://github.com/Mercurygram/Mercurygram/blob/1c103ff74bad9fe954d099a9fd4d0f45ba2e99c4/TMessagesProj/src/main/java/it/belloworld/mercurygram/folders/MgFolders.java#L65-L120)

Сетевой барьер централизован в `ConnectionsManager.sendRequestInternal`: helper удаляет отрицательные IDs из запроса порядка; попытку `messages.updateDialogFilter` для локальной папки он не отправляет и вызывает callback с пустыми `response/error`, чтобы caller прошёл success path. Поэтому одного UI hook для папок недостаточно: клиент перехватывает общий путь отправки запроса. [Код: `ConnectionsManager.java`](https://github.com/Mercurygram/Mercurygram/blob/1c103ff74bad9fe954d099a9fd4d0f45ba2e99c4/TMessagesProj/src/main/java/org/telegram/tgnet/ConnectionsManager.java#L389-L390), [helper](https://github.com/Mercurygram/Mercurygram/blob/1c103ff74bad9fe954d099a9fd4d0f45ba2e99c4/TMessagesProj/src/main/java/it/belloworld/mercurygram/folders/MgFolders.java#L160-L180)

Папки синхронизируются внутри Saved Messages одним редактируемым JSON-документом `mercurygram-folders.json`, помеченным `#mercurygram_folders`; сервер Telegram хранит его как сообщение-файл. Клиент подписан на account-scoped `dialogFiltersUpdated` и события новых/заменённых сообщений, ищет документ при первом запуске sync и извлекает изменения из Saved Messages. [Код](https://github.com/Mercurygram/Mercurygram/blob/1c103ff74bad9fe954d099a9fd4d0f45ba2e99c4/TMessagesProj/src/main/java/it/belloworld/mercurygram/folders/MgFolderSync.java#L28-L52) и [регистрация observer](https://github.com/Mercurygram/Mercurygram/blob/1c103ff74bad9fe954d099a9fd4d0f45ba2e99c4/TMessagesProj/src/main/java/it/belloworld/mercurygram/folders/MgFolderSync.java#L90-L96)

После локального изменения отправка откладывается на 3 секунды; повторное изменение отменяет предыдущую задачу. Первая синхронизация сначала ищет облачный документ, а при первом применении более новой копии сохраняет локальные Mercurygram-папки, созданные до появления sync, и загружает их объединение с cloud-набором. Если состояние сериализации совпадает с уже отправленным, повторной загрузки нет. Ошибка upload повторяется только после следующего изменения папок или следующего запуска. [Код и lifecycle](https://github.com/Mercurygram/Mercurygram/blob/1c103ff74bad9fe954d099a9fd4d0f45ba2e99c4/TMessagesProj/src/main/java/it/belloworld/mercurygram/folders/MgFolderSync.java#L28-L47), [первый merge](https://github.com/Mercurygram/Mercurygram/blob/1c103ff74bad9fe954d099a9fd4d0f45ba2e99c4/TMessagesProj/src/main/java/it/belloworld/mercurygram/folders/MgFolderSync.java#L289-L350), [debounce](https://github.com/Mercurygram/Mercurygram/blob/1c103ff74bad9fe954d099a9fd4d0f45ba2e99c4/TMessagesProj/src/main/java/it/belloworld/mercurygram/folders/MgFolderSync.java#L363-L365), [push](https://github.com/Mercurygram/Mercurygram/blob/1c103ff74bad9fe954d099a9fd4d0f45ba2e99c4/TMessagesProj/src/main/java/it/belloworld/mercurygram/folders/MgFolderSync.java#L368-L450)

При обычном конфликте более новый `updated` заменяет список Mercurygram-папок целиком, а равное время считается уже применённым состоянием; merge содержимого папок нет. Первый sync — исключение: старые локальные папки сохраняются. Существующий порядок папок не синхронизируется и сам по себе не отправляется; новые папки добавляются в конец. Writer выбирает `max(serverTime, previousUpdated + 1)`, сохраняя монотонность локальных записей. [Код применения](https://github.com/Mercurygram/Mercurygram/blob/1c103ff74bad9fe954d099a9fd4d0f45ba2e99c4/TMessagesProj/src/main/java/it/belloworld/mercurygram/folders/MgFolderSync.java#L289-L350), [timestamp](https://github.com/Mercurygram/Mercurygram/blob/1c103ff74bad9fe954d099a9fd4d0f45ba2e99c4/TMessagesProj/src/main/java/it/belloworld/mercurygram/folders/MgFolderSync.java#L383-L416)

Wire-format спецификация фиксирует `format=mercurygram-folders`, `version=1`, отрицательные IDs не больше `-2`, поля include/exclude/pinned, Unicode custom-emoji offsets как UTF-16 units и decimal string для document IDs. Секретные чаты в документ не кодируются, а существующие локальные secret-chat entries переносятся при применении cloud snapshot. Документ также предупреждает о whole-document LWW и коллизиях ID между одновременно редактируемыми устройствами. [Документация `MercurygramFolders.md`](https://github.com/Mercurygram/Mercurygram/blob/1c103ff74bad9fe954d099a9fd4d0f45ba2e99c4/MercurygramFolders.md#L23-L91), [перенос secret chats](https://github.com/Mercurygram/Mercurygram/blob/1c103ff74bad9fe954d099a9fd4d0f45ba2e99c4/TMessagesProj/src/main/java/it/belloworld/mercurygram/folders/MgFolderSync.java#L312-L339)

Sync ограничивает загружаемый blob 4 MiB, поскольку файл с нужным именем может добавить любой участник Saved Messages. Тесты проверяют round-trip/canonical JSON, перенос иконки, неверные entity ranges, совместимость более старого документа, исключение secret chats и отказ от серверных/reserved IDs; это test code, не результат запуска в этом задании. [Код](https://github.com/Mercurygram/Mercurygram/blob/1c103ff74bad9fe954d099a9fd4d0f45ba2e99c4/TMessagesProj/src/main/java/it/belloworld/mercurygram/folders/MgFolderSync.java#L50-L56), [тесты](https://github.com/Mercurygram/Mercurygram/blob/1c103ff74bad9fe954d099a9fd4d0f45ba2e99c4/TMessagesProj_AppTests/src/androidTest/kotlin/it/belloworld/mercurygram/folders/MgFolderSyncTest.kt#L41-L121)

### Local Pins, typed search и composer

Для списка All Chats Mercurygram хранит полный упорядоченный список pin IDs в `UserConfig.mg.mainPins`, восстанавливает `pinned/pinnedNum` перед сортировкой и сохраняет изменение порядка после drag. Вместимость берётся из лимита папок, тогда как передаваемый серверу предел читается отдельно из Telegram config; значит, локальный список может быть шире сетевого. README заявляет лимит в 100 и описывает остаток как локальный. [Код](https://github.com/Mercurygram/Mercurygram/blob/1c103ff74bad9fe954d099a9fd4d0f45ba2e99c4/TMessagesProj/src/main/java/it/belloworld/mercurygram/MgPins.java#L39-L53), [persist/apply](https://github.com/Mercurygram/Mercurygram/blob/1c103ff74bad9fe954d099a9fd4d0f45ba2e99c4/TMessagesProj/src/main/java/it/belloworld/mercurygram/MgPins.java#L62-L105), [повторное применение перед сортировкой](https://github.com/Mercurygram/Mercurygram/blob/1c103ff74bad9fe954d099a9fd4d0f45ba2e99c4/TMessagesProj/src/main/java/org/telegram/messenger/MessagesController.java#L22454-L22458), [README](https://github.com/Mercurygram/Mercurygram/blob/1c103ff74bad9fe954d099a9fd4d0f45ba2e99c4/README.md#L83-L83)

README фиксирует межустройственный компромисс: сервер получает лишь первые допустимые pins, поэтому другие клиенты видят этот поднабор; локальные дополнительные pins сохраняются, но если чат был откреплён на другом устройстве, пока это устройство было долго offline, здесь pin может остаться до явного unpin. [README](https://github.com/Mercurygram/Mercurygram/blob/1c103ff74bad9fe954d099a9fd4d0f45ba2e99c4/README.md#L83-L83). `MgPinsTest` проверяет восстановление очищенных сервером pins, принятие неизвестных pin IDs, archive row и идемпотентность функции применения. [Тесты](https://github.com/Mercurygram/Mercurygram/blob/1c103ff74bad9fe954d099a9fd4d0f45ba2e99c4/TMessagesProj_AppTests/src/androidTest/kotlin/it/belloworld/mercurygram/MgPinsTest.kt#L36-L91)

Typed search парсит `from:`, `before:`, `after:`, `date:` и один `type:`-оператор; принимаются даты `YYYY-MM-DD`, `today`, `yesterday` и список типов из реализации. Ошибочный или неизвестный токен остаётся в тексте запроса, чтобы не расширять молча поиск, например при неразрешённом username. `from:` резолвится через локальный `MessagesController`, если он предоставлен. [Парсер и контракты](https://github.com/Mercurygram/Mercurygram/blob/1c103ff74bad9fe954d099a9fd4d0f45ba2e99c4/TMessagesProj/src/main/java/it/belloworld/mercurygram/search/MgSearchQuery.java#L14-L38), [parse](https://github.com/Mercurygram/Mercurygram/blob/1c103ff74bad9fe954d099a9fd4d0f45ba2e99c4/TMessagesProj/src/main/java/it/belloworld/mercurygram/search/MgSearchQuery.java#L60-L145)

Дни интерпретируются в системном часовом поясе устройства от локальной полуночи; `date:D` задаёт однодневный диапазон, `after` и `before` меняют min/max date запроса. `applyTo(TL_messages_search)` пишет filter/from_id/min_date/max_date в обычную структуру Telegram запроса, а не фильтрует загруженную историю локально. В call site parser вызывается лишь для пользовательского in-chat query; затем поля накладываются на оба пути `messages.search`. Source test покрывает обычный текст, типы, регистр, локальные даты, literal fallback, повторный ключ и passthrough hashtag; тест не запускался. [Парсер и дата](https://github.com/Mercurygram/Mercurygram/blob/1c103ff74bad9fe954d099a9fd4d0f45ba2e99c4/TMessagesProj/src/main/java/it/belloworld/mercurygram/search/MgSearchQuery.java#L90-L167), [applyTo](https://github.com/Mercurygram/Mercurygram/blob/1c103ff74bad9fe954d099a9fd4d0f45ba2e99c4/TMessagesProj/src/main/java/it/belloworld/mercurygram/search/MgSearchQuery.java#L212-L231), [call site](https://github.com/Mercurygram/Mercurygram/blob/1c103ff74bad9fe954d099a9fd4d0f45ba2e99c4/TMessagesProj/src/main/java/org/telegram/messenger/MediaDataController.java#L3855-L3861), [request](https://github.com/Mercurygram/Mercurygram/blob/1c103ff74bad9fe954d099a9fd4d0f45ba2e99c4/TMessagesProj/src/main/java/org/telegram/messenger/MediaDataController.java#L4037-L4055), [test source](https://github.com/Mercurygram/Mercurygram/blob/1c103ff74bad9fe954d099a9fd4d0f45ba2e99c4/TMessagesProj_AppTests/src/androidTest/kotlin/it/belloworld/mercurygram/MgSearchQueryTest.kt#L19-L124)

При включённой опции обычный непустой draft остаётся в локальном `saveDraft`; `allowsCloudSync` пропускает его в сетевой `messages.saveDraft` только когда облачная синхронизация включена. ### Push watchdog и Unicode Fold

Push watchdog регистрирует `AlarmManager.setInexactRepeating`: интервал один час с endpoint и 15 минут без endpoint. Alarm намеренно неточный; комментарии коду указывают, что Doze может отложить его до следующего maintenance window. [Код](https://github.com/Mercurygram/Mercurygram/blob/1c103ff74bad9fe954d099a9fd4d0f45ba2e99c4/TMessagesProj/src/main/java/it/belloworld/mercurygram/push/MgPushWatchdog.java#L30-L80)

Обработчик watchdog вызывает `ensureRegistered` и проверку тишины; при отсутствии любой отметки доставки полные сутки он запрашивает новый endpoint. AppStartReceiver обрабатывает watchdog action отдельно, а boot/app-update путь восстанавливает alarm. Это системные receiver/service и push registration, поэтому они глубже обычного плагинного UI hook. [Watchdog](https://github.com/Mercurygram/Mercurygram/blob/1c103ff74bad9fe954d099a9fd4d0f45ba2e99c4/TMessagesProj/src/main/java/it/belloworld/mercurygram/push/MgPushWatchdog.java#L88-L176), [receiver](https://github.com/Mercurygram/Mercurygram/blob/1c103ff74bad9fe954d099a9fd4d0f45ba2e99c4/TMessagesProj/src/main/java/org/telegram/messenger/AppStartReceiver.java#L37-L70), [manifest](https://github.com/Mercurygram/Mercurygram/blob/1c103ff74bad9fe954d099a9fd4d0f45ba2e99c4/TMessagesProj/src/main/AndroidManifest.xml#L1-L20)

`MgUnicodeFold.fold(String)` нормализует декорированные Unicode-символы для локального поиска; `LocaleController.getTranslitString` применяет её до штатной transliteration, кроме пути `onlyEnglish` (Passport case-preserving path). Радары описывали применение к диалогам, контактам и picker-спискам, но здесь непосредственно проверен центральный LocaleController seam, а не каждый downstream call site. [Алгоритм](https://github.com/Mercurygram/Mercurygram/blob/1c103ff74bad9fe954d099a9fd4d0f45ba2e99c4/TMessagesProj/src/main/java/it/belloworld/mercurygram/MgUnicodeFold.java#L342-L364), [integration seam](https://github.com/Mercurygram/Mercurygram/blob/1c103ff74bad9fe954d099a9fd4d0f45ba2e99c4/TMessagesProj/src/main/java/org/telegram/messenger/LocaleController.java#L3293-L3307)

### Стыки, сборка и практические оговорки

Отдельный `TMessagesProj_PluginTor` — companion APK клиента, который общается с main APK через bound Android service/AIDL; это не модель ExteraGram plug-in. AIDL описывает callback registration, idempotent `start`, `stop`, idle-stop и транспортные параметры. Новые методы добавляются в конец AIDL: порядок определяет transaction codes; комментарий требует синхронно повышать минимальную версию plugin, поскольку старый plugin не знает нового вызова. [AIDL контракт](https://github.com/Mercurygram/Mercurygram/blob/1c103ff74bad9fe954d099a9fd4d0f45ba2e99c4/TMessagesProj/src/main/aidl/it/belloworld/mercurygram/plugin/tor/IMgTorService.aidl#L6-L83)

Main app проверяет наличие установленного companion plugin отдельно от connected/available state; Binder связывается на worker handler через package-explicit `bindService`. Статические проверки описывают также подпись/версию и ограничения bind на pre-Android 12 F-Droid build. Эти механизмы помогают понять межпроцессную интеграцию Mercurygram, но переносить их в обычный plugin без собственных разрешений и доверенной подписи нельзя. [availability](https://github.com/Mercurygram/Mercurygram/blob/1c103ff74bad9fe954d099a9fd4d0f45ba2e99c4/TMessagesProj/src/main/java/it/belloworld/mercurygram/tor/MgTorClient.java#L610-L654), [binding](https://github.com/Mercurygram/Mercurygram/blob/1c103ff74bad9fe954d099a9fd4d0f45ba2e99c4/TMessagesProj/src/main/java/it/belloworld/mercurygram/tor/MgTorClient.java#L1298-L1349)

README явно говорит, что сборка на Windows не поддерживается. Документированы Android SDK, JDK 17, закреплённый NDK, native prerequisites и команды `assembleAfatRelease` / `assembleAfatFd*Release`; Gradle pin в snapshot — NDK `27.2.12479018`. Сборка в этом задании не запускалась. [README prerequisites/build](https://github.com/Mercurygram/Mercurygram/blob/1c103ff74bad9fe954d099a9fd4d0f45ba2e99c4/README.md#L346-L373), [NDK pin](https://github.com/Mercurygram/Mercurygram/blob/1c103ff74bad9fe954d099a9fd4d0f45ba2e99c4/TMessagesProj/build.gradle#L150-L151)

Документация разделяет стабильный `X.Y.Z.M`, snapshot `X.Y.Z.M.K` и pre-stable `X.Y.Z.0.K`; четвёртый компонент участвует в Android versionCode как revision slot. Это release/build схема конкретного репозитория, не общая версия Telegram. [README](https://github.com/Mercurygram/Mercurygram/blob/1c103ff74bad9fe954d099a9fd4d0f45ba2e99c4/README.md#L330-L336), [Gradle](https://github.com/Mercurygram/Mercurygram/blob/1c103ff74bad9fe954d099a9fd4d0f45ba2e99c4/gradle/mg-version.gradle#L14-L19)

Это repository workflow, не runtime API. ## Практические приёмы для плагинных исследований

- Для composer tweaks сначала найдите место, где клиент уже вычислил правильную длину и состояние лимита; здесь это `afterTextChanged`, `Character.codePointCount`, `MgCharCounter.update`. Повторный собственный счёт UTF-16 даст расхождение для supplementary characters.
- Для typed-search-like функции сохраняйте неизвестные/невалидные токены как обычный текст и добавляйте фильтры в существующие поля запроса. Это уменьшает риск молча расширить выборку и не требует локально выгружать историю. Повторить это в ExteraGram можно только если доступны соответствующие DEX/hooks; Mercurygram не подтверждает наличие такого API у ExteraGram.
- Локальные папки показывают обязательность сетевого барьера в общем request path, персистентного локального ID пространства и явного wire format для sync. Это архитектурный образец, но не обещание низкой сложности портирования.
- Push watchdog и Tor companion опираются на manifest, Android system callbacks, bound services, signature permissions и процессный lifecycle. Радар правильно относит watchdog к глубоким изменениям клиента; обёртка UI-плагина сама по себе этих контрактов не воспроизводит.
- Для папок/пинов описывайте владельца состояния и конфликт при синхронизации до начала переноса. README честно указывает, что дополнительные pins остаются device-local; folder sync применяет LWW со специальным первым merge, не переносит порядок существующих папок и сохраняет локальные secret-chat entries.

## Ограничения и несоответствия радара

- Coverage — целевой срез выбранных фич и интеграционных точек. Не читался весь Telegram upstream, остальные Mercurygram-подсистемы, весь README до каждой пользовательской функции и все исторические изменения этих классов.
- В закреплённом tree нет `TMessagesProj_AppTests/.../MgCharCounterTest.kt`; целевой acquisition URL вернул 404. Для счётчика разобраны код вызова и виджет, но отдельного source test не найдено.
- Сетевые эффекты оператора поиска не проверялись против сервера; статически подтверждено только заполнение TL-запроса. Измерение watchdog на реальном Android не проводилось; фактический интервал может быть длиннее заявленного из-за Doze.
- Радар говорит, что локальные папки исключены из Telegram Premium limits. Код подтверждает классификацию отрицательных IDs и отдельную обработку server limits, но в этой странице это не считается независимым измерением серверного лимита.
- Mercurygram folders sync и local pins не дают автоматического merge между параллельными устройствами: folder sync заменяет весь набор по timestamp, а offline unpin может восстановиться локально. Эти ограничения являются частью наблюдаемой стратегии, не случайным обещанием синхронизации.
- Документированные NDK/JDK/Gradle команды относятся только к этому snapshot; приложение, CI и runtime не запускались. На устройстве не проверялись settings, push, folder sync, search, Tor IPC или rendering counter.
- Mercurygram Tor Plugin — companion APK с собственным AIDL и trust relationship. Не считать это аналогом API загрузки Python/DEX-плагинов ExteraGram.
- Остальные функции, явно отмеченные радаром, остаются за пределами этого проверенного среза: Unicode Fold для контактов/picker call sites кроме центрального `LocaleController` seam, отключение proximity sensor, full-resolution photo crop, локальные/privacy-ссылки (tracking cleanup, подтверждение `t.me`/`tg://`, Instant View), защита пользовательских ringtone URI, качество/quality variants видео, оптимизации больших аккаунтов и новые account/navigation-настройки (default folder/free reorder). Они приведены радаром, но не были проверены по pinned реализации в этой ревизии; для технических решений это остаточные gaps, не подтвержденные утверждения страницы.
