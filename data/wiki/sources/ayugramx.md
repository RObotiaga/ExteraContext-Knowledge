## Подтверждённые технические факты

### Локальная модель и пресеты

`Data::ChatFilter` несёт ID, title, emoji, необязательный цвет, флаги, списки исключений `always`/`never` и упорядоченный `pinned`; локальные и cloud filters живут в одном списке `Data::ChatFilters` ([объявление](https://github.com/Kratapand26/AyugramX/blob/e61bc31e0d06b4a92d39845e4031d90bf3fd34ff/Telegram/SourceFiles/data/data_chat_filters.h#L39-L112), [контейнер](https://github.com/Kratapand26/AyugramX/blob/e61bc31e0d06b4a92d39845e4031d90bf3fd34ff/Telegram/SourceFiles/data/data_chat_filters.h#L190-L260)). Все эти C++-типы относятся к desktop-клиенту.

Клиент резервирует ID `1001–1009` для девяти готовых категорий: users, groups, channels, bots, unread, admin, supergroups, basic groups и unmuted; `1000` является базой локального диапазона, а ID пользовательских локальных папок начинаются с `1100`. `IsLocalFilterId(id)` классифицирует любой ID от `1000` ([data_chat_filters.h](https://github.com/Kratapand26/AyugramX/blob/e61bc31e0d06b4a92d39845e4031d90bf3fd34ff/Telegram/SourceFiles/data/data_chat_filters.h#L35-L55)). Это внутренняя схема AyugramX, не переносимый plugin contract.

`createPresetFilter` строит готовые категории из флагов `ChatFilter`: unread объединяет типы контактов, группы, каналы и ботов с `NoRead|NoArchived`; unmuted использует те же типы с `NoMuted|NoArchived`; отдельные категории ставят свои типовые флаги и исключают архив ([реализация](https://github.com/Kratapand26/AyugramX/blob/e61bc31e0d06b4a92d39845e4031d90bf3fd34ff/Telegram/SourceFiles/data/data_chat_filters.cpp#L629-L726)). Хорошая переносимая идея — задавать пресет как декларативное сочетание типа чата и state-фильтров, а локальный ID/сохранение реализовать отдельно под целевой host.

Проверка членства реализует приоритет исключений: `never` отклоняет чат первым; сообщества не попадают по обычному типу и допускаются только через `always`; для остальных тип/права проверяются вместе с `NoMuted`, `NoRead`, `NoArchived`, после чего явное включение `always` может добавить чат ([`ChatFilter::contains`](https://github.com/Kratapand26/AyugramX/blob/e61bc31e0d06b4a92d39845e4031d90bf3fd34ff/Telegram/SourceFiles/data/data_chat_filters.cpp#L365-L439)). При переносе правила в plugin стоит явно определить порядок allow/deny исключений и специальные peer-типы, а не полагаться только на наборы категорий.

### Включение, сохранение и восстановление

Настройки локальных папок принадлежат аккаунту: методы `AyuSettings` принимают Telegram `userId`; JSON-объект `localFolders` индексируется строковым представлением ID пользователя и содержит `presets`, `customs`, `order` ([объявления](https://github.com/Kratapand26/AyugramX/blob/e61bc31e0d06b4a92d39845e4031d90bf3fd34ff/Telegram/SourceFiles/ayu/ayu_settings.h#L386-L402), [кодирование](https://github.com/Kratapand26/AyugramX/blob/e61bc31e0d06b4a92d39845e4031d90bf3fd34ff/Telegram/SourceFiles/ayu/ayu_settings.cpp#L1325-L1362), [декодирование](https://github.com/Kratapand26/AyugramX/blob/e61bc31e0d06b4a92d39845e4031d90bf3fd34ff/Telegram/SourceFiles/ayu/ayu_settings.cpp#L1495-L1546)). Setter-методы вызывают `save()`. Это пример разделения пользовательского состояния по аккаунту; детали Android plugin storage из него не следуют.

Секция `Quick Local Folders` создаёт checkbox для всех девяти presets. Начальное значение берётся из `AyuSettings::localFolderPresetEnabled(userId, preset)`, а последующие изменения направляются в `ChatFilters::toggleLocalPreset(preset, checked)` ([settings_folders.cpp](https://github.com/Kratapand26/AyugramX/blob/e61bc31e0d06b4a92d39845e4031d90bf3fd34ff/Telegram/SourceFiles/settings/sections/settings_folders.cpp#L1066-L1105)). Сам `toggleLocalPreset` сохраняет account-scoped enabled state и добавляет/удаляет соответствующий локальный filter в памяти; в этом call-site переключатель не отправляет MTProto-запрос ([data_chat_filters.cpp](https://github.com/Kratapand26/AyugramX/blob/e61bc31e0d06b4a92d39845e4031d90bf3fd34ff/Telegram/SourceFiles/data/data_chat_filters.cpp#L729-L780)).

Пользовательский `LocalCustomFolder` хранит `id`, title, emoji, optional color, flags и ID peer-наборов `always`, `pinned`, `never` ([структура](https://github.com/Kratapand26/AyugramX/blob/e61bc31e0d06b4a92d39845e4031d90bf3fd34ff/Telegram/SourceFiles/ayu/ayu_settings.h#L33-L42)). `saveLocalFolder` переводит ссылки `History*` в peer IDs, сохраняет запись в `AyuSettings` и обновляет модель фильтров ([реализация](https://github.com/Kratapand26/AyugramX/blob/e61bc31e0d06b4a92d39845e4031d90bf3fd34ff/Telegram/SourceFiles/data/data_chat_filters.cpp#L791-L825)). Это полезный образец для сериализации локального набора фильтра, но не рекомендует использовать Desktop peer IDs в другой платформе без проверки формата и области жизни.

Создание локальной папки в settings вызывает `nextLocalCustomId()`, открывает `EditFilterBox` с новым `ChatFilter`, а callback сохраняет результат через `saveLocalFolder` и добавляет/обновляет UI-строку ([settings_folders.cpp](https://github.com/Kratapand26/AyugramX/blob/e61bc31e0d06b4a92d39845e4031d90bf3fd34ff/Telegram/SourceFiles/settings/sections/settings_folders.cpp#L601-L631)). Следующий свободный пользовательский ID выбирается с `1100` вверх по текущему `_list` ([data_chat_filters.cpp](https://github.com/Kratapand26/AyugramX/blob/e61bc31e0d06b4a92d39845e4031d90bf3fd34ff/Telegram/SourceFiles/data/data_chat_filters.cpp#L783-L789)).

Общий `EditFilterBox` используется и для локальных, и для облачных папок, но сохранение расходится по ownership: в `EditExistingFilter` local ID ведёт к `saveLocalFolder()` и раннему возврату, тогда как cloud filter обновляет session model и отправляет `messages.updateDialogFilter` ([edit_filter_box.cpp](https://github.com/Kratapand26/AyugramX/blob/e61bc31e0d06b4a92d39845e4031d90bf3fd34ff/Telegram/SourceFiles/boxes/filters/edit_filter_box.cpp#L1143-L1195)). Это подтверждает локальный persistence path для существующей папки; полный UI editor и его chatlist-link flow здесь не описывается.

При инициализации `ChatFilters` на главном executor клиента сначала вызывается `applyLocalFilters()`, затем `load()` серверных папок ([конструктор](https://github.com/Kratapand26/AyugramX/blob/e61bc31e0d06b4a92d39845e4031d90bf3fd34ff/Telegram/SourceFiles/data/data_chat_filters.cpp#L441-L449)). Локальные фильтры добавляются в ту же модель, а `received()` при обновлении cloud list временно сохраняет local entries и возвращает их после обработки серверного набора, затем применяет локальные настройки повторно ([восстановление](https://github.com/Kratapand26/AyugramX/blob/e61bc31e0d06b4a92d39845e4031d90bf3fd34ff/Telegram/SourceFiles/data/data_chat_filters.cpp#L877-L955), [слияние с ответом сервера](https://github.com/Kratapand26/AyugramX/blob/e61bc31e0d06b4a92d39845e4031d90bf3fd34ff/Telegram/SourceFiles/data/data_chat_filters.cpp#L957-L1019)). Практический приём: разделять локальный и серверный источник данных, затем явно повторно объединять local state после полной перезагрузки cloud list.

Полный порядок папок сохраняется локально по аккаунту и применяется к общей модели; перед `messages.updateDialogFiltersOrder` из него отфильтровываются локальные ID. В серверный MTProto вызов отправляются только cloud IDs ([`saveOrder`](https://github.com/Kratapand26/AyugramX/blob/e61bc31e0d06b4a92d39845e4031d90bf3fd34ff/Telegram/SourceFiles/data/data_chat_filters.cpp#L1379-L1413)). При удалении локального ID пользовательская папка стирается из настроек, а preset также выключается; запись удаляется из модели ([`deleteLocalFolder`](https://github.com/Kratapand26/AyugramX/blob/e61bc31e0d06b4a92d39845e4031d90bf3fd34ff/Telegram/SourceFiles/data/data_chat_filters.cpp#L827-L857)).

### Дополнительные seams клиента

В `ChatFilter::FromTL` клиент накладывает сохранённые локально color/icon overrides, если сервер не вернул цвет или если фильтр является shared chatlist; комментарий связывает это с non-Premium ограничением и отказом сервера менять shared folder ([data_chat_filters.cpp](https://github.com/Kratapand26/AyugramX/blob/e61bc31e0d06b4a92d39845e4031d90bf3fd34ff/Telegram/SourceFiles/data/data_chat_filters.cpp#L187-L207)). UI сохранения дополнительно пишет локальный цвет для non-premium/shared folders ([settings_folders.cpp](https://github.com/Kratapand26/AyugramX/blob/e61bc31e0d06b4a92d39845e4031d90bf3fd34ff/Telegram/SourceFiles/settings/sections/settings_folders.cpp#L704-L715)). Это client-specific workaround; нельзя считать локальный override официальной серверной возможностью.

`Data::Folder` в другом слое — специальная dialogs-list entry, имеющая `Dialogs::MainList`, обновления unread/full-size через RPL и кешируемые последние чаты; одноимённость не означает, что этот класс реализует пользовательские filter folders ([data_folder.h](https://github.com/Kratapand26/AyugramX/blob/e61bc31e0d06b4a92d39845e4031d90bf3fd34ff/Telegram/SourceFiles/data/data_folder.h#L20-L84), [конструктор](https://github.com/Kratapand26/AyugramX/blob/e61bc31e0d06b4a92d39845e4031d90bf3fd34ff/Telegram/SourceFiles/data/data_folder.cpp#L117-L150)). Не переносите эту внутреннюю модель в plugin API только на основании названия.

## Приёмы для автора плагина

1. Для «умных папок» опишите категории декларативно (тип чата, unread/muted/archive flags), а ручные include/exclude и pinned peer IDs храните отдельно. До реализации зафиксируйте порядок применения `never`, `always` и особых peer types.
2. Если состояние зависит от вошедшей учётной записи, ключуйте настройки по устойчивому account ID и восстанавливайте локальные записи при смене/повторной загрузке session. Не смешивайте его с серверной сущностью без нужды.
3. При совместном списке серверных и локальных элементов сохраняйте local entries перед заменой cloud snapshot и снова объединяйте их после ответа сервера. Для порядка отправляйте серверу только те элементы, которыми сервер владеет.
4. Рассматривайте checkbox presets как пресеты-фильтры, а не как бесконтрольное создание папок при каждом клике: детерминированный локальный ID делает повторное включение идемпотентным; для пользовательских папок отдельно выдавайте свободный ID.
5. Для ExteraGram Android реализуйте эти идеи средствами подтверждённого SDK конкретной версии. `AyuSettings`, `Data::ChatFilters`, `History*`, `Session`, Qt/RPL и MTProto call-sites из этого репозитория — C++/Qt seams desktop-клиента, не host API для Python/DEX plugins.

## Радар и пробелы

Радар называет AyugramX источником идеи «локальные папки + быстрые пресеты» и отмечает, что это Desktop-направление, не Android Plugin SDK (`raw/ayugramx/radar-context.md:35-54`, исходные строки 1415–1435). Снимок кода подтверждает локальные custom folders и UI Quick Local Folders с девятью переключаемыми preset-категориями. Схема `Local Folder + Quick Presets + Saved Messages Sync + Smart Rules` — предложение радара для будущего ExteraGram-плагина: в исследованных файлах AyugramX нет подтверждения Saved Messages sync или Smart Rules.
