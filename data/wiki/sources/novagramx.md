# NovagramX (`ferelking242/novagramx`)

Снимок исходного кода закреплён на `dev`, commit [`5fc9938a74d2a27a639b6b2a837606886f4b4c13`](https://github.com/ferelking242/novagramx/commit/5fc9938a74d2a27a639b6b2a837606886f4b4c13), сохранён 2026-09-27. Это большой Android-клиентный форк NagramX, который README описывает как основанный на Nekogram и AyuGram. Источник полезен как референс реализации встроенных функций клиента — прежде всего regex-фильтра сообщений, локального last-seen и настройки Ghost Mode. Это не ExteraGram SDK, не Python-плагин и не документированный runtime-контракт для внешних расширений.

## Роль, доказательства и границы

В радаре NovagramX назван донором готовых Java/Kotlin-реализаций; идеи «Message Firewall» и переноса в DEX/плагин — предложения автора радара, а не API проекта. Исходники показывают клиентские точки интеграции в `ChatActivity`, `ProfileActivity` и `MessagesController`. Чтобы повторить такую интеграцию внешним плагином, понадобилась бы совместимая точка hook/runtime, которую данный репозиторий не описывает.

Идентичность сверена с `raw/novagramx/snapshot.json` и полным (`tree_truncated: false`) `raw/novagramx/tree.json`: ниже ссылки указывают на этот SHA, а не на подвижную ветку. При этом `raw/novagramx/radar-context.md` содержит пустой список `[]`, `radar-urls.json` тоже пуст; отдельные записи радара находятся в `raw/radar-export-text.md`. Исторических URL коммитов в source-specific radar metadata нет. Следовательно, сравнение радара здесь означает сверку сохранённых общих формулировок с текущим закреплённым снимком; отдельный исторический код радара проверить не удалось.

Изучены README, workflow сборки и выбранные связанные участки реализации regex-фильтров, блок-листов, last-seen и Ghost Mode, включая перехват исходящих запросов. Репозиторий огромен и содержит upstream Telegram/медиакод; всё дерево построчно не изучалось. Build workflow прочитан статически, сборка не запускалась. Ни поведение приложения, ни совместимость ExteraGram на устройстве не проверялись; `runtime-verified` утверждений нет. README также перечисляет LLM, транскрипцию голоса, UnifiedPush, локальную историю удалённых/изменённых сообщений и иконки; эти функции не входят в зафиксированный радаром срез и для них здесь подтверждены только заявления README, не реализация.

## Реализация regex-фильтров

`AyuFilter` — основной фасад этой функции. Общие фильтры — это `FilterModel(regex, caseInsensitive, enabled)`; фильтры диалога хранятся отдельно как `ChatFilterEntry(dialogId, filters)`. Конфиги `RegexFiltersData`, `RegexChatFiltersData`, `RegexFiltersExcludedDialogs` и глобальный флаг объявлены в `NaConfig`; модели сериализуются через Gson в конфиг клиента, а не в отдельную БД ([`AyuFilter.java`, строки 31–94 и 226–265](https://github.com/ferelking242/novagramx/blob/5fc9938a74d2a27a639b6b2a837606886f4b4c13/TMessagesProj/src/main/java/tw/nekomimi/nekogram/filters/AyuFilter.java#L31-L94), [`NaConfig.kt`, строки 405–431](https://github.com/ferelking242/novagramx/blob/5fc9938a74d2a27a639b6b2a837606886f4b4c13/TMessagesProj/src/main/kotlin/xyz/nextalone/nagram/NaConfig.kt#L405-L431)). При чтении модели компилируют Java `Pattern` с `MULTILINE`, при выбранном флаге добавляют `CASE_INSENSITIVE`; `matcher(text).find()` ищет совпадение-подстроку, а не требует полного совпадения текста ([`AyuFilter.java`, строки 674–713](https://github.com/ferelking242/novagramx/blob/5fc9938a74d2a27a639b6b2a837606886f4b4c13/TMessagesProj/src/main/java/tw/nekomimi/nekogram/filters/AyuFilter.java#L674-L713)). Ошибка компиляции при загрузке превращает pattern в `null` и пишет в `FileLog`; UI-редактор запрещает пустой ввод и показывает `PatternSyntaxException`, но import path десериализует и сохраняет правило без отдельного отклонения некорректного regex. Следовательно, imported/старое значение доходит до runtime-compilation и может стать null pattern ([`RegexFilterEditActivity.java`, строки 129–161](https://github.com/ferelking242/novagramx/blob/5fc9938a74d2a27a639b6b2a837606886f4b4c13/TMessagesProj/src/main/java/tw/nekomimi/nekogram/filters/RegexFilterEditActivity.java#L129-L161), [`RegexFiltersSettingActivity.java`, строки 200–352](https://github.com/ferelking242/novagramx/blob/5fc9938a74d2a27a639b6b2a837606886f4b4c13/TMessagesProj/src/main/java/tw/nekomimi/nekogram/filters/RegexFiltersSettingActivity.java#L200-L352)). Для стороннего инструмента импорта это означает: не полагаться только на UI-валидацию — повреждённое persisted-значение может стать неработающим правилом.

`AyuFilter.isFiltered(MessageObject msg, MessageObject.GroupedMessages group)` возвращает `false`, если общий `RegexFiltersEnabled` выключен, сообщение `null` или исходящее. До regex нормализуется полный текст сообщения; исключены sticker/animated-sticker/emoji-типы, пустой текст, сообщения только из emoji, переведённый и restricted-контент. Затем проверяется список исключённых диалогов. Это важные границы полноты: фильтр не равен firewall над всеми типами событий/медиа ([`AyuFilter.java`, строки 105–119 и 175–223](https://github.com/ferelking242/novagramx/blob/5fc9938a74d2a27a639b6b2a837606886f4b4c13/TMessagesProj/src/main/java/tw/nekomimi/nekogram/filters/AyuFilter.java#L105-L119)).

Правила для конкретного диалога проверяются первыми. После них приватные диалоги (`dialogId > 0`) возвращаются без общих правил, если `RegexFiltersEnableInChats` выключен; следовательно, отдельные chat-scoped правила могут срабатывать и при выключенной настройке общих правил для приватных чатов, но общий master-флаг всё равно должен быть включён. Для обоих видов правил совпадение любого включённого regex достаточно для `true` ([`AyuFilter.java`, строки 137–173 и 175–200](https://github.com/ferelking242/novagramx/blob/5fc9938a74d2a27a639b6b2a837606886f4b4c13/TMessagesProj/src/main/java/tw/nekomimi/nekogram/filters/AyuFilter.java#L137-L200)).

Результаты кешируются по `dialogId` и `messageId` в отдельных LRU-кешах ёмкостью 1000 записей на диалог; для альбомной группы результат копируется в записи всех её элементов. Сохранение/редактирование правил очищает модельный и результатный кеш. Для правки сообщения есть отдельный `onMessageEdited(msgId, dialogId)`, который удаляет только его запись ([`AyuFilter.java`, строки 31–39, 90–94, 122–135, 201–224 и 505–512](https://github.com/ferelking242/novagramx/blob/5fc9938a74d2a27a639b6b2a837606886f4b4c13/TMessagesProj/src/main/java/tw/nekomimi/nekogram/filters/AyuFilter.java#L31-L39)). При переносе важно подключить invalidation к собственной редакции/обновлению сообщения; иначе кеш может пережить изменение текста.

Call sites подтверждают, что это фильтрация в рендерере списка сообщений: `ChatActivity` возвращает sentinel `-1000` для совпавшей позиции и пропускает скрытые совпадения при поиске разделителя непрочитанного. Reply-sender block проверяется отдельно. В профиле есть пункт открытия per-chat списка и popup исключения для текущего диалога ([`ChatActivity.java`, строки 38854–38879](https://github.com/ferelking242/novagramx/blob/5fc9938a74d2a27a639b6b2a837606886f4b4c13/TMessagesProj/src/main/java/org/telegram/ui/ChatActivity.java#L38854-L38879), [`ProfileActivity.java`, строки 2661 и 12669–12680](https://github.com/ferelking242/novagramx/blob/5fc9938a74d2a27a639b6b2a837606886f4b4c13/TMessagesProj/src/main/java/org/telegram/ui/ProfileActivity.java#L2661)). Это не универсальная точка перехвата отправки/приёма; поведение с другими поверхностями UI из выбранных call sites не следует.

Управление фильтрами включает общие и per-chat списки, включение/отключение записей, проверку синтаксиса, очистку. Экран настроек экспортирует в clipboard Gson JSON и импортирует с merge по паре `(regex, caseInsensitive)`; при повторе обновляет `enabled`, а новые записи добавляет. Там же переносит custom-filtered users и blocked channels. Формат — внутренняя структура `TransferData`, не заявленный внешний стабильный API ([`RegexFiltersSettingActivity.java`, строки 200–352](https://github.com/ferelking242/novagramx/blob/5fc9938a74d2a27a639b6b2a837606886f4b4c13/TMessagesProj/src/main/java/tw/nekomimi/nekogram/filters/RegexFiltersSettingActivity.java#L200-L352)).

### Блокировка каналов и пользователей

В `AyuFilter` есть отдельные от regex множества blocked channel dialog IDs и custom-filtered user IDs. Каналы принимаются и сохраняются как отрицательные dialog IDs, пользовательские ID — положительные; пользовательская запись также может сохранять `accessHash`, username и displayName. Проверки `isBlockedChannel`/`isCustomFilteredPeer` зависят от `NekoConfig.ignoreBlocked` ([`AyuFilter.java`, строки 391–478 и 514–673](https://github.com/ferelking242/novagramx/blob/5fc9938a74d2a27a639b6b2a837606886f4b4c13/TMessagesProj/src/main/java/tw/nekomimi/nekogram/filters/AyuFilter.java#L391-L478)). В `ChatActivity` блок канала участвует в скрытии сообщения, а `MessagesController` пропускает custom-filtered user при обработке соответствующего blocked-peer списка ([`ChatActivity.java`, строки 38844–38879](https://github.com/ferelking242/novagramx/blob/5fc9938a74d2a27a639b6b2a837606886f4b4c13/TMessagesProj/src/main/java/org/telegram/ui/ChatActivity.java#L38844-L38879), [`MessagesController.java`, строки 11020–11034](https://github.com/ferelking242/novagramx/blob/5fc9938a74d2a27a639b6b2a837606886f4b4c13/TMessagesProj/src/main/java/org/telegram/messenger/MessagesController.java#L11020-L11034)). Это другой механизм, чем правило regex и его per-dialog exclusion.

## Локальная история last-seen

Схема `LastSeenEntity` — Room-строка `(userId PRIMARY KEY, lastSeen int)`, DAO умеет прочитать все строки, удалить значения старше cutoff и заменить пачку. Ayu database version 26 добавляет таблицу миграцией 25→26; очередь `lastSeenQueue` — один фоновый `DispatchQueue` с приоритетом `THREAD_PRIORITY_BACKGROUND` ([`LastSeenEntity.java`, строки 5–9](https://github.com/ferelking242/novagramx/blob/5fc9938a74d2a27a639b6b2a837606886f4b4c13/TMessagesProj/src/main/java/com/radolyn/ayugram/database/entities/LastSeenEntity.java#L5-L9), [`LastSeenDao.java`, строки 12–22](https://github.com/ferelking242/novagramx/blob/5fc9938a74d2a27a639b6b2a837606886f4b4c13/TMessagesProj/src/main/java/com/radolyn/ayugram/database/dao/LastSeenDao.java#L12-L22), [`AyuData.java`, строки 88–112](https://github.com/ferelking242/novagramx/blob/5fc9938a74d2a27a639b6b2a837606886f4b4c13/TMessagesProj/src/main/java/com/radolyn/ayugram/database/AyuData.java#L88-L112), [`AyuQueues.java`, строки 7–12](https://github.com/ferelking242/novagramx/blob/5fc9938a74d2a27a639b6b2a837606886f4b4c13/TMessagesProj/src/main/java/com/radolyn/ayugram/utils/AyuQueues.java#L7-L12)).

`LastSeenHelper.preload()` при включённом `SaveLocalLastSeen` чистит записи старше семи дней и заполняет статический in-memory cache. `saveLastSeen(userId, timestamp)` игнорирует выключенную настройку/неположительный timestamp, не заменяет более позднее значение более ранним и ставит отложенную запись. Pending значений сбрасывается пачкой не чаще одного раза на 5 секунд; при исключении/недоступности DAO значения requeue-ятся. Выключение функции очищает pending; cache не очищается этим путём, но getter при выключенном флаге возвращает `0` ([`LastSeenHelper.java`, строки 19–156](https://github.com/ferelking242/novagramx/blob/5fc9938a74d2a27a639b6b2a837606886f4b4c13/TMessagesProj/src/main/java/com/radolyn/ayugram/utils/LastSeenHelper.java#L19-L156)).

Данные берутся из нескольких локально наблюдаемых источников: при получении offline user status; из загруженных сообщений профиля/диалога (самое позднее сообщение автора); из дат peer reactions, включая recent reactions в сообщениях и updates контроллера. Вызовы встречаются в `MessagesController` и `ChatActivity` ([`MessagesController.java`, строки 6814–6817 и 18994–18995](https://github.com/ferelking242/novagramx/blob/5fc9938a74d2a27a639b6b2a837606886f4b4c13/TMessagesProj/src/main/java/org/telegram/messenger/MessagesController.java#L6814-L6817), [`LastSeenHelper.java`, строки 217–263](https://github.com/ferelking242/novagramx/blob/5fc9938a74d2a27a639b6b2a837606886f4b4c13/TMessagesProj/src/main/java/com/radolyn/ayugram/utils/LastSeenHelper.java#L217-L263), [`ChatActivity.java`, строки 40668 и 43006](https://github.com/ferelking242/novagramx/blob/5fc9938a74d2a27a639b6b2a837606886f4b4c13/TMessagesProj/src/main/java/org/telegram/ui/ChatActivity.java#L40668)). Поэтому README-ярлык «last seen tracking» нельзя истолковывать как полный server-side журнал присутствия: реализация накапливает наибольшую увиденную дату из доступных клиенту сигналов. Helper предоставляет `getFormattedLastSeenOrDefault`, но в проверенных `UserCell` и `ProfileActivity` его вызов не найден; где результат отображается, осталось не подтверждено.

## Ghost Mode и passcode: расхождение документации с кодом

`GhostModeActivity` показывает переключатели для read receipts сообщений/историй, online, upload progress и offline-after-online. Long-press конкретного переключателя меняет его соответствующий `...Locked` config и disables/enables строку; guard `getGhostModeLockedCount() >= 4` ограничивает число блокируемых параметров четырьмя, хотя строк пять ([`GhostModeActivity.java`, строки 161–195 и 217–224](https://github.com/ferelking242/novagramx/blob/5fc9938a74d2a27a639b6b2a837606886f4b4c13/TMessagesProj/src/main/java/tw/nekomimi/nekogram/settings/GhostModeActivity.java#L161-L195)). В изученном обработчике нет вызова `PasscodeHelper`. Между тем README говорит «lockable behind the passcode» ([README, строки 18–22](https://github.com/ferelking242/novagramx/blob/5fc9938a74d2a27a639b6b2a837606886f4b4c13/README.md#L18-L22)); это заявление документации, которое данным UI-кодом не подтверждено. Отдельный `PasscodeHelper` хранит настройки per-account passcode и сравнивает SHA-256 от salt+passcode+salt, однако связь этого механизма с per-toggle lock из inspected code не установлена ([`PasscodeHelper.java`, строки 18–67 и 98–118](https://github.com/ferelking242/novagramx/blob/5fc9938a74d2a27a639b6b2a837606886f4b4c13/TMessagesProj/src/main/java/tw/nekomimi/nekogram/helpers/PasscodeHelper.java#L18-L67)). Не переносить предположение о password gate как подтверждённый контракт.

## Сборка, диагностика и практическое применение

README предлагает получить Telegram API credentials, создать `local.properties` с `TELEGRAM_APP_ID`, `TELEGRAM_APP_HASH` и параметрами подписи, заменить `TMessagesProj/release.keystore`, затем запускать `./gradlew TMessagesProj:assembleStaging` либо открыть проект Android Studio ([README, строки 52–73](https://github.com/ferelking242/novagramx/blob/5fc9938a74d2a27a639b6b2a837606886f4b4c13/README.md#L52-L73)). Опциональный FCM требует собственного `google-services.json`. Staging workflow использует JDK 21, Android API 36, NDK 27.2.12479018, Build Tools 36.0.0 и `arm64-v8a`, затем загружает APK как artifact; push запускается для `dev`, но paths-ignore исключает Markdown и `.github/**`, кроме самого staging workflow ([`staging.yml`, строки 3–36, 41–45 и 102–135](https://github.com/ferelking242/novagramx/blob/5fc9938a74d2a27a639b6b2a837606886f4b4c13/.github/workflows/staging.yml#L3-L36)). Следовательно, формулировка README «на каждый push» имеет оговорки по фильтру путей. Canary build также ориентирован на arm64 и умеет отдельно пропустить upload по dispatch input/commit marker ([`canary.yml`, строки 1–19 и 30–40](https://github.com/ferelking242/novagramx/blob/5fc9938a74d2a27a639b6b2a837606886f4b4c13/.github/workflows/canary.yml#L1-L19)). Здесь изучалась конфигурация, не фактический CI run.

**Рецепт для разработчика плагина:** использовать AyuFilter как источник алгоритма/модели, извлечь минимальную логику `text → compiled patterns → allow/hide`, отдельно спроектировать storage и lifecycle плагина, а точки поиска `ChatActivity` рассматривать как привязанные к этой версии клиента. Для локального last-seen сохранять лишь timestamp, реально наблюдавшийся на клиенте, сворачивать повторные записи, ограничивать срок хранения и чётко описывать какие события его питают. Репозиторий не доказывает наличие ExteraGram hook API, через который эти Java call sites доступны Python-плагину.

## Дополнительная точка вмешательства: Ghost Mode в исходящих запросах

Ghost Mode даёт полезную для анализа сетевую точку интеграции: `ConnectionsManager.sendRequestInternal(TLObject, ...)` вызывает `AyuGhostUtils.interceptRequest(...)` до сериализации outbound-запроса. Результат — `InterceptResult(blockRequest, effectiveOnComplete)`; при блокировке sender прекращает обработку, при пропуске callback может быть заменён. Метод распознаёт Telegram TL-типы: read-history/content/views и story-read запросы можно блокировать; для read-запроса подставляется synthetic `TL_messages_affectedMessages`, чтобы вызывающая цепочка получила completion. Typing requests блокируются при выключенном `sendUploadProgress`, online status request переписывается в `offline=true`, а callback отправки сообщения оборачивается с запросом offline через 1 секунду. Это внутренняя точка клиента перед сетевой сериализацией, не публичный plugin API ([`ConnectionsManager.java`, строки 380–397](https://github.com/ferelking242/novagramx/blob/5fc9938a74d2a27a639b6b2a837606886f4b4c13/TMessagesProj/src/main/java/org/telegram/tgnet/ConnectionsManager.java#L380-L397), [`AyuGhostUtils.java`, строки 140–187 и 259–304](https://github.com/ferelking242/novagramx/blob/5fc9938a74d2a27a639b6b2a837606886f4b4c13/TMessagesProj/src/main/java/com/radolyn/ayugram/utils/AyuGhostUtils.java#L140-L187)).

Read- и typing-исключения хранятся per-dialog независимо: `AyuGhostPreferences` использует ключи `ghostModeReadExclusion_<abs(chatId)>` и `ghostModeTypingExclusion_<abs(chatId)>` в Neko preferences и `ConcurrentHashMap` как кеш. Оба типа обрабатываются до решения GhostMode. При переносе следует учитывать, что для этих ключей знак dialog ID схлопывается через `abs()` ([`AyuGhostPreferences.java`, строки 7–36](https://github.com/ferelking242/novagramx/blob/5fc9938a74d2a27a639b6b2a837606886f4b4c13/TMessagesProj/src/main/java/com/radolyn/ayugram/utils/AyuGhostPreferences.java#L7-L36), [`AyuGhostUtils.java`, строки 147–173](https://github.com/ferelking242/novagramx/blob/5fc9938a74d2a27a639b6b2a837606886f4b4c13/TMessagesProj/src/main/java/com/radolyn/ayugram/utils/AyuGhostUtils.java#L147-L173)).
