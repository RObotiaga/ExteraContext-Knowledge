## Роль и границы источника

Это крошечный пример Python-плагина с последовательностью «перехват точной команды → сетевой запрос за IP и геоданными → диалог или bulletin». В нём есть call-sites для `BasePlugin`, hook отправки сообщения, передачи callback helper-у `run_on_ui_thread`, `AlertDialogBuilder` и `BulletinHelper`. Это код одного плагина, не документация и не реализация host API: имена и контракты ExteraGram здесь показаны только в употреблении.

Файл задаёт `__id__ = "iptag"`, имя `IP Tag`, описание «По команде .iptag сразу показывает окно загрузки, затем — твой IPv4 и примерное местоположение», версию `1.5.0`, минимальное приложение `>=12.5.1` и автора `@Ensureyou` ([`iptag.py`, строки 12–17](https://github.com/wsp2ch/iptag-plugin-Exteragramm-/blob/5fcd2df5465e25b7316ac1cf750a2e976c2dd62e/iptag.py#L12-L17)). Это метаданные исходника, а не проверка совместимости или наблюдение UI. README заявляет, что команда `.iptag` показывает IP во всплывающем окне и что плагин проверяли с включёнными плагинами; такое описание не подтверждает runtime-проверку этого снимка ([`README.md`, строки 1–6](https://github.com/wsp2ch/iptag-plugin-Exteragramm-/blob/5fcd2df5465e25b7316ac1cf750a2e976c2dd62e/README.md#L1-L6)). В сохранённом коде реализация дополнительно делает геозапросы; README их не описывает.

## Реализация

`fetch_ipv4()` делает `requests.get("https://api.ipify.org?format=json", timeout=5)` и читает `r.json()["ip"]`; комментарий исходника утверждает, что сервис возвращает только IPv4 ([`iptag.py`, строки 20–23](https://github.com/wsp2ch/iptag-plugin-Exteragramm-/blob/5fcd2df5465e25b7316ac1cf750a2e976c2dd62e/iptag.py#L20-L23)). Код не проверяет HTTP status до разбора JSON и не валидирует формат адреса: он полагается на контракт сервиса/комментарий и поле `ip`. `fetch_location(ip)` по очереди пробует `ipwho.is/{ip}` и `ipapi.co/{ip}/json/`, с таймаутом 4 секунды на запрос ([строки 26–35](https://github.com/wsp2ch/iptag-plugin-Exteragramm-/blob/5fcd2df5465e25b7316ac1cf750a2e/iptag.py#L26-L35)). Для ipwho результат с явным `success: false` пропускается; далее извлекаются `city`, `region`, `country` и `connection.isp`. Для второго провайдера извлекаются `city`, `region`, `country_name`, `org` ([строки 37–50](https://github.com/wsp2ch/iptag-plugin-Exteragramm-/blob/5fcd2df5465e25b7316ac1cf750a2e/iptag.py#L37-L50)). Исключение при запросе или JSON parsing логируется и запускает следующую попытку; если обе попытки не дали tuple, функция возвращает четыре `None` ([строки 51–55](https://github.com/wsp2ch/iptag-plugin-Exteragramm-/blob/5fcd2df5465e25b7316ac1cf750a2e/iptag.py#L51-L55)).

У fallback есть важная граница: при корректном JSON без `success: false` функция сразу возвращает поля, даже если все они пусты; для ipapi поле `error` отдельно не проверяется. Следовательно, переход ко второму сервису происходит при исключении или отрицательном `success` ipwho, но не просто при неполном ответе первого сервиса. `fetch_ip_info()` ловит ошибку получения IPv4 и включает текст исключения в результат; после успеха собирает непустые город, регион и страну через запятую, иначе выводит «неизвестно», а провайдера добавляет только при наличии ([строки 58–73](https://github.com/wsp2ch/iptag-plugin-Exteragramm-/blob/5fcd2df5465e25b7316ac1cf750a2e976c2dd62e/iptag.py#L58-L73)).

При `on_plugin_load()` регистрируется `add_on_send_message_hook()`. Hook берёт `params.message` через `getattr`, принимает только строку, затем сравнивает `message_text.strip()` с точной строкой `.iptag`; регистр не нормализуется и дополнительных аргументов быть не должно ([строки 76–97](https://github.com/wsp2ch/iptag-plugin-Exteragramm-/blob/5fcd2df5465e25b7316ac1cf750a2e976c2dd62e/iptag.py#L76-L97)). При совпадении он передаёт показ загрузчика helper-у с именем `run_on_ui_thread`, стартует daemon `threading.Thread` для получения данных и возвращает `HookResult(strategy=HookStrategy.CANCEL)`. Это call-site и намерение отмены; реализация и семантика host helper/hook в этом репозитории отсутствуют, а фактическая отмена отправки не проверялась. Остальные сообщения и ранние ошибки возвращают пустой `HookResult()`; если ошибка возникает после распознавания команды, fallback hook потенциально пропускает `.iptag` дальше, поскольку исключение обработано возвратом по умолчанию.

Загрузчик и финальный экран строятся с `get_last_fragment()` и `fragment.getParentActivity()`. Если activity нет, spinner не создаётся. Иначе показывается некликабельный spinner-диалог, ссылка на builder хранится в `self._loading_builder` ([строки 99–120](https://github.com/wsp2ch/iptag-plugin-Exteragramm-/blob/5fcd2df5465e25b7316ac1cf750a2e976c2dd62e/iptag.py#L99-L120)). Worker получает итоговую строку и передаёт callback `_render_result` helper-у `run_on_ui_thread`; код полагается на его имя, реализация helper здесь отсутствует. Метод сначала скрывает spinner, заново ищет fragment/activity, затем показывает диалог с кнопкой `OK`; без activity использует `BulletinHelper.show_info(info, fragment)`. Исключения рендеринга пишутся в log и приводят к попытке `BulletinHelper.show_error(...)` ([строки 122–148](https://github.com/wsp2ch/iptag-plugin-Exteragramm-/blob/5fcd2df5465e25b7316ac1cf750a2e976c2dd62e/iptag.py#L122-L148)).

При этом `_fetch_and_render()` не оборачивает `fetch_ip_info()` и постановку callback в общий `try/finally`: неожиданное исключение может завершить worker до `_render_result`, поэтому spinner не будет закрыт этим путём ([`iptag.py`, строки 122–124](https://github.com/wsp2ch/iptag-plugin-Exteragramm-/blob/5fcd2df5465e25b7316ac1cf750a2e976c2dd62e/iptag.py#L122-L124)). В классе нет `on_plugin_unload()`, отмены/ожидания worker или cleanup выполняющейся операции. Значит, отложенный callback потенциально может обратиться к UI после выгрузки; это вывод по отсутствию cleanup, не runtime-проверка ([`iptag.py`, строки 76–148](https://github.com/wsp2ch/iptag-plugin-Exteragramm-/blob/5fcd2df5465e25b7316ac1cf750a2e976c2dd62e/iptag.py#L76-L148)).

## Внешние данные, ограничения и безопасное применение

Код отправляет HTTP-запрос к ipify, а полученный IP включает в URL геолокационного провайдера. Практическое следствие кода: внешний адрес, видимый сервису ipify, и адрес, переданный сервису геолокации, выходят за пределы приложения. Какой именно адрес возвращается, зависит от маршрута/VPN/proxy/сетевого выхода; это вывод из модели удалённого HTTP-запроса, а не проверенный здесь сетевой захват. Геоданные представлены провайдером по IP и в UI подписаны как местоположение; точность адреса/геолокации и сроки хранения сервисами источником не установлены.

В репозитории нет пользовательского подтверждения передачи IP, настроек провайдера, кеширования, отмены запроса, rate-limit или тестов ошибок. Сетевые таймауты ограничивают ожидание каждого запроса, но код не показывает отдельный общий deadline для обеих геопровайдерных попыток. Вызов `requests` здесь происходит в daemon thread, поэтому он не занимает UI thread по показанной логике; это структурное свойство кода, не результат измерения отзывчивости приложения. Не проверялись разрешения host-приложения, доступность `requests`, API-совместимость версий клиента, состояние UI при выгрузке плагина и фактическое поведение dialog/bulletin.

Радар называл проект «минимальным примером» команды → HTTP → popup и отмечал дату создания 7 сентября 2026; это вторичный контекст, не доказательство функции. Дата репозитория в GitHub metadata — 2026-09-07T04:18:33Z; commit и tree этого снимка закреплены отдельно. Радар не заменяет проверку README/кода и несколько упрощает поведение, опуская геолокацию и fallback-диалог ([локальный radar context, строки 33–43](../../raw/iptag/radar-context.md#L33-L43)).

## Практический рецепт, который действительно следует из кода

Для небольшого event-driven plugin action этот источник демонстрирует форму: зарегистрировать message hook при plugin load; защитить доступ к параметру и проверить команду; вернуть `HookResult` со стратегией `CANCEL` только для совпавшей команды (фактический host-контракт требуется проверять отдельно); делать блокирующий HTTP в daemon worker; передавать UI callback helper-у `run_on_ui_thread`; при сетевой ошибке вернуть отображаемый текст. Переносить нужно только наблюдаемую структуру. Имена Host API и UI builder зависят от установленной документации/SDK и здесь не гарантируются; рецепт не является проверенным шаблоном совместимости. Для функций, передающих пользовательский IP третьим лицам, нужно заранее явно объяснить эту передачу и проверить актуальные privacy/terms провайдеров.
