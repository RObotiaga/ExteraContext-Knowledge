# RObotiaga/exteragram-plugin-template

Источник: [репозиторий GitHub](https://github.com/RObotiaga/exteragram-plugin-template), fork шаблона ExteraGram с Python/BasePlugin frontend и Kotlin/DEX backend. Зафиксированный commit: [`bbf44de36e16c360a3f5afcbc99bc331ac52ebb9`](https://github.com/RObotiaga/exteragram-plugin-template/tree/bbf44de36e16c360a3f5afcbc99bc331ac52ebb9), ветка `master`, снимок получен 2026-09-27. Лицензия — MIT ([LICENSE](https://github.com/RObotiaga/exteragram-plugin-template/blob/bbf44de36e16c360a3f5afcbc99bc331ac52ebb9/LICENSE#L1-L20)). В радаре это именно рабочий Kotlin/DEX/EAF-шаблон и практический workflow, а не набор новых общих API; радар упоминает связку шаблона с внешним `extera-gradle-plugin` как привлекательный toolchain, но это вторичная оценка и не описание содержимого данного репозитория ([контекст радара, исходные строки 742–750](../../raw/template-robotiaga/radar-context.md#L30-L39)). Зафиксированный `build.gradle.kts` реализует собственный Android/Gradle/D8 pipeline.

Все ссылки на исходники ниже закреплены за этим SHA. Источник содержит рабочую реализацию упаковки и JVM-моста, образцы Python/Kotlin кода, CI и большую авторскую документацию-навык. Документационные описания SDK/Elyx считаются `docs`, а не независимым подтверждением текущего SDK: сам skill задаёт приоритет живой официальной документации и точного APK над сторонним конспектом ([00-source-priority.md](https://github.com/RObotiaga/exteragram-plugin-template/blob/bbf44de36e16c360a3f5afcbc99bc331ac52ebb9/skills/exteragram-eaf-template/references/00-source-priority.md#L6-L64)). Runtime проверки в рамках ingest не выполнялись.

## Устройство и важные факты

### EAF и смешанная архитектура

Основной продукт — structured `.eaf` ZIP: в корне лежат `refmap.yml`, `metainfo.yml`, `main.py`, каталоги `assets/` и `src/`; `plugin_src/` становится `src/`. Kotlin компилируется отдельно, а release DEX добавляется как бинарный `assets/classes.dex`. EAF-путь сохраняет `main.py` исходником, без DEX hex; `assets/classes.dex` зарезервирован и должен поступать из Gradle output ([README, строки 17–38, 52–81](https://github.com/RObotiaga/exteragram-plugin-template/blob/bbf44de36e16c360a3f5afcbc99bc331ac52ebb9/README.md#L17-L38), [build_eaf.py, строки 134–206](https://github.com/RObotiaga/exteragram-plugin-template/blob/bbf44de36e16c360a3f5afcbc99bc331ac52ebb9/tools/build_eaf.py#L134-L206)). Пакер явно добавляет ZIP directory entries `src/` и `assets/`, проверяет их directory semantics, запрещает дубликаты и небезопасные пути, сравнивает DEX с входными байтами, проверяет ZIP и записывает результат через временный файл ([build_eaf.py, строки 92–131, 186–242](https://github.com/RObotiaga/exteragram-plugin-template/blob/bbf44de36e16c360a3f5afcbc99bc331ac52ebb9/tools/build_eaf.py#L92-L131)).

Structured `metainfo.id` ограничен 2–32 ASCII буквами/цифрами/underscore; дефис запрещён. `just init` использует ещё более узкое пересечение с legacy metadata: ID должен начинаться с буквы. CI синхронно сверяет Python `__id__`, Elyx `id`, Python/metadata/pyproject версии; автора намеренно разрешает менять ([build_eaf.py, строки 22–65](https://github.com/RObotiaga/exteragram-plugin-template/blob/bbf44de36e16c360a3f5afcbc99bc331ac52ebb9/tools/build_eaf.py#L22-L65), [ci.yml, проверка metadata](https://github.com/RObotiaga/exteragram-plugin-template/blob/bbf44de36e16c360a3f5afcbc99bc331ac52ebb9/.github/workflows/ci.yml#L30-L79), [justfile, init](https://github.com/RObotiaga/exteragram-plugin-template/blob/bbf44de36e16c360a3f5afcbc99bc331ac52ebb9/justfile#L97-L176)).

README говорит, что Elyx может запускать `main.py` без `__file__`, и описывает `file_utils.get_plugins_dir()` как главный способ найти установленный каталог. В Python-коде это реализовано через кандидаты от `__file__`, импортированного `get_plugins_dir()`, `ElyxPlugins/<id>` и `<plugins-dir>/<id>`, с legacy embedded fallback ([Python bridge, строки 156–211, 213–275](https://github.com/RObotiaga/exteragram-plugin-template/blob/bbf44de36e16c360a3f5afcbc99bc331ac52ebb9/exteragram-plugin-template.py#L156-L211)). Это приватное знание runtime-пути внутри шаблона, а не общий Elyx API; для иных плагинов в skill предлагается публичный Elyx assets facade ([02-elyx-eaf.md, строки 157–182](https://github.com/RObotiaga/exteragram-plugin-template/blob/bbf44de36e16c360a3f5afcbc99bc331ac52ebb9/skills/exteragram-eaf-template/references/02-elyx-eaf.md#L157-L182)).

### Python → JVM bridge и lifecycle

`JvmPluginBridge.load()` читает DEX, проверяет `dex\n`, создаёт `InMemoryDexClassLoader(ByteBuffer, ApplicationLoader.applicationContext.getClassLoader())` и загружает `ru.n08i40k.template.Plugin`. Reflection-вызов требует точного `java.lang.Class.getDeclaredMethod(String, Class...)`; Python передаёт Java типы явно. Неподтверждённый DEX/class-load сбой логируется и блокирует дальнейшую подготовку. Entry API — Kotlin companion `@JvmStatic` методы `inject(String, ValueCallback)`, `finalizeInject()`, `eject()`, `invokeChatContextMenuCallback(String,long)`, `invokeSettingsActionCallback(String)` ([Python bridge, строки 107–154, 543–600](https://github.com/RObotiaga/exteragram-plugin-template/blob/bbf44de36e16c360a3f5afcbc99bc331ac52ebb9/exteragram-plugin-template.py#L107-L154), [Plugin.kt, строки 36–45, 65–178](https://github.com/RObotiaga/exteragram-plugin-template/blob/bbf44de36e16c360a3f5afcbc99bc331ac52ebb9/src/main/kotlin/ru/n08i40k/template/Plugin.kt#L36-L178)).

Загрузка вынесена из `on_plugin_load()` в daemon Python thread. Она сериализована class-level lock и идёт в порядке `load DEX → inject JVM → register Python UI → finalizeInject/hook`. Повторная загрузка при `_full_load_started` пропускается. На ошибке вызывается crash-report path; на выгрузке удаляется Python menu item, вызывается Kotlin `eject()` и bridge reference очищается ([Python entry, строки 487–655](https://github.com/RObotiaga/exteragram-plugin-template/blob/bbf44de36e16c360a3f5afcbc99bc331ac52ebb9/exteragram-plugin-template.py#L487-L655)).

На стороне Kotlin `inject` synchronized и защищён от повторного injection того же classloader; через `System.getProperties()` хранится supplier для eject предыдущего plugin loader, новый inject ждёт завершения старого. `finalizeInject` отдельно запускает hooks после Python UI registration. `onEject()` снимает Xposed unhook handles, отменяет `backgroundScope`, ждёт дочерние jobs, затем через `EjectNotifier` дожидается `RefCounter == 0` ([Plugin.kt, строки 73–159, 192–267](https://github.com/RObotiaga/exteragram-plugin-template/blob/bbf44de36e16c360a3f5afcbc99bc331ac52ebb9/src/main/kotlin/ru/n08i40k/template/Plugin.kt#L73-L159)). Eject listeners сортируются по возрастанию priority и очищаются после вызова; текущий `Logger` подписан с priority 1000, счётчик UI work — в последнем barrier priority 999 ([EjectNotifier.kt, строки 6–30](https://github.com/RObotiaga/exteragram-plugin-template/blob/bbf44de36e16c360a3f5afcbc99bc331ac52ebb9/src/main/kotlin/ru/n08i40k/template/event/eject/EjectNotifier.kt#L6-L30), [Plugin.kt, строки 208–233](https://github.com/RObotiaga/exteragram-plugin-template/blob/bbf44de36e16c360a3f5afcbc99bc331ac52ebb9/src/main/kotlin/ru/n08i40k/template/Plugin.kt#L208-L233)).

### Hooks и callbacks

Python `ChatContextMenu` регистрирует action через `BasePlugin.add_menu_item(MenuItemData(... CHAT_ACTION_MENU ...))`, запоминает выданные host item IDs и удаляет их при unload/eject. Callback принимает либо `dialog_id`/`dialogId`, либо fragment-объект; он безопасно извлекает `getDialogId()` и преобразует ID в Long перед JVM вызовом. В демонстрации Kotlin callback показывает bulletin и логирует peer ID ([Python entry, строки 278–379](https://github.com/RObotiaga/exteragram-plugin-template/blob/bbf44de36e16c360a3f5afcbc99bc331ac52ebb9/exteragram-plugin-template.py#L278-L379), [ChatContextMenuActions.kt, строки 8–30](https://github.com/RObotiaga/exteragram-plugin-template/blob/bbf44de36e16c360a3f5afcbc99bc331ac52ebb9/src/main/kotlin/ru/n08i40k/template/ChatContextMenuActions.kt#L8-L30)). Settings use `Header` и `Text`; action key передаётся в Kotlin с точной строковой сигнатурой ([Python entry, строки 381–410](https://github.com/RObotiaga/exteragram-plugin-template/blob/bbf44de36e16c360a3f5afcbc99bc331ac52ebb9/exteragram-plugin-template.py#L381-L410)). Kotlin registries запрещают дубликаты и регистрацию после freeze; чтение разрешено только после freeze. Неизвестный key вызывает исключение, поэтому обе стороны должны сохранять одинаковые callback keys ([LockableRegistry.kt, строки 3–31](https://github.com/RObotiaga/exteragram-plugin-template/blob/bbf44de36e16c360a3f5afcbc99bc331ac52ebb9/src/main/kotlin/ru/n08i40k/template/registry/LockableRegistry.kt#L3-L31)).

Kotlin hooks делятся на `before`/`after`; handles Xposed сохраняются в `hooks` и снимаются при eject. `ExampleHookBundle` ищет `LaunchActivity.onResume()` без параметров по reflection и пропускает feature при отсутствии метода, затем ставит after hook. Это только пример версии target JAR; signature `LaunchActivity.onResume()` нельзя объявлять совместимой для любого клиента без соответствующего APK ([Plugin.kt, строки 235–267](https://github.com/RObotiaga/exteragram-plugin-template/blob/bbf44de36e16c360a3f5afcbc99bc331ac52ebb9/src/main/kotlin/ru/n08i40k/template/Plugin.kt#L235-L267), [ExampleHookBundle.kt, строки 8–25](https://github.com/RObotiaga/exteragram-plugin-template/blob/bbf44de36e16c360a3f5afcbc99bc331ac52ebb9/src/main/kotlin/ru/n08i40k/template/hook/impl/ExampleHookBundle.kt#L8-L25)).

### Gradle, host JARs, shading и runtime safety

Задекларированы Android Gradle Plugin `9.0.1`, Kotlin `2.2.0`, compile/target SDK `36.1/36`, min SDK `26`, Build Tools `36.1.0`, JVM bytecode 11; CI/release запускают Java 21. Фиксированный host compile input — `libs/Telegram-compile.jar`, в дополнение к raw `Telegram.jar` для подготовки ([build.gradle.kts, строки 17–43, 240–360](https://github.com/RObotiaga/exteragram-plugin-template/blob/bbf44de36e16c360a3f5afcbc99bc331ac52ebb9/build.gradle.kts#L17-L43), [libs.versions.toml](https://github.com/RObotiaga/exteragram-plugin-template/blob/bbf44de36e16c360a3f5afcbc99bc331ac52ebb9/gradle/libs.versions.toml#L1-L22)). Плагин компилируется против Android/Telegram/Xposed/Kotlin и ряда compileOnly API; Kotlin stdlib, coroutines и i18n4k отдельно попадают в `embed` DEX-вход, с relocation под `ru.n08i40k.template_shaded.*`. Build task извлекает JAR вложений AAR, объединяет class inputs, убирает runtime копии библиотек, которые встраивает, оставляя исходные зависимости на R8 classpath для разрешения ссылок ([build.gradle.kts, строки 331–453](https://github.com/RObotiaga/exteragram-plugin-template/blob/bbf44de36e16c360a3f5afcbc99bc331ac52ebb9/build.gradle.kts#L331-L453)).

Remapper сохраняет host APIs, Android, собственный package и отдельные compile-only namespaces в исходных именах; прочие встроенные dependency classes переезжают в отдельный shaded package. Ресурсы `META-INF/com.android.tools/r8/` и `META-INF/proguard/` от relocated библиотек выбрасываются, чтобы старые package rules не давали ложные diagnostics. Синтетические имена dex2jar вида `Foo-IA` нормализуются в `Foo_IA` только если такой класс реально есть ([build.gradle.kts, строки 33–110, 124–148, 416–475](https://github.com/RObotiaga/exteragram-plugin-template/blob/bbf44de36e16c360a3f5afcbc99bc331ac52ebb9/build.gradle.kts#L33-L110)). R8 запускается напрямую через `d8.jar` как R8 CLI в `--release --dex`; `Warning:` и unmatched ProGuard rules приводят к ошибке, широкого `-ignorewarnings` нет. Узкий `-dontwarn` оставлен для compile-time `animal_sniffer.IgnoreJRERequirement` ([build.gradle.kts, строки 483–579](https://github.com/RObotiaga/exteragram-plugin-template/blob/bbf44de36e16c360a3f5afcbc99bc331ac52ebb9/build.gradle.kts#L483-L579)). ProGuard keep сохраняет package самого plugin и volatile fields в relocated coroutines/SafeContinuation; Runtime-visible metadata оставлена, RuntimeInvisibleAnnotations намеренно не сохраняются ([proguard-rules.pro, строки 1–27](https://github.com/RObotiaga/exteragram-plugin-template/blob/bbf44de36e16c360a3f5afcbc99bc331ac52ebb9/proguard-rules.pro#L1-L27)).

`validate_dex_runtime.py` перечисляет final DEX defined/external type descriptors и сверяет внешние типы с узким allowlist Android/Java, host Telegram/Extera, Xposed, `org.json`, RecyclerView. Это статическая проверка surface, а не ART link test ([validate_dex_runtime.py, строки 10–22, 54–114](https://github.com/RObotiaga/exteragram-plugin-template/blob/bbf44de36e16c360a3f5afcbc99bc331ac52ebb9/tools/validate_dex_runtime.py#L10-L22)). `FixTelegramJar.java` ремонтирует dex2jar JAR: пересобирает InnerClasses metadata из видимых references (для Kotlin supertype resolution) и удаляет из compile JAR packages, поставляемые Gradle dependencies ([FixTelegramJar.java, строки 5–28, 61–79, 192–252](https://github.com/RObotiaga/exteragram-plugin-template/blob/bbf44de36e16c360a3f5afcbc99bc331ac52ebb9/tools/FixTelegramJar.java#L5-L28)). Host JAR — ABI конкретного APK; компиляция с чужим билдом не доказывает совместимость.

### Build, CI, debug и release

`just dex` собирает debug DEX; `just ci` — release DEX; `just eaf` пакует уже собранный DEX; `just build` связывает release DEX и EAF. `just embed` и `just watch` остаются legacy однофайловыми путями, где DEX встраивается hex-комментариями ([justfile, строки 25–64](https://github.com/RObotiaga/exteragram-plugin-template/blob/bbf44de36e16c360a3f5afcbc99bc331ac52ebb9/justfile#L25-L64)). `just update-apk <apk>` локально преобразует переданный APK через dex2jar, FixTelegramJar и сохраняет оба JAR в `libs/`; он не выбирает и не скачивает APK автоматически ([justfile, строки 66–91](https://github.com/RObotiaga/exteragram-plugin-template/blob/bbf44de36e16c360a3f5afcbc99bc331ac52ebb9/justfile#L66-L91)). Watcher опрашивает mtime Python entry и DEX, строит временный legacy `.py` и использует `exteragram_utils.dev_client` для upload/reload; это не structured EAF file sync ([dev_watch.py, строки 1–13, 24–34, 114–154](https://github.com/RObotiaga/exteragram-plugin-template/blob/bbf44de36e16c360a3f5afcbc99bc331ac52ebb9/tools/dev_watch.py#L1-L34)).

CI всегда делает Python syntax checks, сверяет метаданные и пакует smoke EAF с искусственным DEX, проверяя ID rejection, байтовый DEX, layout и ZIP. Полная Gradle/DEX цепочка с runtime-surface validation включается, только если оба host JAR доступны. При полном пути EAF публикуется Actions artifact на 14 дней; Telegram publish условный и опирается на repository secrets ([ci.yml, строки 20–220](https://github.com/RObotiaga/exteragram-plugin-template/blob/bbf44de36e16c360a3f5afcbc99bc331ac52ebb9/.github/workflows/ci.yml#L20-L220)). Manual Release требует оба JAR, запускает metadata bump, release DEX, EAF validation, provenance attestation, затем коммитит metadata, ставит tag и публикует `.eaf` ([release.yml, строки 1–35, 59–123, 125–208](https://github.com/RObotiaga/exteragram-plugin-template/blob/bbf44de36e16c360a3f5afcbc99bc331ac52ebb9/.github/workflows/release.yml#L1-L35)).

### Ограничения и конфликтующие данные

- На уровне repo code, release metadata, плагин ID `exteragram_plugin_template`, версия `0.1.0`, `app_version >=12.5.1`, `sdk_version >=1.4.5.3` ([metainfo.yml](https://github.com/RObotiaga/exteragram-plugin-template/blob/bbf44de36e16c360a3f5afcbc99bc331ac52ebb9/metainfo.yml#L1-L7)); это снимок конкретного форка, не текущий baseline всех ExteraGram plugins.
- README содержит документационное заявление, что structured Elyx DEX load и Python→JVM callback подтверждены на AyuGram runtime ([README, строки 173–179](https://github.com/RObotiaga/exteragram-plugin-template/blob/bbf44de36e16c360a3f5afcbc99bc331ac52ebb9/README.md#L173-L179)). В том же commit ROADMAP конкретизирует AyuGram 12.9.0: установка EAF и создание Python UI подтверждены, но JVM callback не подтверждён; зафиксирован `JVM plugin is not loaded`, а runtime debug оставлен в backlog ([ROADMAP, строки 7–28](https://github.com/RObotiaga/exteragram-plugin-template/blob/bbf44de36e16c360a3f5afcbc99bc331ac52ebb9/ROADMAP.md#L7-L28)). Это конфликт между двумя документационными свидетельствами, а не доказательство, что разные описания относятся к одному успешному тесту: сборка/артефакт/логи из README не приведены. Код показывает задуманный bridge и обработку ошибки, но не разрешает runtime-статус. Поэтому на AyuGram 12.9.0 подтверждены только установка и Python UI по ROADMAP; JVM execution остаётся неподтверждённым, а общее заявление README — непроверенным docs.
- CI smoke DEX создаёт синтетический payload с `dex\n035` и подтверждает только EAF packaging/layout. Настоящая Gradle release DEX сборка и статическая DEX runtime-surface проверка выполняются только при наличии обоих `libs/Telegram.jar` и `libs/Telegram-compile.jar` ([ci.yml, строки 85–107, 149–220](https://github.com/RObotiaga/exteragram-plugin-template/blob/bbf44de36e16c360a3f5afcbc99bc331ac52ebb9/.github/workflows/ci.yml#L85-L107)). Значит, зелёный smoke при отсутствующих JAR не является подтверждением полной сборки. Ни один workflow run этого SHA не инспектировался.
- Репозиторий читает файлы `.py` как исходники и `pyproject.toml` требует Python `>=3.14` для developer tooling; это не заявляет Python runtime клиента (skill указывает 3.11 и отправляет проверять официальный SDK) ([pyproject.toml](https://github.com/RObotiaga/exteragram-plugin-template/blob/bbf44de36e16c360a3f5afcbc99bc331ac52ebb9/pyproject.toml#L1-L22), [12-pitfalls-compatibility.md, строки 41–50](https://github.com/RObotiaga/exteragram-plugin-template/blob/bbf44de36e16c360a3f5afcbc99bc331ac52ebb9/skills/exteragram-eaf-template/references/12-pitfalls-compatibility.md#L41-L50)).
- Kotlin helper `Fragment.kt` обращается к приватному `LaunchActivity.actionBarLayout`; `ExampleHookBundle` ищет private/client implementation details reflection-ом. Их имена и поведение привязаны к host JAR/runtime версии, а не гарантированы public SDK.
- `RefCounter.dec()` уменьшает счётчик без защиты от negative/duplicate dec; consumers новых helper callbacks должны соблюдать ровно один `inc()`/`dec()` pair. Lifecycle barrier блокирует на `runBlocking` при eject и поэтому должен использоваться только для короткой UI callback работы.
- Raw host JARs в tree есть, но не включены в приобретённые текстовые файлы и в этом исследовании не анализировались бинарно; происхождение именно этих JAR и совпадение с конкретным APK в snapshot не устанавливались.

## Рецепты применения

1. **Новый EAF fork:** выбрать ID без дефиса; менять package/ID/name через `just init` только после проверки скрипта на нужной версии; синхронизировать `metainfo.yml`, Python metadata, `Plugin.ID`, package namespace и version; собрать host JAR из конкретного целевого APK; выполнить release path и инспектировать фактический ZIP с `assets/` и `src/` directory entries.
2. **Добавить действие меню с DEX backend:** определить menu placement через актуальную SDK документацию; сделать уникальный key константой на обоих слоях; регистрировать menu item с явным owner и remove при unload; зарегистрировать Kotlin callback до freeze; передать ровно соответствующие Java parameter classes; не объявлять работу завершённой, пока не пройден реальный callback на точном клиенте.
3. **Добавить Kotlin method hook:** сначала определить target class и точную сигнатуру по APK/JAR нужного host build; регистрировать только после `finalizeInject`; сохранить каждый unhook handle; callback оставить коротким и безопасным по thread; снять handles и очистить generation state при eject.
4. **Добавить dependency в standalone DEX:** решить compileOnly vs embedded/runtime; embedded code должно быть relocated для избежания host collision; сохранить original jar на R8 classpath, если host signatures ссылаются на original names; удалить устаревшие consumer rules, но перевести нужную семантику под relocated namespace; проверить final DEX runtime surface.
5. **Диагностировать `JVM plugin is not loaded`:** идти от первого load stage: DEX candidate/path/read → magic/size → parent loader → `loadClass` linkage exception → `inject` → UI registration → `finalizeInject` → feature callback. Сообщение callback считается следствием, пока более ранний сбой не исключён; см. [field failure playbook](https://github.com/RObotiaga/exteragram-plugin-template/blob/bbf44de36e16c360a3f5afcbc99bc331ac52ebb9/skills/exteragram-eaf-template/references/13-field-failure-playbook.md#L249-L279).
6. **Тестировать build gates:** различать synthetic EAF smoke, реальный Gradle/R8/D8 + DEX validator и runtime device test. Smoke с искусственными DEX magic доказывает ZIP plumbing, не Kotlin class linkage. Проверять exact artifact/run/head, metadata, ZIP paths, byte-equal DEX и отсутствие встроенного hex в structured `main.py`.
