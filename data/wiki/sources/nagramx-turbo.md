# Nagram X Turbo

- Репозиторий: https://github.com/temporaryna/NagramXTurbo
- Снимок ветки `dev`: `267a33ead32b6f003b6aa8f913e7727e9992a7f2`; зафиксирован 2026-09-27. Снимок полного дерева включает 21 821 путь.
- Лицензия репозитория: GPL-3.0 ([LICENSE](https://github.com/temporaryna/NagramXTurbo/blob/267a33ead32b6f003b6aa8f913e7727e9992a7f2/LICENSE)); код AyuGram дополнительно содержит просьбу сохранять авторство/кредит.
- Роль: полноценный Android-клиент Telegram, форк Nagram X. Это полезный пример интеграции настроек, хранения локальной истории, сетевых обновлений и UI в собственное приложение; источник не является SDK или руководством по ExteraGram-плагинам.
- Версионная база по README: Nagram X `12.10.0-a6c7d0a`, обновления Telegram синхронизированы до `12.10.3-9552e55`. Это версии, указанные этим снимком, не текущая версия Telegram или ExteraGram.
- Код читался как статические данные. APK не собирался; приложение и фичи не запускались. Все выводы об исполнении отмечены как `code`, а не `runtime-verified`.

Поэтому приведённые ниже классы — внутренние детали NagramXTurbo, не публичные plugin API. Отсутствие API во всём репозитории не утверждается.

## Технические факты

### Настройки и сборка

Turbo раздел добавлен в Nekogram settings через выделенную строку, которая открывает `TurboSettingsActivity`. Экран построен из `CellGroup` и типизированных `ConfigItem` для переключателя, select box, заголовка и custom view; настройки сгруппированы по input bar, media, forwarding, fonts и deleted messages. На некоторых параметрах экран строит UI-строки прямо из `NaConfig`, но конкретное применение происходит в других частях клиента. [Код: [NekoSettingsActivity](https://github.com/temporaryna/NagramXTurbo/blob/267a33ead32b6f003b6aa8f913e7727e9992a7f2/TMessagesProj/src/main/java/tw/nekomimi/nekogram/settings/NekoSettingsActivity.java#L101), [TurboSettingsActivity](https://github.com/temporaryna/NagramXTurbo/blob/267a33ead32b6f003b6aa8f913e7727e9992a7f2/TMessagesProj/src/main/java/tw/nekomimi/nekogram/settings/TurboSettingsActivity.java#L123)]

`NaConfig` сохраняет настройки как `ConfigItem` с типом, ключом и default value; среди типов есть bool, int, string, sets/maps. Например, включение iOS input appearance и compact input size по умолчанию выключено, а `actionButtonStyle` — целочисленный enum. Переносить название Java/Kotlin property отдельно от ключа preference недостаточно: конфигурационная схема здесь определяется `addConfig(key, type, default)`. [Код: [NaConfig](https://github.com/temporaryna/NagramXTurbo/blob/267a33ead32b6f003b6aa8f913e7727e9992a7f2/TMessagesProj/src/main/kotlin/xyz/nextalone/nagram/NaConfig.kt#L1392), [loadConfig](https://github.com/temporaryna/NagramXTurbo/blob/267a33ead32b6f003b6aa8f913e7727e9992a7f2/TMessagesProj/src/main/kotlin/xyz/nextalone/nagram/NaConfig.kt#L1768)]

`TMessagesProj/build.gradle` читает `TURBO_BASE` из Gradle property, environment или `local.properties` и передаёт boolean в `BuildConfig`; `BuildVars.TURBO_BASE` — собранный variant flag, а не пользовательская настройка. В `TurboSettingsActivity` для base отсутствуют строки forwarding/protected-forward, deleted messages и edits history. Код здесь подтверждает условное построение соответствующих экранных настроек, но не доказывает, что все реализации этих функций исключены из APK. Updater читает отдельное поле URL для base. README/CHANGELOG описывают base-вариант без набора спорных функций. [Код: [TMessagesProj build](https://github.com/temporaryna/NagramXTurbo/blob/267a33ead32b6f003b6aa8f913e7727e9992a7f2/TMessagesProj/build.gradle#L64), [BuildVars](https://github.com/temporaryna/NagramXTurbo/blob/267a33ead32b6f003b6aa8f913e7727e9992a7f2/TMessagesProj/src/main/java/org/telegram/messenger/BuildVars.java#L28), [TurboSettingsActivity](https://github.com/temporaryna/NagramXTurbo/blob/267a33ead32b6f003b6aa8f913e7727e9992a7f2/TMessagesProj/src/main/java/tw/nekomimi/nekogram/settings/TurboSettingsActivity.java#L157), [UpdateHelper](https://github.com/temporaryna/NagramXTurbo/blob/267a33ead32b6f003b6aa8f913e7727e9992a7f2/TMessagesProj/src/main/java/tw/nekomimi/nekogram/helpers/remote/UpdateHelper.java#L117); документация: [CHANGELOG](https://github.com/temporaryna/NagramXTurbo/blob/267a33ead32b6f003b6aa8f913e7727e9992a7f2/CHANGELOG.md#L25)]

Корневой `build.gradle` задаёт для Android-модулей compile SDK 37, Build Tools 36.0.0, NDK 27.2.12479018, Java/Kotlin target 21, min SDK 27 и target SDK 36. Gradle-конфигурация app module прекращается, если отсутствуют `TELEGRAM_APP_ID`/`TELEGRAM_APP_HASH` или API ID равен публичному sample `6`; комментарий предупреждает, что Telegram отзывает сессии клиентов, использующих этот ID. Это декларации сборки pinned SHA и комментарий исходника, а не результат сборки. README отдельно называет Android Studio, SDK 36/37 и NDK и рекомендует задачи `:TMessagesProj:assembleStaging` или `assembleRelease`; ни одна задача не запускалась. ### Пересылка

`ShareAlert` — точка взаимодействия пользователя с настройками пересылки. В режиме редактирования изменённый текст отправляется отдельным путём `sendForwardEditedAsCopy`; оригинальный текст извлекается из caption, а для обычного текстового сообщения — из `ChatActivity.getMessageContent`. `ForwardTextEdit.withEditedText(...)` временно заменяет message/entities/caption/messageText вокруг callback отправки и восстанавливает прежние поля в `finally`; это уменьшает риск оставить изменённый объект в состоянии, используемом другими call-site. Точные ограничения выбора редактируемых сообщений остаются во вспомогательном классе. [Код: [ForwardTextEdit](https://github.com/temporaryna/NagramXTurbo/blob/267a33ead32b6f003b6aa8f913e7727e9992a7f2/TMessagesProj/src/main/java/xyz/nextalone/nagram/helper/ForwardTextEdit.java#L12), [ShareAlert](https://github.com/temporaryna/NagramXTurbo/blob/267a33ead32b6f003b6aa8f913e7727e9992a7f2/TMessagesProj/src/main/java/org/telegram/ui/Components/ShareAlert.java#L3298)]

Protected-forward поддерживает режимы ask/always/never в `NaConfig`. `ProtectedForward.containsProtected(messages)` проверяет выбранные сообщения; `ShareAlert` вызывает policy helper только если сборка не base и приложение может отправить их как копию. Ask показывает разовый выбор, а always/never сохраняются в конфиге. Это клиентская политика обхода штатного ограничения Telegram, а не универсальный безопасный API и не поведение, доступное Base-сборке. [Код: [ProtectedForward](https://github.com/temporaryna/NagramXTurbo/blob/267a33ead32b6f003b6aa8f913e7727e9992a7f2/TMessagesProj/src/main/java/xyz/nextalone/nagram/helper/ProtectedForward.java#L31), [ShareAlert](https://github.com/temporaryna/NagramXTurbo/blob/267a33ead32b6f003b6aa8f913e7727e9992a7f2/TMessagesProj/src/main/java/org/telegram/ui/Components/ShareAlert.java#L3350), [NaConfig](https://github.com/temporaryna/NagramXTurbo/blob/267a33ead32b6f003b6aa8f913e7727e9992a7f2/TMessagesProj/src/main/kotlin/xyz/nextalone/nagram/NaConfig.kt#L1422)]

### Локальная история удалённых сообщений и media

Выбор сохранения удалённого сообщения фильтруется до записи: глобальный `EnableSaveDeletedMessages`, исключения для dialog и user, категория чата, затем специальные флаги для авторов-ботов. `AyuSavePreferences.saveDeletedMessageFor(accountId, dialogId, ...)` адресует account явно; исключения кешируются в `ConcurrentHashMap`, читаются/записываются через Nekogram preferences, полная загрузка выполняется через `Utilities.stageQueue`. Это хороший пример разделения decision helper и UI, но такой перехват доступен лишь внутри клиентской реализации. [Код: [AyuSavePreferences](https://github.com/temporaryna/NagramXTurbo/blob/267a33ead32b6f003b6aa8f913e7727e9992a7f2/TMessagesProj/src/main/java/com/radolyn/ayugram/messages/AyuSavePreferences.java#L70)]

Ayu-хранилище использует Room: `AyuDatabase` объявляет таблицы deleted/edited messages, deleted reactions и last-seen; версия схемы в этом SHA — 26. `DeletedMessage` задаёт составные индексы по `userId`/`dialogId`/message и отдельные варианты с `topicId`, `replyMessageId` и `groupedId`, а также одиночный индекс `dialogId`. `DeletedMessageDao` содержит отдельные запросы для этих контекстов, пагинации и групп media; account-slot ID в индексах нет (`userId` — поле Telegram-пользователя). Экран истории выбирает страницы по 50 сообщений, для encrypted диалога отдельное поведение. `DeletedMessage.fakeId` — отдельный auto-generated Room primary key; не путать эти данные с серверной Telegram историей. [Код: [AyuDatabase](https://github.com/temporaryna/NagramXTurbo/blob/267a33ead32b6f003b6aa8f913e7727e9992a7f2/TMessagesProj/src/main/java/com/radolyn/ayugram/database/AyuDatabase.java#L23), [DeletedMessage](https://github.com/temporaryna/NagramXTurbo/blob/267a33ead32b6f003b6aa8f913e7727e9992a7f2/TMessagesProj/src/main/java/com/radolyn/ayugram/database/entities/DeletedMessage.java#L12), [DeletedMessageDao](https://github.com/temporaryna/NagramXTurbo/blob/267a33ead32b6f003b6aa8f913e7727e9992a7f2/TMessagesProj/src/main/java/com/radolyn/ayugram/database/dao/DeletedMessageDao.java#L20), [AyuMessageBase](https://github.com/temporaryna/NagramXTurbo/blob/267a33ead32b6f003b6aa8f913e7727e9992a7f2/TMessagesProj/src/main/java/com/radolyn/ayugram/database/entities/AyuMessageBase.java#L12), [AyuViewDeleted](https://github.com/temporaryna/NagramXTurbo/blob/267a33ead32b6f003b6aa8f913e7727e9992a7f2/TMessagesProj/src/main/java/com/radolyn/ayugram/ui/AyuViewDeleted.java#L98)]

`MediaController` после локального появления файла отправляет UI-thread notification `DELETED_MEDIA_LOADED_NOTIFICATION` только если это не base build, функция сохранения удалённого включена, а `MessageObject` помечен как удалённый Ayu. ### Обновления и сеть

`BaseRemoteHelper` берёт `MessagesController`, `ConnectionsManager`, `MessagesStorage` и `FileLoader` из `UserConfig.selectedAccount`; его `load()` не принимает account ID, поэтому это привязка к выбранному аккаунту клиента. Метаданные читаются через `messages.search` по специальному каналу и тегу `#<tag>`; при отсутствующем/просроченном access hash код сначала разрешает username канала, сохраняет users/chats локально, затем повторяет поиск. Из ответов он парсит совпавшие JSON-сообщения и кэширует первый результат по тегу в `nekoremoteconfig` preferences; пустой результат очищает прежнее значение. Это закрытая внутренняя remote-config схема, не REST-клиент общего назначения. [Код: [BaseRemoteHelper](https://github.com/temporaryna/NagramXTurbo/blob/267a33ead32b6f003b6aa8f913e7727e9992a7f2/TMessagesProj/src/main/java/tw/nekomimi/nekogram/helpers/remote/BaseRemoteHelper.java#L21)]

`UpdateHelper` выбирает `updateDebug`, `updateRelease` или `updateBeta`; более высокая `version_code` считается новее, равный code сравнивается по build timestamp. Для base сборки берётся `url_base`, для обычной — `url`; ABI-предпочтение читается из `Build.SUPPORTED_ABIS`, с отдельным fallback. `ApkDownloader.download(url, callback)` проверяет, что переданный URL начинается с `https://github.com/temporaryna/NagramXTurbo/releases/`, затем скачивает на single-thread executor в `files/update`, пишет в `.tmp` и переименовывает файл после завершения чтения потока. Это проверка исходной строки URL; поведение redirect и реальная проверка целостности/подписи отдельно не исследовались. Callback progress/success/error переводятся в UI thread. Код не доказывает, что APK устанавливается в этом потоке. [Код: [UpdateHelper](https://github.com/temporaryna/NagramXTurbo/blob/267a33ead32b6f003b6aa8f913e7727e9992a7f2/TMessagesProj/src/main/java/tw/nekomimi/nekogram/helpers/remote/UpdateHelper.java#L59), [ApkDownloader](https://github.com/temporaryna/NagramXTurbo/blob/267a33ead32b6f003b6aa8f913e7727e9992a7f2/TMessagesProj/src/main/java/tw/nekomimi/nekogram/helpers/remote/ApkDownloader.java#L22)]

## Что это даёт разработчику плагинов ExteraGram

Практически переносимы как идеи: отделять экран настройки от типизированной схемы; хранить пользовательские параметры по ясному ключу с default и миграцией; выполнять крупную загрузку на выделенном executor и отдавать callback в UI thread; фильтровать сохранение по account/chat/category перед записью; ограничивать download URL точным release-prefix и финализировать скачивание через temporary file. Конкретные классы, Telegram TL requests, `UserConfig`, `NotificationCenter`, Ayu Room DB и внутренние настройки недоступны плагину автоматически — перед переносом каждый вызов необходимо заменить на публичный API PySDK/ExteraGram и проверить на нужной версии.
