В GitHub metadata лицензия не указана (`license: null`). Репозиторий описывает себя как неофициальный AyuGram iOS-порт поверх Swiftgram и Telegram iOS с встроенными плагинами ReqGram. Здесь нет Android Plugin SDK: это исходники большого Swift/iOS-приложения, поэтому их вызовы — примеры внутренней интеграции клиента, а не API, доступный из `.plugin` ExteraGram/AyuGram. ## Роль и границы доказательств

Наибольшую ценность для разработки дают три группы примеров: локальное сохранение удалённых/изменённых сообщений в отдельном хранилище; независимая загрузка и кэширование бейджей нескольких проектов; настройка пользовательских возможностей внутри нативного клиента. Эти образцы помогают формулировать требования к Android-плагину или клиентской доработке, но не доказывают, что их Swift-типы или Telegram iOS hooks переносимы в Android.

README перечисляет режим призрака, историю сообщений, оформление, Gift ID, Local Editor/ZwyLib и анимации текста. Из загруженных файлов подробно прослежены AyuGram-хранилище, hooks, фильтры, бейджи и нативная settings UI ReqGram. Реализации всех шести объявленных встроенных плагинов и всех их Android-аналогов в этом источнике нет. README сообщает о проверке на iOS 16.7.10; отдельного протокола/лога проверки в изученном наборе нет, поэтому это только заявление документации, не результат данного ingest.

## Технические факты

### Плагинная модель и интерфейсы

- `Swiftgram/AyuGram/BUILD` объявляет Swift-library target `AyuGram`, включает `Sources/**/*.swift`, экспортирует его наружу через Bazel `//visibility:public`, но зависит от Swift-модулей `SGLogging` и `SGSimpleSettings`. Это интеграционный модуль внутри iOS-сборки, а не загружаемый Android-плагин.
- `reqGramSettingsController(context: AccountContext) -> ViewController` строит нативный список плагинов ReqGram: Gift ID, отправка подарка по ID, отправитель удалённых подарков, Local Edictor/ZwyLib, снятие лимита пересылки ZwyLib и анимация текста Private Let. Значительная часть действий реализована как переключатели/описания; одна явная команда здесь валидирует положительный `Int64` gift id и запускает Telegram `makeStarGiftByIdController`, который затем помещается в navigation stack.
- `SGTextAnimationPreviewItem` строит preview посимвольно на `CATextLayer`, комбинирует opacity/slide/scale/rotation/blur через `CAAnimationGroup`, зацикливает preview и отключает анимацию при Reduce Motion. Это UI preview; по этому файлу одному нельзя вывести, что все параметры и delete/cursor effects работают на всех экранах клиента.
- `AyuStreamerMode` адаптирует desktop streamer privacy к iOS: подписывается на `UIScreen.capturedDidChangeNotification`, сообщает UI, когда включённый режим должен скрывать/размывать контент, и отдельно сигнализирует о скриншоте после факта. iOS-реализация не блокирует screenshot и не исключает окно из записи.

### Локальная история и безопасность файлов

- `AyuMessageStore` хранит удалённые snapshots и редакции отдельно от Postbox в одном JSON-файле; документированный предел — 500 удалённых сообщений на пару account/peer, размер файла ограничен 128 MiB. Доступ сериализован очередью `AyuStorage`; запись атомарна, после commit observers вызываются на main queue.
- `AyuSavedMessage` сохраняет account, peer, message/thread ids, автора, даты, текст, flags/copy-protection, media metadata, Telegram entity/peer metadata и связанные custom emoji. Байты вложений вынесены в файлы; у старых JSON-записей отсутствующие новые optional-поля декодируются через `decodeIfPresent`.
- `AyuStorage` размещает данные в `<Application Support>/AyuGram/`, помечает каталог как исключённый из iCloud backup и использует `completeUntilFirstUserAuthentication`; вложения раскладываются по `accountId/peerId/`. Разрешение пути отвергает absolute/traversal-пути, перепроверяет account/peer и проходит по каждому сегменту, запрещая symlink при чтении/удалении.
- `AyuHooks.willDeleteMessages` делает snapshot до удаления, а `willReplaceMessage` до замены сохраняет предыдущий непустой текст. Сохранение локальной истории — перехват момента до удаления/замены; README справедливо предупреждает, что оно не скачивает утраченное с серверов и успевает сохранить медиа только если ресурс уже доступен клиенту.
- Для преднамеренного удаления есть отдельный короткоживущий intent `AyuDeleteIntent.registerKeepLocally(accountPeerId:ids:)`: записи account-scoped, одноразово потребляются точным набором или однозначным подмножеством ID, истекают через 5 секунд; неоднозначное сопоставление ничего не сохраняет. Без intent обычный локальный delete удаляет архивную копию, чтобы не воскрешать собственное удаление.
- Ephemeral voice/round-video захват ограничен входящими cloud-сообщениями, явным view-once/TTL, поддерживаемыми media, настройками конкретного типа диалога и отсутствием copy protection. Если файл не успел попасть в MediaBox, durable pending capture может ждать завершения ресурса и возобновляться при старте аккаунта; незавершённые файлы не считаются сохранёнными. Секретные чаты исключены.
- Store-change callback регистрируется независимым токеном `addStoreChangedObserver` и должен удаляться через `removeStoreChangedObserver`; callback доставляется на main queue. Этот механизм позволяет обновлять UI конкретных peer после дискового commit, не подменяя подписки других экранов.

### Фильтры и совместимость

- `AyuRegexFilter` содержит id, текст шаблона, enabled/reversed/caseInsensitive и optional peer id. Фильтры записываются JSON-строкой в `SGSimpleSettings`; шаблоны компилируются лениво по generation, некорректные Java-dialect patterns пропускаются с логом, максимум длины шаблона — 512 символов.
- `AyuFilters.shouldHide(text:peerId:messageId:isOutgoing:isBroadcast:)` не скрывает исходящие сообщения, не действует на обычные чаты без `ayuFiltersInChats`, проверяет shadow-ban до regex и ограничивает verdict cache 4096 записями. Изменение набора сбрасывает cache; reveal для peer живёт только в памяти до завершения сессии.
- `AyuUtils.filterZalgo` оставляет базовые символы и ограничивает подряд идущие Unicode combining marks двумя; `formatPeerId` выводит скрытый, Telegram или Bot API формат по настройке. Это конкретные алгоритмы клиента, не гарантии общей семантики Android-фильтров.

### Удалённые бейджи

- `AyuRemoteConfig` моделирует grants с issuer, assignment id и полным peer type/id; типы — user/group/channel. Одинаковый numeric ID в разных namespace не должен совпадать. Два legacy AyuGram/exteraGram endpoint читаются в compact формате, ReqGram — в отдельном формате `schemaVersion: 1` с массивом `badges`.
- Три endpoint в текущем коде запрашиваются отдельно на utility serial queue через ephemeral `URLSession`, с HTTPS-only gate, GET, timeout 15 секунд и byte limit 1 MiB. Кэши хранятся раздельно в `UserDefaults` по source, обновление планируется раз в час, данные старше 7 дней или прошедшего `expiresAt` не показываются; лимиты — 10 000 grants/source и 16/peer.
- Для пустого/ошибочного/невалидного ответа сохраняется последний кэш только соответствующего источника. Compact-ответ трактует `developers/supporters` как users, `officialChannels/supporterChannels` как channels; legacy custom badges также ограничены user scope. ReqGram payload требует положительный schemaVersion `1`, peer type/id, стабильный очищенный id и известный kind; malformed записи отбрасываются.
- Внешние тексты бейджей очищаются от controls, format chars и переводов строк, ограничиваются 1024 UTF-8 bytes и 160 символами. Числовые ID принимаются только положительными целыми; строковая десятичная форма сохраняет значения выше точности `Double`, `NSNumber`-float и JSON boolean отклоняются.
- Фиксированные AyuGram/exteraGram роли отображаются стандартными проектными emoji IDs (supporter `5391059537102927631`, остальные фиксированные роли `5390820689676633124`); custom grants используют свой document ID. Resolver сортирует роли и сохраняет issuer/assignment identity; compatible fixed roles dedupe между двумя источниками. Badge UI хранит отдельный проектный контент и объяснение, не превращая remote badge в authoritative Telegram verification.

### Сборка и поставка

- `versions.json` фиксирует app `12.9.2`, Xcode/deploy Xcode `26.2`, Bazel `8.4.2` с контрольной суммой и macOS `26`. README требует macOS, Python 3, Xcode и полного клона с submodules; конфигурация с собственными Telegram `api_id`, `api_hash`, bundle id и team id хранится вне репозитория.
- В README проектный Xcode-файл/target остаются `Telegram/Swiftgram.xcodeproj` и `//Telegram:Swiftgram`, хотя имя продукта ReqGram. Это объясняет важную границу кастомизации: собственное название клиента не означает переименованный внутренний upstream target.
- README требует macOS, Python 3, Xcode и полный клон с submodules; конфигурацию с Telegram `api_id`/`api_hash`, собственными bundle/team ID, сертификатами, profiles и ключами предписывает хранить вне репозитория ([README, строки 57–74](https://github.com/voterol/ReqGram/blob/0400a92db3415411c0430d5bbc360efc1b5ee175/README.md#L57)). Генератор `Make.py generateProject` закрывает запущенный Xcode и затем открывает сгенерированный проект, поэтому изменения надо сохранить заранее ([Make.py](https://github.com/voterol/ReqGram/blob/0400a92db3415411c0430d5bbc360efc1b5ee175/build-system/Make/Make.py#L586)). Это инструкция README и статическая проверка скрипта, не воспроизводимая сборка.
- README отдельно предупреждает: `--xcodeManagedCodesigning` при генерации отключает системные iOS extensions, но не внутренние ReqGram-плагины; Apple Watch по умолчанию не встраивается ([README](https://github.com/voterol/ReqGram/blob/0400a92db3415411c0430d5bbc360efc1b5ee175/README.md#L36), [Make.py](https://github.com/voterol/ReqGram/blob/0400a92db3415411c0430d5bbc360efc1b5ee175/build-system/Make/Make.py#L567)). Архив IPA без подходящей подписи, provisioning profile и entitlements не становится устанавливаемым, а повторная подпись может ограничить системные функции. При отдельной настройке подписи включённым extension targets нужны соответствующие профили.
- Для смены App Group entitlement README описывает отдельное хранилище основного приложения `Application Support/TelegramContainer` и обычный `UserDefaults`; авто-миграции нет, поэтому после смены подписи/entitlements прежние данные могут перестать отображаться. README также говорит, что `.appex` fallback не использует ([README](https://github.com/voterol/ReqGram/blob/0400a92db3415411c0430d5bbc360efc1b5ee175/README.md#L35)). Код соответствующего `SGAppGroupIdentifier.swift` отсутствует среди сохранённых файлов, так что детали остаются непроверенными по реализации и не смешиваются с `AyuStorage` (`Application Support/AyuGram`).
- Скрипт `Make.py` принимает глобальный `--overrideXcodeVersion` перед подкомандой `build`/`generateProject`; это пропускает проверку версии, но само по себе не подтверждает совместимость Xcode. README называет повторную сборку после завершения/отмены текущей операции в Xcode обходом ошибки `build-request.json not updated yet`, повторную генерацию — обходом `Telegram_xcodeproj: no such package`/отсутствия BUILD, а генерацию без provisioning profiles через upstream-флаг `--disableProvisioningProfiles` считает неподтверждённой ([README](https://github.com/voterol/ReqGram/blob/0400a92db3415411c0430d5bbc360efc1b5ee175/README.md#L127)). В текущем `ProjectGeneration.py` аргумент до Bazel не передаётся ([ProjectGeneration.py](https://github.com/voterol/ReqGram/blob/0400a92db3415411c0430d5bbc360efc1b5ee175/build-system/Make/ProjectGeneration.py#L10)).
- У `--embedWatchApp` есть требования из сборочного скрипта: device configuration (`debug_arm64` или `release_arm64`), отдельные Watch `api_id`/`api_hash`, и для distribution — Watch provisioning profile; без подходящего профиля resolver выдаёт ошибку ([Make.py](https://github.com/voterol/ReqGram/blob/0400a92db3415411c0430d5bbc360efc1b5ee175/build-system/Make/Make.py#L615)). README отдельно говорит, что Apple Watch требует собственной подписи. Ни сборка Watch target, ни практическая диагностика здесь не запускались.
- Workflow `.github/workflows/build.yml` выключен для push и запускается вручную (`workflow_dispatch`); snapshot-файл указывает `runs-on: macos-13`, а шаг выбирает `/Applications/Xcode_26.2.app`. Этот CI-файл сам по себе не подтверждает успешную сборку данной версии или совместимость инструментария runner.

## Техники и рецепты, пригодные как идеи

1. **Сохраняйте локальную историю на входе в destructive lifecycle.** Для истории редакций копируйте старую версию до замены; для удалений снимайте snapshot до удаления. Проверьте account/peer/thread identity, отказ пользователя сохранять и clearing-history, чтобы архив не воскресил вручную удалённые сообщения. В Android-плагине способ перехвата и доступность прежней версии надо подтвердить в конкретном SDK.
2. **Отделите байты вложений от метаданных.** Записывайте относительный путь, account/peer scope, проверяйте traversal и symlink при каждом чтении/удалении, ограничивайте размер и число объектов, атомарно заменяйте базу. Не считайте remote-only/частичный кэш сохранённым файлом.
3. **Передавайте intent через узкий одноразовый токен.** Для UI-флага «сохранить локально» используйте account + точный выбранный ID-набор + короткий TTL; очистите intent при отмене. Не применяйте глобальный boolean, который может быть случайно потреблён параллельным удалением.
4. **Для нескольких удалённых реестров храните отдельный last-known-good на источник.** Невалидный ответ одного endpoint не должен очищать кэш другого; задайте HTTPS, timeout, лимит потока байтов, валидируйте IDs/text до UI и ограничьте возраст кэша. Проверяйте peer namespace перед выдачей привилегии/бейджа.
5. **Уважайте ограничения платформы при privacy-функциях.** Состояние iOS screen capture можно наблюдать и скрывать UI-контент, а screenshot — обнаружить после события; этот пример не доказывает запрет записи экрана.

## Ограничения и расхождения

- Это код iOS-приложения; Swift APIs, Postbox types, Bazel targets и lifecycle hooks здесь не являются Android `.plugin` API. Возможные переносы требуют повторной реализации на поддерживаемом ExteraGram/AyuGram интерфейсе.
- В `REQGRAM_BADGES_SPEC.md` статус указан как `implementation in progress`, а блок значений говорит, что production endpoint, роль-emoji IDs, donate/payment URL, контакт и Learn More ещё предстоит предоставить. В текущем `ReqGramBadgeConfiguration.swift` при этом задан endpoint `https://api-reqgram.tgstorage.space/v1/badges` и donate URL `https://t.me/ReqGramDonation_bot`; шесть badge ID и прочие action URLs равны `nil`. Кодовые константы подтверждают только наличие конфигурации в этом SHA, но не доступность endpoint, production-статус или согласование значений с более поздней спецификацией.
- Спецификация заявляет аддитивное объединение источников, но это следует считать документированным ожидаемым поведением, пока оно не проверено на устройстве. Кодовая реализация `AyuRemoteConfig` — более сильное статическое свидетельство алгоритма, не runtime-подтверждение.
- README говорит о сохранении медиа только если приложение успело их получить; исходники уточняют для ephemeral audio/round video recovery через pending capture, но не обещают восстановление несохранённых данных с Telegram.
- README указывает iOS 16.7.10 как проверенную версию. В текущем task у нас нет воспроизводимого протокола той проверки или доказательства работоспособности каждой перечисленной функции.
- В снимке не найден отдельный AyuGram/ReqGram unit-test target по именам дерева. Не читались все тесты общего upstream, все UI call-sites, продуктовые серверы и Android-реализации упомянутых оригинальных плагинов.
- `.github/workflows/build.yml` содержит только ручной запуск, macOS runner `macos-13` и путь к Xcode `26.2`; совместимость такой пары не подтверждена этой конфигурацией и успешного запуска CI не проверяли.
- README перечисляет настройки Ghost Mode, локальную историю (включая импорт/экспорт), оформление и скрытие Premium UI, но полный путь этих функций по UI/core в снимке не прослежен. В частности, документация об App Group fallback не сопоставлена с отсутствующим `SGAppGroupIdentifier.swift`; подробности можно подтверждать только по README.
