## Роль источника и сверка с радаром

Это конкретный пример учета активности на исходящем send hook с хранением агрегируемых записей в plugin settings и простым Android alert dialog. Радары правильно указывают сообщения, символы, интервалы сегодня/7/30 дней, ограничение 5000 сообщений на чат и заявленную совместимость. Чтение кода уточняет, что сообщение целиком не сохраняется, команды отменяются hook-ом, а остальные строки, начинающиеся с точки, исключаются из учета. Упоминание «локально/без сервера» заявлено README; в единственном `.plugin` нет сетевых импортов или сетевых вызовов, но это статическое наблюдение только этого файла, а не runtime-аудит host API.

### Учет чатов и записей

`_chat_id(params)` сначала принимает числовой `peer` напрямую, затем пробует `peer.user_id`, `peer.chat_id`, `peer.channel_id`, затем `params.dialog_id`, `dialogId` и `did`. Для group ID строится строка `-chat_id`, для channel — `-1000000000000 - channel_id`; при полном провале используется общий ключ `"unknown"`. Это локальная логика данного плагина, не общая спецификация Peer/Dialog ID. Так как `account` не участвует в ключе и настройках, одинаковые ключи чатов разных аккаунтов потенциально смешиваются; это вывод из call-site, а не проверка поведения host storage.

Запись содержит только Unix timestamp в секундах и `len(text)` после `.strip()`. Текст/медиа не сохраняются. На каждый чат оставляется только хвост из 5000 записей. Отправка команд `.stats`, `.stat`, `.stats today`, `.stats week`, `.stats month` распознается без учета регистра и возвращает `HookResult(strategy=HookStrategy.CANCEL)`. Другие строки, начинающиеся с `.`, hook пропускает без учета; непустые обычные строки сохраняет и затем возвращает пустой `HookResult`.

Период «сегодня» начинается в полночь по локальному `datetime.now()`; «неделя» и «месяц» означают скользящие 7 и 30 суток. Для выбранного периода меняется count строк сообщений, но число символов и среднее на диалоге остаются общими для всех сохраненных записей: `_make_text()` получает `chars` и `total` без фильтра периода, а меняет только `count`. Поэтому при выбранном периоде count может быть нулевым при ненулевых символах и среднем, а подписи `Символов всего` и `В среднем` относятся к сохраненной истории, а не только к выбранному периоду.

## Практический рецепт

Для похожего локального счетчика достаточно зарегистрировать send hook в load lifecycle, проверить тип и пустоту текста, преобразовать chat identity в строковый ключ, добавить минимальную запись `(timestamp, derived metric)` в plugin setting, ограничить длину списка, а команды управления отменять через соответствующий hook result. Перед переносом нужно сверить точную схему `params`, поведение hook относительно отправки, ключ учетной записи и реальный settings persistence с документацией/API конкретного клиента. Если UI открывается из hook, вызов dialog следует передавать в UI thread и проверять наличие текущего fragment/activity.

README описывает установку как скачивание `chat_stats.plugin`, открытие файла в AyuGram/exteraGram, установку плагина и отправку `.stats` для первого просмотра. Это опубликованная инструкция автора (`docs`), не runtime-проверка данного шага на конкретной версии приложения.

## Ограничения и незакрытые вопросы

- Статистический snapshot включает только непустые текстовые сообщения, которые попали в hook; исходник не проверяет подтверждение сервером, успешную отправку, edit/delete, медиа, сервисные сообщения или retry. Поэтому «отправлено» из README точнее читать как «обработано send hook-ом».
- Обрезка пробелов изменяет метрику длины; `len()` в Python считает Unicode code points, а не визуальные графемы или байты UTF-8.
- Ключ `"unknown"` может свести записи разных чатов. Параметр `account` игнорируется, поэтому account isolation не подтверждена и вероятно отсутствует в собственной схеме плагина.
- Для окна периода выводятся all-time символы и среднее, даже когда число сообщений ограничено сегодня/неделей/месяцем.
- Границы дат основаны на локальном времени процесса; зоны, изменение часового пояса и DST отдельно не обрабатываются. Будущая timestamp-запись также входит в сравнение `>= start`.
- README заявляет хранение только на устройстве, однако плагин использует host settings API; правила резервного копирования/экспорта и область изоляции storage здесь не описаны. Сетевых вызовов в `.plugin` не найдено, но безопасность процесса клиента и API runtime этим не проверяются.
- Хранилище защищает только верхний уровень от non-dict и проверяет `messages` как list при записи; вложенное chat-значение и записи не валидируются при подсчете. Нестандартная или поврежденная settings-схема может вызвать исключение в подсчете/формировании диалога либо записи; hook перехватывает ошибку сохранения и логирует ее.
- Не запускались тесты, клиент, UI или plugin package. Нет runtime-результатов, доказательства фактической совместимости с любым конкретным AyuGram/ExteraGram build либо гарантии успешной доставки сообщения.
- Источник не содержит лицензии в repository metadata, а исторические commit URL в предоставленном радарном наборе отсутствуют.
