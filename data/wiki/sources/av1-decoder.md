## Системный декодер и поток выбора

`scan_decoders(mime)` перечисляет `MediaCodecList.ALL_CODECS`, исключает encoder и фильтрует `getSupportedTypes()` для `video/av01` или `video/hevc`. На API 29+ software классифицируется как `isSoftwareOnly() || !isHardwareAccelerated()`; на более старых Android исходник использует именные префиксы `omx.google.`, `c2.android.`, `c2.google.` либо fallback для имени вне `omx.`/`c2.`. Возможности берутся из верхних границ поддерживаемой ширины/высоты; ошибки capabilities не отменяют запись codec с нулевыми границами. Программный список сортируется так, чтобы имя с `dav1d` стояло первым ([кодек scan, строки 133-163](https://github.com/stxlvn/exteragram-av1-sw-decoder/blob/6367bdcabbf2f7b4b08baa133284f4f122927947/av1_sw_decoder.plugin#L133-L163)).

При загрузке плагин сканирует обе MIME-группы. Если программного декодера нет ни для AV1, ни для HEVC, он пишет `idle` и не ставит хуки. Иначе через class loader приложения ищет `org.telegram.ui.Components.VideoPlayer`, затем устанавливает заявленные hooks; для ExoPlayer ищет сначала `com.google.android.exoplayer2.*`, затем `androidx.media3.exoplayer.*`. Отсутствие Media3/ExoPlayer классов помечается как `class not found`, тогда как отсутствие Telegram `VideoPlayer` завершает установку после статуса. Поиск методов делается через Java reflection, по всем `getDeclaredMethods()` с указанным именем, исключая bridge methods; конструкторная точка ставит hook на все declared constructors ([class lookup, строки 66-82](https://github.com/stxlvn/exteragram-av1-sw-decoder/blob/6367bdcabbf2f7b4b08baa133284f4f122927947/av1_sw_decoder.plugin#L66-L82), [install, строки 598-679](https://github.com/stxlvn/exteragram-av1-sw-decoder/blob/6367bdcabbf2f7b4b08baa133284f4f122927947/av1_sw_decoder.plugin#L598-L679)).

Подмена `VideoPlayer.supportsHardwareDecoder(String)` срабатывает только когда исходный результат false, codec строка равна `av1` или `av01`, найден системный software AV1, настройка enabled включена и ранее не зафиксирован `sw_failed`. Она возвращает true и ставит `override_used` ([hook, строки 337-352](https://github.com/stxlvn/exteragram-av1-sw-decoder/blob/6367bdcabbf2f7b4b08baa133284f4f122927947/av1_sw_decoder.plugin#L337-L352), [state predicates, строки 712-723](https://github.com/stxlvn/exteragram-av1-sw-decoder/blob/6367bdcabbf2f7b4b08baa133284f4f122927947/av1_sw_decoder.plugin#L712-L723)). Это обход Telegram-проверки «только hardware», а не факт ускорения: реализация нацелена на software path.

`getQualities` меняет список in-place. В режиме fallback (default) удаляются AV1 URI, только если в совокупности есть хоть один non-AV1 URI; в режиме always AV1 оставляют вместе с альтернативами. В обоих режимах удаляются AV1 URI, у которых `min(width,height)` выше лимита (`480/720/1080/1440/без лимита`, default 1080); `min` здесь означает короткую сторону, а не вертикальную высоту. Если удаление иначе убрало бы все URI, сохраняется один с наименьшей площадью. Пустые quality groups удаляются ([фильтр, строки 95-130](https://github.com/stxlvn/exteragram-av1-sw-decoder/blob/6367bdcabbf2f7b4b08baa133284f4f122927947/av1_sw_decoder.plugin#L95-L130), [settings constants, строки 38-49](https://github.com/stxlvn/exteragram-av1-sw-decoder/blob/6367bdcabbf2f7b4b08baa133284f4f122927947/av1_sw_decoder.plugin#L38-L49)). Поэтому README wording «только если нет другого кодека» следует читать вместе с отдельным cap: разрешение может отбросить AV1 и в fallback режиме. В коде также есть `QualityForPlayerHook` только для trace/scheduled diagnostics, не для выбора URI.

Когда AV1 подмена уже использовалась, `MediaCodecUtil.getDecoderInfos(mime, secure, tunneling)` переставляет результат: software перед hardware, dav1d первым среди программных при включённом `prefer_dav1d`. HEVC переупорядочивается только если включён `force_sw_hevc`; предпочтение dav1d для HEVC выключено. В список возвращается новый Java `ArrayList`; аппаратный кодек остаётся в конце для fallback. Конструктор `DefaultRenderersFactory` через reflection записывает private `enableDecoderFallback = True`, когда `can_override()` разрешает AV1 (найден программный AV1, настройка включена и ошибка ранее не фиксировалась) либо включён доступный software HEVC; этот hook не требует, чтобы AV1 `override_used` уже случился ([decoder hook, строки 510-563](https://github.com/stxlvn/exteragram-av1-sw-decoder/blob/6367bdcabbf2f7b4b08baa133284f4f122927947/av1_sw_decoder.plugin#L510-L563)). Оба приёма зависят от конкретных внутренних полей/сигнатур библиотеки и могут перестать совпадать при смене версии клиента.

Если `onPlayerError` увидит `av1`/`av01` в строке ошибки или cause и `override_used`, он выставляет `sw_failed`; дальнейшая AV1 eligibility override отключена до следующего `on_plugin_load` (перезагрузки плагина или приложения), потому что флаг сбрасывается при загрузке экземпляра. Поиск — это простое lowercase string match, не типизированная причина decoder failure. В коде есть также trace hooks для first frame, tracks, renderer format support, codec init/error и player events; `onCodecInitialized` записывает имя переданного codec без фильтрации по MIME, поэтому этот callback сам по себе не доказывает инициализацию AV1 ([handlers, строки 384-508](https://github.com/stxlvn/exteragram-av1-sw-decoder/blob/6367bdcabbf2f7b4b08baa133284f4f122927947/av1_sw_decoder.plugin#L384-L508), [VideoPlayer и renderer hooks, строки 610-659](https://github.com/stxlvn/exteragram-av1-sw-decoder/blob/6367bdcabbf2f7b4b08baa133284f4f122927947/av1_sw_decoder.plugin#L610-L659)).

## Lifecycle, threading, settings

`on_plugin_load` создаёт token/session и записывает его в атрибут общего Python `sys`; каждый `PluginHook` проверяет token прежде чем выполнять callback, что делает устаревшие оставшиеся hooks неактивными после следующей загрузки экземпляра. `on_plugin_unload` обнуляет token, отменяет diagnostic timer и вызывает сохранённые unhook callbacks. Это защита от старых hooks после reload, предусмотренная самим кодом; гарантию поведения plugin manager она не устанавливает ([lifecycle, строки 318-335 и 564-597](https://github.com/stxlvn/exteragram-av1-sw-decoder/blob/6367bdcabbf2f7b4b08baa133284f4f122927947/av1_sw_decoder.plugin#L318-L335)).

В настройках хранятся enable, режим качества, max resolution, dav1d preference, HEVC software switch и opt-in диагностики. Долгое нажатие на AV1 switch переключает скрытый раздел. README заявляет Android 10+ минимум и предупреждает, что software decode высокого разрешения может тормозить на слабом CPU; это документационные заявления без измерений в репозитории ([README, строки 47-50](https://github.com/stxlvn/exteragram-av1-sw-decoder/blob/6367bdcabbf2f7b4b08baa133284f4f122927947/README.md#L47-L50)). Исходник не проверяет Android API 29 как минимальную версию: он сканирует доступные кодеки, а при отсутствии software AV1 продолжает установку, если найден software HEVC ([scan, строки 133-163](https://github.com/stxlvn/exteragram-av1-sw-decoder/blob/6367bdcabbf2f7b4b08baa133284f4f122927947/av1_sw_decoder.plugin#L133-L163), [startup, строки 598-609](https://github.com/stxlvn/exteragram-av1-sw-decoder/blob/6367bdcabbf2f7b4b08baa133284f4f122927947/av1_sw_decoder.plugin#L598-L609)). UI также утверждает, что software AV1 есть начиная с Android 10; это текст предупреждения, а не гарантия наличия codec на каждом устройстве ([warning, строки 739-745](https://github.com/stxlvn/exteragram-av1-sw-decoder/blob/6367bdcabbf2f7b4b08baa133284f4f122927947/av1_sw_decoder.plugin#L739-L745)). Переключатель называет dav1d обычно более быстрым libgav1, однако исходник лишь повышает его приоритет по имени и не содержит benchmark; подтверждённых цифр производительности нет ([setting, строки 807-812](https://github.com/stxlvn/exteragram-av1-sw-decoder/blob/6367bdcabbf2f7b4b08baa133284f4f122927947/av1_sw_decoder.plugin#L807-L812), [ordering, строки 532-550](https://github.com/stxlvn/exteragram-av1-sw-decoder/blob/6367bdcabbf2f7b4b08baa133284f4f122927947/av1_sw_decoder.plugin#L532-L550)).

## Сеть, данные и безопасность

При включённом `send_logs` события для load, выбранного AV1, player/codec errors, tracks и HEVC ставятся на отложенную отправку. Причины до запуска таймера объединяются; первый запущенный daemon `threading.Timer` отправляет накопленный список. Очередь событий ограничена 400 записями, дедупликация 200 ключами, диагностический payload — 200 KiB. `Diagnostics.add` пропускает текст через regex, который заменяет `tg://`, `/storage/`, `/data/`, `file://` и `http(s)://` фрагменты, затем пишет локальный plugin log. Обычный POST посылается в `https://stxlvn.tech/av1log` через `java.net.URL.openConnection()`; заданы connect/read timeouts 15 секунд, content type JSON, отдельная аутентификация не задаётся. Автоматическая отправка и ручная отправка лога вызывают один `send`, но ручная кнопка не проверяет `send_logs` перед запуском daemon worker thread ([diagnostics constants/redaction, строки 51-63](https://github.com/stxlvn/exteragram-av1-sw-decoder/blob/6367bdcabbf2f7b4b08baa133284f4f122927947/av1_sw_decoder.plugin#L51-L63), [timer, очередь и send, строки 166-243](https://github.com/stxlvn/exteragram-av1-sw-decoder/blob/6367bdcabbf2f7b4b08baa133284f4f122927947/av1_sw_decoder.plugin#L166-L243), [manual worker, строки 758-776](https://github.com/stxlvn/exteragram-av1-sw-decoder/blob/6367bdcabbf2f7b4b08baa133284f4f122927947/av1_sw_decoder.plugin#L758-L776)).

Важное отличие от README privacy summary: «Отправить сведения об SDK» — отдельный ручной путь. Он импортирует 10 перечисленных SDK modules, записывает `module.__file__`, версии и `inspect.getsource(module)` (до 180 KiB на модуль), а при невозможности чтения source сериализует signatures публичных callable members; payload разбивается на части до 200 KiB и уходит тем же POST. Этот путь не вызывает `Diagnostics.add` и, следовательно, описанный там `PRIVATE_RE` не применяется к module path/source. Нельзя сводить оба payload к заявлению README «без путей»: перед применением/включением SDK-dump нужно учитывать его более широкий состав ([SDK modules, строки 58-62](https://github.com/stxlvn/exteragram-av1-sw-decoder/blob/6367bdcabbf2f7b4b08baa133284f4f122927947/av1_sw_decoder.plugin#L58-L62), [snapshot and upload, строки 245-315](https://github.com/stxlvn/exteragram-av1-sw-decoder/blob/6367bdcabbf2f7b4b08baa133284f4f122927947/av1_sw_decoder.plugin#L245-L315), [manual SDK button, строки 768-776](https://github.com/stxlvn/exteragram-av1-sw-decoder/blob/6367bdcabbf2f7b4b08baa133284f4f122927947/av1_sw_decoder.plugin#L768-L776)). Сам сетевой запрос статически не проверялся; фактическое содержимое endpoint и передача не подтверждались.

## Сверка с радаром и README

Радар верно распознаёт плагин как пример глубоких hooks Media3/ExoPlayer и MediaCodec selection; README вместе с кодом подтверждает два режима AV1, quality cap, дав1d preference, опциональный software HEVC и fallback ([radar context](../../raw/av1-decoder/radar-context.md); [README L13-L20, L37-L45](https://github.com/stxlvn/exteragram-av1-sw-decoder/blob/6367bdcabbf2f7b4b08baa133284f4f122927947/README.md#L13-L20)). Уточнения по коду:

- Хук `DefaultRenderersFactory` в README описан как хук конструктора и код действительно ставит его на все найденные constructors; `VideoPlayer` методы идут через reflection по точному имени, но весь реальный runtime class layout не приложен.
- Фраза «software decoder Android» означает ранее установленный/зарегистрированный системный `MediaCodec`, не decoder, поставляемый `.plugin`.
- Android 10+ указан и в README, и в тексте runtime warning, однако source не проверяет API 29 как минимум; фактический software AV1 определяется per-device scan. Высокое разрешение «может тормозить» и преимущество скорости dav1d — документационные/UI claims, не измерения из репозитория.
- «Хуки Media3 необязательные» относится к optional library class lookup; отсутствие Telegram `VideoPlayer` прекращает `_install`, а если system software AV1/HEVC отсутствуют — плагин вообще idle.
- README говорит о приватном/редактированном логе; в коде простой regex лишь для пяти URI/path patterns, а отдельный ручной SDK-dump отправляет source/modules и `__file__` без этого фильтра.
- README упоминает отправку «после создания AV1-декодера»; исходник ставит `onCodecInitialized` hook, который логирует переданный codec без проверки MIME. Это событие не доказывает AV1-specific initialization или завершённое воспроизведение.
- В radar-context указан push 25 сентября в 05:03 UTC; repository metadata снимка сообщает `pushed_at` 26 сентября 13:38:03 UTC, поэтому исторический timestamp радара не совпадает с текущим snapshot metadata ([repository.json](../../raw/av1-decoder/repository.json)).

## Практические приёмы и ограничения переноса

1. Для похожего плагина отделяйте eligibility/filtering от фактического codec choice: здесь Telegram `supportsHardwareDecoder` и `getQualities` меняют верхний уровень, а `MediaCodecUtil.getDecoderInfos` затем меняет приоритет системных candidates.
2. Сохраняйте decoder fallback, если переупорядочиваете список, иначе приоритизация software candidate может убрать путь восстановления; здесь аппаратные entries остаются в конце и отдельно включён private fallback flag.
3. Перед reflection hook сначала проверяйте class availability и найденные member counts; этот код фиксирует `ok (count)`, `no methods`, class-not-found/error статусы вместо предположения о стабильном internals contract.
4. Делайте hook handlers отказоустойчивыми: callbacks ловят исключения, а generation token не даёт старым hooks продолжать работу после reload.
5. Проверяйте отдельно privacy всех upload paths. Локальная очистка строк в logger не покрывает SDK source dump, module paths, metadata или новые поля payload.

Практические советы описывают паттерны исходника, а не подтверждённые безопасные/совместимые рецепты. Не установлены рабочая версия ExteraGram/AyuGram, Media3/ExoPlayer ABI, hook performance, устойчивость private field names, software decode throughput, качество результата, network endpoint contract, release packaging или результат на устройстве. Это исследование только статическое; ничего не импортировалось/запускалось, не устанавливалось и не собиралось. Адаптацию к AyuGram нельзя заключить из названия проекта или `BasePlugin` API.
